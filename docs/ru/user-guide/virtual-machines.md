---
title: Виртуальные машины
description: Запустите ARGVUS с виртуальным графическим оборудованием.
---
`argvus start` обнаруживает виртуализацию и экспортирует настройки совместимости для затронутых сеансов, включая программный рендеринг и резервные варианты курсора/модификаторов, если это требуется обнаруженной средой.

Если виртуальная машина по-прежнему не отображается, проверьте среду сеанса и журналы перед добавлением переопределения. См. [решение проблем с графикой](/docs/user-guide/troubleshooting/graphics-and-virtual-machines/).

Когда обнаруживается виртуализация, `argvus start` экспортирует переменные совместимости для сеанса, включая программный рендеринг, программный курсор и резервные варианты модификаторов. Это делает обычный путь входа первым, что следует попробовать; не добавляйте постоянное переопределение только потому, что рабочий стол работает в виртуальной машине.

Если обнаружение недостаточно, используйте переопределение пользователя Hyprland как диагностический резервный вариант:

```sh
mkdir -p ~/.config/argvus/data/hypr
nano ~/.config/argvus/data/hypr/user.lua
```
Добавляйте это только тогда, когда это требуется графическим стеком виртуальной машины:

```lua
hl.env("LIBGL_ALWAYS_SOFTWARE", "1")
```
Выйдите из системы и войдите снова после изменения среды сеанса. Подтвердите активное значение с помощью `echo $LIBGL_ALWAYS_SOFTWARE`; программный рендеринг может сделать рабочий стол пригодным для использования, но может снизить производительность.

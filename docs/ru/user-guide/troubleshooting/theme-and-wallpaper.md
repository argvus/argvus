---
title: Устранение неполадок с темой и обоями
description: Диагностировать распространение темы и сгенерированные файлы внешнего вида.
---
Проверьте канонический раздел `appearance` в `$XDG_CONFIG_HOME/argvus/config.json`, затем просмотрите сгенерированные файлы в `$XDG_CONFIG_HOME/argvus/data/generated`. Устаревшие dot-файлы используются только как входные данные для миграции.

`argvus-config` является единственным писателем ниже `data/generated/`. Чтобы восстановить сломанную тему или обои, перестройте всю генерацию из канонического документа и примените результат вместо прямого редактирования сгенерированных потребителей:

```sh
argvus config validate
argvus config apply
argvus sessionctl reload
```
`argvus theme-switch` (который запускает `argvus config theme-apply`) и `argvus config accent` являются оркестраторами: они проверяют, блокируют, показывают заставку, выполняют подтверждение через `argvus-config`, а затем согласуют внешних потребителей, которые не могут читать `config.json`. Они никогда не записывают `data/generated/`, и тематическая транзакция не записывает файлы GTK, хранения или `mode.css` через отдельные скрипты. Используйте `argvus config accent --apply` для повторного запуска только согласования акцентов.

Официальные изменения темы применяют сохранённые значения внешнего вида и обновляют соответствующих потребителей во время выполнения. Применение пользовательской темы перезапускает панель задач, Hyprland, обои и службы Панели управления. Переключение Sticky или Spaced повторно применяет отступы, границы и поля панели задач для этого режима, затем перезапускает панель задач, телеметрию и службы перезагрузки Hyprland. Цвета уведомлений Dunst являются исключением, пока активен режим "Не беспокоить": их перезагрузка откладывается до отключения DND. Если на другой поверхности сохраняются старые цвета, проверьте, что сборка темы активна и что это выбранная вами тема, затем снова выполните перезагрузку:

```sh
cat "${XDG_CONFIG_HOME:-$HOME/.config}/argvus/data/generated/theme/current/build.toml"
argvus config theme-runtime consumers
```
Каждый тематический файл поступает из сборки: тема, которая не установлена (нет `theme.toml` под `/usr/share/argvus/themes/` или `~/.local/share/argvus/themes/`) или не отображается, отклоняется, и предыдущая тема остаётся. `argvus theme check DIRECTORY` показывает шаблон и строку каждой ошибки рендеринга. Панель Waybar обновляет свои цвета только с `reload_style_on_change` в её JSONC. Если переключатель кажется зависшим, проверьте, всё ли ещё работает; он записывает себя в `theme-switch.active`, рядом с его блокировкой:

```sh
cat "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/theme-switch.active"
ps -ef | grep -E 'theme-switch|theme-apply'
```
PID в маркере, который все еще активен, означает, что переключение не завершено. Переключатель ожидает максимум 60 секунд для блокировки темы и проекции и 5 секунд для команд перезагрузки; маркер, процесс которого завершился, устарел, и следующее переключение его игнорирует. Включите вывод вышеуказанных команд при сообщении о проблеме.

Если только приветствие до входа в систему белое или использует резервную тему, сравните приватный источник с его публичной проекцией:

```sh
uid=$(id -u)
argvus config get /appearance/theme --raw
sudo cat "/var/lib/argvus/greeter/themes/$uid"
sudo cat "/var/lib/argvus/greeter/themes/$uid.accent" 2>/dev/null || true
```
Восстановите проекцию, не изменяя конфигурацию greetd:

```sh
sudo argvus greeter-setup --sync-themes
```
Этот файл опубликован для предварительной аутентификации оркестратором отображения и находится вне `data/generated/`, поэтому простой `argvus config apply` его не обновляет.

Если приветствие сообщает `Invalid color name: 'null'` в кэше Kitty, обновите пакет `argvus terminal` и пересоздайте кэш, снова открыв приветствие. Отсутствие канонического акцента является значением по умолчанию, а не цветом Kitty; текущий запускатель терминала отклоняет JSON `null` и недопустимые устаревшие значения перед записью `active_tab_foreground`.

Если по умолчанию терминал перестает открываться после нескольких изменений темы, проверьте производный кэш Kitty вместо того, чтобы редактировать его вручную:

```sh
argvus config get /appearance/theme --raw
ls -l "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/argvus-terminal"
argvus terminal --apply
argvus terminal --print-config
```
Команда выше читает канонические настройки предпочтений. `.active-theme` является лишь проекцией для совместимости. Кэш регенерируется с помощью `argvus terminal` и синхронизируется с применением темы. Отсутствие или устаревание `/usr/lib/argvus/loading-theme/splash` указывает на неполное обновление пакета; пересоберите и установите согласованные пакеты перед оценкой результата в живой сессии.

Если границы окон сохраняют цвет предыдущей темы, не редактируйте вручную Lua-файл Hyprland. Изменения темы и акцентов проецируются из `config.json`, после чего `argvus sessionctl reload` перезагружает Hyprland и повторно применяет активные, неактивные и групповые цвета границ на протяжении всей сессии:

```text
config.json → projection plan → Hyprland reload → hyprctl reapply of active/inactive/group borders
```
Предпочтения границы изменяются через `argvus config borders` (или его делегата `borders-switch.sh`) в Центре управления и на Панели управления; перезагрузка повторно применяет зафиксированные цвета в течение жизненного цикла сессии и не вычисляет их заново.

Проверьте план и фактические значения композитора:

```sh
jq . "${XDG_STATE_HOME:-$HOME/.local/state}/argvus/config-projection.json"
hyprctl -j getoption general:col.active_border
hyprctl -j getoption general:col.inactive_border
argvus sessionctl reload
```
Если `hyprctl` не может подключиться к текущему сокету Hyprland, проекция границы считается неудачной, и зависимые компоненты не считаются успешно перезагруженными. Проверьте журнал пользовательской сессии перед повторной попыткой.

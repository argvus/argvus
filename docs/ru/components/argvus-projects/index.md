`argvus projects` перечисляет и открывает ваши проекты. Это команда в процессе выполнения пакета `argvus`, а `SUPER + O` открывает селектор.

## Команды

```text
argvus projects                    pick a project (SUPER + O)
argvus projects open SELECTOR      open a project by position, full path or unique name
argvus projects add [--root] DIR   add a project, or a root holding projects
argvus projects remove DIR         remove a project or root
argvus projects list               print configured roots and paths
argvus projects pick [PROMPT]      print the path picked from the list, for other tools
```
## Что такое проект

Проект — это каталог, указанный в конфигурации (`/projects/paths`), или подкаталог корневого каталога, указанного в `/projects/roots`. Всего может быть указано не более девяти проектов: это номера ярлыков `SUPER + CTRL + N`. Открытие проекта фокусирует рабочее пространство Hyprland. В первый раз при открытии проекта ARGVUS запускает терминал и установленный в `/projects/editor` редактор внутри него.

Конфигурация читается и записывается через `argvus config`, поэтому Панель управления и оболочка видят один и тот же список.

## Рабочие пространства проекта и панель задач

Проекты используют обычные именованные рабочие пространства Hyprland, а не специальные рабочие пространства. `SUPER + O` показывает номер проекта, каталог и прямую `SUPER + CTRL + N` ссылку. Обе точки входа фокусируются на одном и том же рабочем пространстве. В панели задач отображаются только открытые рабочие пространства с меткой `Project: name`, активным состоянием и подсказкой, содержащей полный путь и ссылку. Нажмите на кнопку рабочего пространства, чтобы вернуться к нему. Панель задач следует за монитором рабочего пространства.

Канонический путь каталога определяет стабильную идентичность рабочего пространства; изменение порядка в списке изменяет ссылку, а не рабочее пространство. Проекты с одинаковым именем каталога остаются отдельными, а символические ссылки на один и тот же каталог дедуплицируются. Запуски терминала и редактора явно нацелены на рабочее пространство проекта. Редакторы, которые повторно используют существующий процесс/окно, могут сохранять собственное поведение рабочего пространства этого приложения.

Рабочие области, открытые до обновления, сохраняют свои существующие окна и исходные имена. Открытие проекта после обновления использует его новую идентичность, основанную на пути; закрывайте старые окна проекта, когда это удобно. Автоматическая ассоциация или перемещение не выполняются, так как старое имя ненадежно идентифицирует каталог. При дублировании имен каталогов используйте выбор из списка, номер или полный канонический путь вместо неоднозначного имени.

Открытие проекта заново генерирует `$XDG_RUNTIME_DIR/argvus/project-workspaces.json` атомарно из настроенного списка проектов и переводов. Это метаданные сессии для меток рабочих областей и подсказок, а не конфигурация; не редактируйте их. Перезапустите проект после изменения списка или языка, чтобы обновить его метки. Обновите как `argvus`, так и `argvus-waybar`, а также конфигурацию `argvus-taskbar` для этой интеграции.

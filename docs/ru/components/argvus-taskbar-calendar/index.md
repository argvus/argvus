title: Календарь
description: Используйте календарь панели задач ARGVUS.

`argvus-taskbar-calendar` — это всплывающее окно календаря GTK4, открываемое из модуля даты Waybar или с помощью:

```sh
argvus --calendar
argvus taskbar-calendar toggle
argvus taskbar-calendar status
```
Он поддерживает локальные события, напоминания и импорт/экспорт ICS. Его пользовательская служба — `argvus-taskbar-calendar.service`. Используйте `argvus taskbar-calendar --help` для параметров, поддерживаемых установленной версией.

Календарь следует активной теме ARGVUS, включая варианты Sticky и Spaced. Изменения темы применяются через сгенерированный кеш пользователя; используйте `argvus taskbar-calendar reload`, если работающему всплывающему окну требуется явное обновление.

При открытии через модуль даты на панели задач всплывающее окно прикрепляется к краю панели: оно открывается под верхней панелью задач и над нижней панелью задач, выровненное по правому краю модуля даты. Прямой запуск без учета геометрии панели задач использует указатель мыши или резервный метод монитора.

## Команды

```bash
argvus taskbar-calendar                 open the calendar
argvus taskbar-calendar toggle          show or hide it (the Waybar date module uses this)
argvus taskbar-calendar show | hide
argvus taskbar-calendar config          open the system configuration for editing (sudo)
argvus taskbar-calendar config-path     print the configuration path
argvus taskbar-calendar reload
argvus taskbar-calendar import file.ics
argvus taskbar-calendar export --output calendar.ics
argvus taskbar-calendar sync
argvus taskbar-calendar status
argvus taskbar-calendar service
```
## События и напоминания

События по умолчанию отключены. Включите их во всплывающем окне в разделе **Настройки > События**; выбор сохраняется в каталоге состояния и также включает и запускает `argvus-taskbar-calendar.service`, который показывает напоминания. Отключение их останавливает сервис.
- **+ СОБЫТИЕ** (или `n`) открывает редактор для выбранного дня. События можно создавать и изменять начиная с сегодняшнего дня; событие прошлых дней также можно открыть и удалить.
- Новое событие начинается в 09:00 и длится по умолчанию, установленному в Настройках. Изменение времени начала сохраняет длительность; время окончания раньше времени начала означает, что событие заканчивается на следующий день.
- Каждое событие показывает уведомление со звуком при его начале, независимо от того, что указано в полях **Напоминание** и **Повторение**. Событие, сохранённое после его начала (например, событие на весь день, созданное в течение дня), уведомляет в течение 30 секунд.
- **Напоминание** добавляет более раннее уведомление, выбранное время до начала (в начале, если это время уже прошло).
- Для события на весь день поле времени становится **УВЕДОМЛЯТЬ В**: событие охватывает весь день и уведомляет в это время (00:00 уведомляет в начале дня). Время сохраняется при повторном открытии события.
- Для событий на весь день **Повторение** уведомляет снова через выбранный интервал после этого времени.
- Редактирование события без изменения его начала не повторяет уже показанные напоминания.
- Уведомления соответствуют языку календаря (Настройки > Язык).
- День показывает точку (`•`), когда в нем проходит событие, включая каждый день ночного или много-дневного события. Дни соответствуют местному часовому поясу.
- Локальные события удаляются автоматически через 10 минут после их окончания. Если событие уже закончилось при его сохранении, оно остается доступным как минимум 10 минут после сохранения.

Импортированные файлы `.ics` сохраняют свои даты, часовые пояса (`TZID`) и будильники (`VALARM`).
Импортированные события также уведомляют при их начале, кроме их собственных будильников. Повторяющиеся события (`RRULE`)
сохраняются и экспортируются, но отображается и напоминается только их первое появление.
После обновления пакета служба напоминаний выходит, и systemd запускает новую версию
в течение 30 секунд. `sync` сообщает только о настроенных удалённых календарях; синхронизация CalDAV ещё не реализована.

## Пути

- Конфигурация: `/etc/argvus/taskbar/calendar/config.toml` (системная; по умолчанию поставляется с пакетом).
- Стили: `/etc/argvus/taskbar/calendar/style.css` и `theme.css`; цвета активной темы ARGVUS берутся из темы, построенной через кеш ниже.
- Данные: `$XDG_DATA_HOME/argvus-taskbar-calendar/` (или `~/.local/share/argvus-taskbar-calendar/`).
- Состояние: `$XDG_STATE_HOME/argvus/taskbar/calendar/` (или `~/.local/state/...`); переключение событий хранится там.
- Кеш: `$XDG_CACHE_HOME/argvus-taskbar-calendar/` (или `~/.cache/argvus-taskbar-calendar/`).

Цвет подсветки считывается из `~/.config/argvus/data/.accent-color` и применяется во время выполнения поверх цветов темы.

Автоматический выбор языка следует за пользователем `locale.conf`, английский язык установлен по умолчанию. Явные предпочтения языка календаря по-прежнему переопределяют автоматический выбор.

Календарь на панели задач, ARGVUS Focus, ARGVUS Clock и Панель управления взаимно исключают друг друга: открытие одного закрывает остальные.

Ошибки чтения календаря отображаются отдельно от пустой повестки дня. Открытие базы данных, загрузка ежедневных событий и загрузка ежемесячных индикаторов имеют разные сообщения. Выберите день снова, чтобы повторить попытку. Неудачное обновление сохраняет ранее загруженные данные только за тот же день или месяц; действительные результаты другого запроса остаются доступными.

## Общие языковые каталоги

Интерфейс использует общие каталоги `argvus-i18n` для всех десяти языков. Тексты хранятся в `resources/locales/<locale>/taskbar-calendar.json` в основной рабочей области и устанавливаются с помощью `argvus`. Английский язык используется по умолчанию; новые языки больше не требуют локального двуязычного словаря.

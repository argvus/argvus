title: Конфигурационные файлы
description: Пользовательская, системная, стандартная для пакета и сгенерированная конфигурация ARGVUS.
---

| Уровень | Расположение | Значение |
| --- | --- | --- |
| Система | `/etc/argvus/` | Конфигурация администратора для сервисов и провайдеров. |
| Значения пакета по умолчанию | `/usr/share/argvus/` | Компоненты только для чтения по умолчанию и ресурсы времени выполнения. |
| Пользователь | `$XDG_CONFIG_HOME/argvus/config.json` | Канонические переносимые настройки. |
| Управляемые данные | `$XDG_CONFIG_HOME/argvus/data/` | Данные компонентов, файлы совместимости и внутренние метаданные. |
| Сгенерированные | `$XDG_CONFIG_HOME/argvus/data/generated/` | Проекции `config.json`, записываемые только `argvus-config`. Никогда не редактируйте, не копируйте в другое место как конфигурацию и никогда не читайте обратно как источник. |
| Время выполнения | `$XDG_RUNTIME_DIR/` и `$XDG_CACHE_HOME/` | Сокеты, блокировки и временное состояние. |

Активная тема, акцент, пользовательские обои и состояние эффектов являются логическим состоянием пользователя. Управляемая логическая модель задокументирована в [Canonical configuration](/docs/reference/argvus-config/)]. Сгенерированные файлы Hyprland, GTK, Qt6ct, Waybar, Quickshell, Dunst, Hyprlock, Yazi, Superfile, терминала, шрифтов и съемных устройств не следует рассматривать как независимые источники истины.

`argvus-config` также зеркалирует слой темы в `data/waybar/argvus-taskbar.{jsonc,css}` и `data/waybar/argvus-widget-telemetry.{jsonc,css}`. Эти копии заменяются на стандартные пакеты при изменении внешнего вида, затем их ограниченные управляемые блоки переписываются, поэтому рассматривайте их как производные, а не как вручную поддерживаемые файлы. Нативная конфигурация приложений в `$XDG_CONFIG_HOME/<app>` отличается: это целевой адаптер, написанный оркестраторами внешнего вида, никогда не проектором.

## Исключение из правила одного пишущего

`argvus config` является единственным автором `data/generated/`. Существует одно исключение для миграции: когда создается пользовательская копия упакованного файла, файл, который более старая версия оставила под `data/generated/`, перемещается в его пользовательское местоположение (`data/`), чтобы пользователь сохранил свои изменения. Перемещение происходит только для файлов, которые текущая версия не генерирует. Не полагайтесь на этот путь для новых файлов: добавляйте сгенерированный файл в проекцию, а не сюда.

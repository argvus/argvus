title: Конфигурация ARGVUS
description: Логический JSON-конфигурационный контракт, используемый ARGVUS.
---
ARGVUS хранит управляемые пользовательские настройки в модульных JSON-файлах под `$XDG_CONFIG_HOME/argvus/config/` (обычно `~/.config/argvus/config/`). Они формируют каноническую логическую модель настроек, управляемых ARGVUS, и `argvus-config` является единственным компонентом, который записывает файлы ниже `data/generated/`. Родные файлы и сгенерированные файлы остаются проекциями совместимости или специфическими для приложений переопределениями.

## Руководство пользователя: Быстрый старт

Для большинства пользователей конфигурация происходит через Центр управления ARGVUS или этот инструмент командной строки:

```sh
# View your configuration location and validate it
argvus config path
argvus config validate

# Get a specific value
argvus config get /appearance/theme
argvus config get /appearance/theme --raw    # Without JSON formatting

# Set a value (must be valid JSON)
argvus config set /appearance/theme '"gruvbox-dark"'

# Apply changes to reload the session
argvus config apply
```
Для администраторов и продвинутой настройки продолжайте чтение ниже.

Пользователь root содержит только канонический документ и управляемые данные:

```text
~/.config/argvus/
├── config.json
└── data/
```
Файл записывается атомарно, сохраняется приватным для пользователя и защищен `.config.lock`, вне дерева `data/`, которое может быть заменено во время проекции. Предыдущая версия хранится в `data/backups/config.json.bak`.

## Командная строка

Подкоманда `argvus config` предоставляется в процессе пакетом `argvus`:

```sh
argvus config path
argvus config validate
argvus config ensure
argvus config migrate
argvus config status
argvus config explain /layout/gaps_out
argvus config get /appearance/theme --effective --raw
argvus config set /appearance/accent '"#61AFEF"'
argvus config patch appearance-patch.json
argvus config audio volume +5
argvus config audio mute toggle
argvus config apply-theme universe --variant sticky --accent '#EEEEEE' --gtk-mode dark
argvus config apply-theme universe-spaced --variant spaced --accent '#EEEEEE' --gtk-mode dark
argvus config theme-manifest universe-spaced
argvus config unset /appearance/accent
argvus config apply
argvus config rebuild
argvus config project
argvus config project --force
```
`ensure` создает новый `config.json` с настройками схемы по умолчанию или заполняет отсутствующие поля, не заменяя явные значения. Ошибка возникает при некорректном JSON. `migrate` импортирует существующее наследованное состояние внешнего вида, не заменяя уже присутствующие значения в `config.json`. `argvus sessionctl` запускает `recover`, `ensure`, `migrate` и `project` перед применением перезагрузки после изменения конфигурации:

```sh
argvus sessionctl apply-config
```
`apply` и `rebuild` являются псевдонимами для перестройки всех проекций из `config.json`; `project` — это историческое написание и принимает `--force`. `apply` также делегирует перезагрузку во время выполнения после коммита `argvus sessionctl`. Установите `ARGVUS_NO_RUNTIME=1` для подготовки или изолированных тестов. Генерация происходит на промежуточном сервере, и дерево `data/` меняется только после успешного завершения всех проекторов. Поэтому удаление `data/generated/` и запуск `argvus config apply` является воспроизводимой перестройкой без публикации частичной последовательности выходов Hyprland или Taskbar. Команда записывает производные хэши секций и решение во время выполнения в `$XDG_STATE_HOME/argvus/config-projection.json` (обычно `~/.local/state/argvus/config-projection.json`). Ни манифест, ни сгенерированные файлы не являются источником истины. `apply` выполняет перезагрузку после коммита через `argvus sessionctl`; `project` остаётся только проекцией для совместимости.

Каждая постоянная мутация использует одно и то же правило: если канонический документ изменился, CLI вызывает один централизованный `argvus sessionctl reload` после коммита. Результат перезагрузки записывается в `data/internal/last-reload.json`.

`argvus sessionctl reload`, следовательно, является шагом *применения*, а не шагом проекции. Когда входящий манифест сообщает о незавершенной работе, он восстанавливает целевых потребителей, описанных в плане, и снова не вызывает `argvus config project`; повторная проекция создала бы идентичное дерево и отбросила бы план, который мутация только что создала. Он возвращается к миграции и проекции только в случае отсутствия зафиксированного плана, например, при запуске сессии.

### Цели перезагрузки

`argvus config session-plan` отвечает на перезагрузку с целями тех разделов, которые изменились, а `argvus sessionctl` выполняет только их. Splash покрывает перезагрузку только тогда, когда цель воссоздает поверхность: панель Waybar или Панель управления, которая возвращается на экран, сдвигают каждое окно. Всё остальное перезагружается на месте.

| Изменение | Цели | Сплэш |
| --- | --- | --- |
| Тема, цвет выделения или режим GTK | `hyprland`, `consumers`, `wallpaper`, `polkit` | нет |
| Только обои | `wallpaper` (hyprpaper IPC; служба перезапускается только для swaybg) | нет |
| `effects` (размытие, анимации, прозрачность, тень) | `hyprland`, `consumers` | нет |
| `layout` окон (зазоры, границы) | `hyprland` | нет |
| `layout.taskbar` (расположение, поля) | `hyprland`, `taskbar`, `widget_telemetry` | да |
| `fonts` | `consumers` | нет |
| `control_panel` (переключение, карточки) | `control_panel` | да |
| `default_apps`, `keyboard_shortcuts`, `hyprland`, `displays` | `hyprland` | нет |
| `power` | `hypridle` | нет |

`consumers` запускает `argvus config theme-runtime consumers` (стили панелей, Панель управления через IPC, цвета Hyprland, перезагрузка темы Dunst, btop и kitty). Dunst отложит перезагрузку темы, пока активен режим «Не беспокоить». `wallpaper` запускает `argvus config theme-runtime wallpaper`, который показывает фактический `/appearance/wallpaper`. Хэш `layout.taskbar` хранится отдельно от расположения окон в манифесте проекции, поэтому изменение промежутка не перезапускает панели. Резервный план `full`, используемый, когда нет зафиксированного плана, перезапускает все поверхности под заставкой.

Каждая эффективная конфигурация имеет рабочее поколение. Оно хранится в `data/internal/generation.json` и в манифесте проекции под `$XDG_STATE_HOME/argvus/config-projection.json`; оно не является частью конфигурации dotfiles. Повторное применение неизменённой эффективной конфигурации сохраняет поколение. `status` сообщает, совпадают ли хэш манифеста, метаданные поколения и все сгенерированные файлы; `apply` исправляет устаревшую или неполную проекцию.

`explain /path` считывает разрешатель напрямую и выводит эффективное значение, источник, тему и вариант. Он не анализирует сгенерированные файлы и не создаёт второе правило приоритета.

Проецирование тем и эффектов реализовано в самом `argvus-config`. 
Транзакция темы (`argvus theme-switch`, которая запускает `theme-apply`), `argvus config accent` и `argvus effects-toggle` не проецируют: они проверяют, блокируют, фиксируют через этот CLI, а затем согласовывают внешних потребителей, которые не могут прочитать `config.json`. `argvus effects-toggle` — это тонкий делегат без собственного вывода. Помощники для отображения внешнего вида никогда не вызываются проектором и никогда не должны записывать ниже `data/generated/`.

### Поверхности проекции

`project_effective` отображает каждого потребителя, принадлежащего ARGVUS, в одном промежуточном дереве перед публикацией:

| Поверхность | Вывод |
| --- | --- |
| Hyprland | `generated/hypr/`, включая профили тем, `spaces-effective.conf`, `borders-effective.conf`, `hypridle.conf` и `monitors.lua` |
| Layout/effects | `generated/effects/`, `generated/spaces.conf`, `generated/borders.conf` |
| Waybar | `generated/waybar/`, включая `argvus-taskbar.css` и `argvus-widget-telemetry.{jsonc,css}` |
| Темы телеметрии виджетов | `generated/widget-telemetry/` и `generated/waybar/widget-telemetry-themes/` |
| QuickShell | `generated/quickshell/` |
| Уведомления | `generated/notifications/` и `dunstrc` |
| Экран блокировки | `generated/hypr/hyprlock.conf` и профили тем Hyprtoolkit |
| GTK | `generated/gtk/` |
| Yazi | `generated/yazi/` |
| Superfile | `generated/superfile/` |
| Терминал и профили Qt | `generated/terminal/`, `generated/qt6ct/` |
| Шрифты | `generated/fonts.conf` плюс управляемые блоки шрифтов в таблицах стилей Waybar |
| Съемные устройства | `generated/removable-devices/theme.css` |
| Обои | `generated/hypr/hyprpaper.conf` и `data/hypr/hyprpaper.conf` |
| Панель управления и настройки по умолчанию | `data/control-panel/`, `data/control-center/defaults.json` |
| Календарь, ввод, клавиатура, питание | календарь TOML, фрагмент ввода, состояние клавиатуры, маркер бодрствования |

Слой темы также дублируется за пределами сгенерированного корня:
`data/waybar/argvus-taskbar.{jsonc,css}`,
`data/waybar/argvus-widget-telemetry.{jsonc,css}`, `data/foot/`,
`data/qt6ct/`, `data/hypr/hyprtoolkit.conf` и
`data/hypr/application-style.conf`. Эти копии заменяются стандартными файлами из пакета, когда изменяется раздел внешнего вида, и проектор затем переписывает только свои ограниченные управляемые блоки — блок шрифта в стилях Waybar и блоки `ARGVUS_TELEMETRY_*` в профиле телеметрии — поэтому текст за пределами маркеров не сохраняется при смене темы. `fonts.targets` и
`control_panel.widget_telemetry_blocks` остаются каноническими: Центр управления
сохраняет их через `argvus-config` и никогда сам не записывает эти файлы.

Выбор блока телеметрии виджета является каноническим на `/control_panel/widget_telemetry_blocks`, массив из семи имен блоков (`system`, `cpu_gpu`, `memory`, `storage`, `processes`, `network`, `keys`). Устаревший файл `$XDG_STATE_HOME/argvus/widget-telemetry-blocks` читается только как резервный для миграции и никогда не записывается. ` and ` and blocks all обновляет канонический массив одной атомарной записью, а `apply-state` предполагает, что выбор уже был сохранен его вызывающей стороной.

Настройки отступов и границ в Hyprland следуют тем же принципам. Команды argvus config spaces и argvus config borders (и их исторические обёртки совместимости) обновляют /layout; Rust генерирует data/generated/spaces-effective.conf и data/generated/borders-effective.conf и отвечает за проверку и применение изменений через hyprctl. .spaces и .borders являются состоянием только для миграции и никогда не являются источником истины.

Состояние акцента и режима GTK используют одну и ту же границу Rust. Используйте ` or ` or argvus config accent --theme-default для управления акцентом и `argvus config mode toggle|set dark|light` для режима GTK. Исторические скрипты акцента и режима являются обёртками для совместимости; `.accent-color`, `.accent-custom` и `.gtk-mode` предназначены только для миграции/проекции.

Логические пути ARGVUS также разрешаются `argvus config paths`. Устаревший файл `paths.sh` предоставляет только функции для совместимости; нативные переопределения, пользовательские данные, сгенерированные данные и системный запас разрешаются моделью путей Rust.

`audio` изменяет стандартный выходной источник и записывает результат в `/audio` за один шаг: `argvus config audio volume <N|+N|-N> [--limit PERCENT]` и `argvus config audio mute <on|off|toggle>`. Он записывает хранилище без перезагрузки конфигурации, потому что PipeWire уже имеет это значение. Модуль громкости Waybar, медиаклавиши Hyprland и Панель управления используют его, поэтому `argvus config project`, который проецирует `/audio` на источник, никогда не восстанавливает старую громкость. Громкость выше 100% (клавиши Hyprland позволяют до 150%) сохраняется как 100.

`patch` применяет объект JSON, ключи которого являются JSON-указателями, в одной заблокированной операции чтения-модификации-записи. `apply-theme` выполняет эквивалентную атомарную транзакцию темы и заменяет управляемые разделы внешнего вида из необязательного профиля внешнего вида темы или встроенных значений по умолчанию. Команды изменения создают `NextUserConfig`, разрешают `EffectiveConfig`, подготавливают все проекторы, и только затем публикуют канонический JSON. Операционный маркер `.config-transaction.json` позволяет `argvus config recover` проецировать предыдущую конфигурацию после сбоя между данными и публикацией JSON. Значения по умолчанию темы объявляются в манифесте каждой темы (`themes/<theme>/theme.toml`): стандартный акцент (`palette.accent`), цветовая схема GTK и обои. CSS, Lua, Rasi и Qt файлы формируются из него в сборку темы.

Смена темы, включая светлую/тёмную, сбрасывает цвет выделения на значение по умолчанию для темы, даже если пользователь выбрал собственный цвет: пользовательский цвет сохраняется только до следующей смены темы. Используйте `argvus config accent` после смены темы, чтобы установить его снова. Применение темы с `argvus config theme-apply` записывает `/appearance/accent` и `/appearance/gtk_mode` из манифеста, а `argvus config accent` записывает выбранный цвет с установленным `accent_custom`, в одну команду.

`apply-theme` принимает вариант явно как `--variant sticky|spaced` и разрешает запрашиваемое имя через манифест, так что запрос никогда не сможет разрешиться к ресурсам другого варианта. `theme-manifest THEME` — это то же самое разрешение, представленное только для чтения: оно выводит запись манифеста вместе с `asset_id` и `layout_variant`, к которым было выполнено разрешение, что необходимо вызывающему для работы с упакованными ресурсами. Sticky — это идентификатор без суффикса, и только Spaced имеет суффикс `-spaced`, поэтому `dracula-sticky` и `argvus-dark-dracula-sticky` принимаются и нормализуются в `dracula`.

С помощью `--raw` строковые значения выводятся без кавычек JSON, в то время как объекты и массивы остаются значениями JSON. Файлы темы и макета больше не записываются помощником проекции; `config.json` остается единственным постоянным источником этих настроек. Если проекция не удается, перезагрузка сессии останавливается до перезапуска поверхностей рабочего стола, чтобы более старая частичная тема не отображалась как текущая.

## Экспорт и импорт

Для обмена профилями используется та же логическая модель:

```sh
argvus config export --scope appearance --output appearance.json
argvus config import --scope appearance appearance.json
```
Используйте `--scope desktop` для полной управляемой модели рабочего стола. Отсутствующие поля используют значения по умолчанию ARGVUS; сгенерированный вывод не следует редактировать напрямую.

Экспорт и импорт темы из Центра управления обмениваются темой и её визуальным профилем: архив содержит директорию темы схемы 2 (`<id>/theme.toml`, опционально `appearance.json` и `effects.conf`, `overrides/`, обои), которая устанавливается в `$XDG_DATA_HOME/argvus/themes/`. Профиль содержит оформление, геометрию расположения, визуальные эффекты, шрифты и представление панели. Аудио, клавиатура, сеть и другие невизуальные настройки остаются вне темы. Используйте область `appearance` выше, чтобы переместить полную конфигурацию внешнего вида, и область `desktop` для полного резервного копирования конфигурации.

Текущая схема группирует предпочтения под `appearance`, `layout`, `effects`, `fonts`, `control_panel`, `default_apps`, `keyboard_shortcuts`, `hyprland`, `displays`, `power`, `session`, `calendar` и `removable_devices`. `default_apps` является единственным постоянным источником для предпочитаемых приложений, а `keyboard_shortcuts` хранит стабильные английские ключи, независимые от локали, со строковыми значениями или `null` для отключенных привязок.

Центр управления считывает канонические значения внешнего вида при открытии страницы «Внешний вид» и записывает изменения через `argvus-config`. Существующие родные файлы состояния остаются проекциями для сценариев внешнего вида и старых установок.

Панель управления использует `control_panel.cards` для порядка и видимости карточек и `control_panel.enabled` для главного переключателя панели. Ее файлы `control-panel/cards.json` и `state/control-panel` хранятся как проекции для совместимости. Изменения, сделанные в Панели управления, поэтому входят в область экспорта `desktop`.

Настройки шрифтов используют `fonts.targets` для семейства, стиля и размера задачной панели, телеметрии, Панели управления, системы, приложений, терминала и целей браузера. `fonts.rendering` хранит настройки сглаживания, hinting, порядка субпикселей и DPI. `fonts.conf`, правило fontconfig, настройки рабочего стола и управляемые блоки шрифтов внутри стилей Waybar являются проекциями: Центр управления сохраняет `/fonts/targets/*` через `argvus-config`, а проектор переписывает только его ограниченный блок.

Настройки Hyprland используют `keyboard_shortcuts` для ярлыков, `hyprland.input` для настроек мыши и тачпада и `hyprland.keyboard` для раскладки XKB, варианта и опций. ID привязки манифеста сопоставляется со стабильным `config_key` (например, `window.close` → `close_window` и `window.drag_mouse` → `drag_window__floating_window_only`). Настройки дисплея используют `displays.monitors`, `displays.workspaces` и `displays.primary_monitor`. Натуральные TOML-файлы и сгенерированные Lua-файлы под `data/generated/` остаются проекциями, используемыми Hyprland.

Каждый переключатель `effects` по умолчанию включен (анимации, размытие, телеметрия виджетов и каждая прозрачная поверхность), также на виртуальных машинах и в режимах низкого энергопотребления; тень окна (`shadow_enabled`) и дрожание (`wobble_enabled`) по умолчанию выключены. Настройки эффектов используют `effects` для главного переключателя Анимаций (`animations`, применяемого к `hyprland.lua` из проектируемого `hypr/state.lua`, независимо от переключателя Эффектов, который представляет собой `blur_global_enabled` плюс `transparency_<surface>_enabled` из `taskbar`, `control-panel`, `widget-telemetry`, `terminal` и `launchers`, и считается включенным, когда включен любой из них; `argvus effects-toggle animations|effects` переключает их), глобальный переключатель размытия (`blur_global_enabled`), параметры размытия Hyprland (`blur_size`, `blur_passes`, `blur_brightness`, `blur_noise`, `blur_contrast`, `blur_vibrancy`, `blur_vibrancy_darkness`), тень окна (`shadow_enabled`, `shadow_sharp`, `shadow_color`) `shadow_range`, `shadow_render_power`, `shadow_offset_x`, `shadow_offset_y`, `shadow_scale`), значения анимаций (`animation_<leaf>_speed`, `_curve`, `_style`, `_popin` и `_enabled` для каждой анимации, плюс `animation_bezier_x1` до `animation_bezier_y2` и `animation_spring_mass`, `animation_spring_stiffness` и `animation_spring_dampening` для пользовательских кривых) и значения прозрачности для каждой поверхности. Эффекты принадлежат теме, а не варианту: Sticky и Spaced используют одну и ту же проекцию эффектов `<theme>.conf`, в то время как их проекции макета различаются. В настоящее время поверхности включают `taskbar`, `control-panel` и `widget-telemetry`; значения прозрачности выражены в процентах от `0` до `100` (поверхности Центра управления и лаунчера по умолчанию равны `15`, остальные — `50`), параметры размытия — это числа в пределах диапазонов, объявленных в `schema.json`, а состояния включения — булевы значения. Значения анимаций также проверяются `argvus-config`: скорости являются числа от `1` до `10` (разрешены десятичные дроби), проценты всплывающих окон — целые числа от `1` до `100`, кривые должны быть именами со страницы «Анимации», стили должны быть именами со страницы «Анимации» и приниматься собственным листом анимации (например, `popin` отклоняется для `animation_workspace_in_style`, `gnomed` принимается только для открытия и закрытия окон, а варианты слайдов отклоняются для оконных и многослойных створок), точки Безье Y остаются между `-1` и `2`, диапазон Hyprland 0.56.2, а другие параметры кривой остаются в пределах документированных диапазонов. Листы `layers` и `switching` больше не существуют, поэтому конфигурации, сохраненные до их удаления, теряют ключи `animation_layers_enabled`, `animation_layers_speed`, `animation_layers_curve` и `animation_switching_*` при загрузке. Стили вне текущего набора удаляются, а точки Безье Y за пределами от `-1` до `2` фиксируются, поэтому упакованные значения по умолчанию снова применяются к все, что было удалено.

Настройки питания используют `power.screen_off_minutes`, `power.lock_minutes`, `power.keep_awake` и политики крышки/кнопки питания. Проектируемые формы — `data/generated/hypr/hypridle.conf` и маркер `data/power/keep-awake`; `.keep-awake` используется только для миграции. `session.language` устарел: существующие значения игнорируются, новые записи отклоняются, и файл совместимости языков не проектируется. Установите `LANG` в пользовательском `locale.conf` вместо этого. Настройки календаря используют `calendar` и проецируются в TOML пользователя панели задач календаря. Настройки съемных устройств используют `removable_devices`; приложение съемных устройств рассматривает этот раздел как пользовательское переопределение стандартных настроек.

`migrate` импортирует старые корневые файлы и разделы один раз, сохраняя существующее каноническое значение. Устаревшие `defaults.json`, `/defaults`, `/hyprland/keybindings`, `keybindings.toml`, dot-файлы, `generated/` и каталоги компонентов перемещаются под `data/`; повторные перезагрузки не воссоздают старую корневую структуру. Повторный выбор текущей темы идемпотентен: если каноническое состояние и проекции уже совпадают, план проекции сообщает об отсутствии изменений разделов, а сеанс пропускает заставку и перезапуск служб. 

Энергия следует тому же контракту проекции: Центр управления записывает `/power` в `config.json`, `argvus config project` рендерит `data/hypr/hypridle.conf` атомарно, и только после этого `argvus sessionctl` может перезапустить `argvus-hypridle.service`. Удаление этого файла восстанавливается с помощью `argvus config project`; значение `0` пропускает соответствующий тайм-аут и означает Никогда.

Внешний вид экрана блокировки проецируется Rust из канонической темы, акцента, эффектов, обоев и состояния шрифта в `data/hypr/hyprlock.conf`. Историческая точка входа `hyprlock-theme.sh` предназначена только для совместимости и делегирует функции `argvus config lock apply`; `--invalidate` лишь инвалидирует кэш размытого обоев.

Изменения таймаута питания используют `/power/lock_minutes` и `/power/screen_off_minutes` в качестве источника истины. `argvus config project` повторно использует существующий рендерер Hypridle, а точка входа `idle-timeout.sh` является лишь адаптером для совместимости; перезапуск службы по-прежнему делегируется `argvus sessionctl`.

Внешний вид уведомлений выводится из канонической темы, акцента и эффектов в `data/notifications/dunstrc`. Исторический файл уведомлений `theme.sh` только предоставляет функции совместимости, вызывающие `argvus config notifications`; он не парсит и не изменяет конфигурацию Dunst.

Ориентированные на оборудование адаптеры, такие как обнаружение дисплея и управление Bluetooth, теперь импортируются доменом дисплея Rust: `nwg-displays` является внешним импортером, в то время как `/displays` и `data/generated/hypr/monitors.lua` остаются каноническим и производным состоянием соответственно. Инструменты дисплея изменяют макет с помощью `argvus config monitor-set`, `monitor-primary`, `monitor-workspaces` и `monitor-remove`; команды дисплея — это `argvus config display status|list-modes|set|apply|apply-nwg|migrate-nwg|nwg-import|nwg-apply`. Файл Hyprland проецируется из `/displays`; ни один shell-скрипт больше его не записывает. Выбор обоев, режим группы утилит на панели задач и поиск приложений по умолчанию также используют API `argvus-config`; их исторические точки входа Shell являются UI или совместимыми оболочками. Keep Awake — это постоянная настройка `/power/keep_awake`, проецируемая на маркер `data/power/keep-awake`, в то время как блокировка-DPMS является состоянием выполнения сеанса.
`$XDG_CACHE_HOME/argvus/lock-dpms`. Конфигурация раскладки клавиатуры теперь принадлежит помощнику Rust `argvus-keyboard-layout`: настроенный порядок берется из сгенерированного проецирования ввода Hyprland или запасной локали, в то время как активная раскладка остается состоянием выполнения сеанса, обнаруженного Hyprland. Точка входа цикла и демон раскладки клавиатуры являются только оболочками совместимости; пользовательская служба запускает демон Rust напрямую, и `argvus sessionctl keyboard-layout cycle` является стабильной командой для вызывающих.

Состояние выполнения Bluetooth следует границе внешнего адаптера, но не является частью `argvus-config`: `argvus bluetooth` отвечает за типизированный разбор и проверку `bluetoothctl`, ограниченные попытки, проверки системных служб и статус RFKill. `argvus bluetoothctl` является точкой входа. Питание адаптера, сопряженные устройства и подключенные устройства остаются состоянием выполнения BlueZ, а не каноническим JSON-состоянием; проверка Bluetooth на рабочем оборудовании зависит от среды.
## Идентификация и согласование во время выполнения

Используйте `argvus config status --verbose` для проверки точного бинарного файла, идентичности сборки, корневой конфигурации, сгенерированного корня, корня активов, исходника манифеста и активного поколения. Он сообщает состояния проекции `synchronized`, `stale`, `incomplete`, `legacy` и `pending-transaction`.

`argvus config --version` сообщает версию пакета, ревизию сборки, когда они предоставлены средой сборки, и профиль. Разработческие тесты должны явно внедрять свои бинарные файлы и ресурсы; они не должны использовать `argvus config` или `~/.config/argvus` молча. `apply` безопасно нормализует устаревшие комбинированные идентификаторы, такие как `argvus-dark-spaced`, в отдельные значения темы и варианта перед реконструкцией проекций. Идентификация упакованных ресурсов в этой версии не записывается в манифест.

### Настройки покачивания (Hyprland 0.57+)

`effects.wobble_enabled`, `wobble_stiffness`, `wobble_damping`, `wobble_mass`, `wobble_intensity` и `wobble_mesh` проектируются напрямую в `hypr/state.lua`. Используйте `argvus effects-toggle wobble-settings get`, чтобы прочитать их, или `argvus effects-toggle wobble-settings set enabled=enabled stiffness=100 damping=10 mass=1 intensity=1 mesh=8`, чтобы сохранить и запросить перезагрузку. `enabled=disabled` отключает эффект.

Центр управления делится черновиком анимаций: `animations-settings get` также возвращает записи `wobble_*`, а `animations-settings set` принимает эти полные имена вместе с существующими аргументами анимации. Это сохраняет весь черновик в одном проверенном патче и запрашивает одну перезагрузку. Например:

```sh
argvus effects-toggle animations-settings set enabled=enabled wobble_enabled=true wobble_intensity=0 wobble_mesh=8
```
Глобальный `enabled` управляет анимациями; `wobble_enabled` — это его независимое предпочтение. Отключение глобальных анимаций подавляет колебания в Lua без удаления этого предпочтения. Недопустимые значения отклоняют весь патч. Отсутствующие ключи получают значения по умолчанию ARGVUS без замены существующих выборов. См. [Appearance](/docs/user-guide/appearance/#window-wobble) для границ и значений по умолчанию.

### Пользовательские сочетания клавиш

`/keyboard_shortcuts` сохраняет свои существующие строковые или нулевые значения для официальных действий манифеста. Пользовательские глобальные сочетания клавиш используют отдельный объект `/hyprland/custom_shortcuts`, который хранится в `config/hyprland.json`. Его стабильные идентификаторы `custom_` независимы от описаний и локалей. Каждая запись имеет `description`, `keys`, `enabled` и типизированный `action`:

```json
{
  "custom_editor": {
    "description": "Open my editor",
    "keys": "SUPER + CTRL + E",
    "enabled": true,
    "action": { "type": "command", "command": "editor --new-window" }
  },
  "custom_float": {
    "description": "Toggle floating",
    "keys": "SUPER + CTRL + F",
    "enabled": false,
    "action": {
      "type": "dispatcher",
      "dispatcher": "window.float",
      "arguments": { "action": "toggle" }
    }
  }
}
```
Пример представляет собой значение `/hyprland/custom_shortcuts`, а не полный документ конфигурации. Имена диспетчеров берутся из поддерживаемых фабрик Lua-диспетчеров; аргументы — это необязательный объект JSON или `null`, никогда не выполняемый код. У пользовательских ярлыков нет подкарты, привязки к мыши или расширенных флагов. Проекция записывает `data/generated/hypr/custom-shortcuts.lua` как экранированную таблицу данных, включая пустую таблицу, когда удаляется последняя запись. И полная проекция, и `project --only keyboard_shortcuts` её генерируют. Hyprland регистрирует включённые записи с `hl.bind`; возможные сбои регистрации файла и отдельных элементов удерживаются и логируются.

Центр управления создаёт/редактирует записи и отключает подтверждённые конфликты с помощью одной транзакции `argvus config patch`. Он сохраняет их перед применением через существующий сервис конфигурации. Неудачное применение не отменяет успешное сохранение. Восстановление официальных настроек сохраняет пользовательские записи и отклоняется, если оно приведёт к конфликту с активным пользовательским ярлыком. Описания пользователей остаются буквальным текстом во всех локалях и в генерируемой итоговой шпаргалке.

## Глобальный режим окна

Откройте **Центр управления → Рабочий стол и ввод → Hyprland → Окна → Режим** и выберите **Упорядоченные окна (по умолчанию)** или **Плавающие окна**. Тот же селектор доступен через значок режима окна в группе утилит панели задач.

Этот параметр применяется ко всем мониторам и рабочим областям и сохраняется после выхода из системы. Режим плавающих окон конвертирует существующие окна приложений и вновь открытые окна. Режим плиток восстанавливает только окна, которые были конвертированы этой политикой; диалоговые окна и другие окна, которые уже были плавающими, остаются плавающими. Окно, явно закреплённое во время активности режима плавающих окон, также остаётся плавающим, чтобы сохранить своё закрепление. Макет плиток пересчитывается; его точное предыдущее дерево разбиения не восстанавливается.

`SUPER + SHIFT + Space` сохраняет своё нормальное поведение для каждого окна в режиме плиток. В режиме плавающих окон оно не возвращает окно в режим плиток. Панели, панель задач и уведомления являются поверхностями layer-shell и не подвергаются изменениям. Режим полноэкранного отображения и максимизации продолжают использовать обычное поведение Hyprland.

Каноническим предпочтением является `/hyprland/window_mode` в `$XDG_CONFIG_HOME/argvus/config/hyprland.json`. Его сгенерированная проекция — `data/generated/hypr/window-mode.lua`; не редактируйте её. Реестр восстановления по окнам находится под `$XDG_RUNTIME_DIR/argvus`, с привязкой к экземпляру композитора, и сохраняется при перезагрузке конфигурации. Он не используется в новой сессии.

Если приложение ожидает выполнения или завершилось с ошибкой, интерфейс отличает это от сохранённого предпочтения. Выберите опцию снова, чтобы повторить попытку. Без композитора предпочтение сохраняется для следующего входа.

```sh
argvus config window-mode get
argvus config window-mode status --json
argvus config window-mode set floating
argvus config window-mode set tile
argvus config window-mode toggle
```
## Кнопки окна и панель приложения

Плавающий режим добавляет заголовок ARGVUS с кнопками **Свернуть**, **Развернуть / Восстановить** и **Закрыть** для обычных окон приложений. Двойной щелчок по заголовку переключает максимизацию. Дополнительное оформление скрыто в режимах Tile и полноэкранном режиме. Приложения, которые рисуют свои собственные элементы управления, могут отображать обе панели; единообразные элементы управления ARGVUS являются намеренными.

Второй Waybar появляется на каждом мониторе, на противоположном краю от главной панели задач. Он отображает только окна, принадлежащие текущему рабочему пространству этого монитора, включая свернутые окна этого рабочего пространства. Открытое специальное рабочее пространство имеет приоритет. Закрепленные окна остаются видимыми; скрытые вкладки групп не создают дополнительных записей, а свернутая группа имеет одну запись восстановления. Вкладки внутри приложения не перечисляются отдельно. Свернутые записи сохраняют первоначальную связь с монитором/рабочим пространством. Щелкните по неактивному окну, чтобы активировать его, по активному окну — чтобы свернуть, или по свернутому окну — чтобы восстановить; в его контекстном меню доступны восстановление, сворачивание, развертывание/восстановление и закрытие. Значки неизвестных приложений заменяются символом окна. Активация или восстановление записи сохраняет положение указателя. Вторичная панель использует эффективный первичный CSS (цвета, шрифты, рамки и скругления), с учетом своей высоты и зеркальных отступов на противоположном крае.

`SUPER + Alt + Up` размещает основную панель вверху, а панель окна внизу. `SUPER + Alt + Down` делает наоборот. Повторение направления оставляет позиции без изменений. У плитки есть только основная панель. Возврат к плитке восстанавливает все свернутые окна перед удалением панели окна, а затем сохраняет исходную политику плитки/плавающего режима.

Минимизация использует зарезервированное рабочее пространство `special:argvus-minimized`. Не используйте это рабочее пространство вручную. Процесс `argvus windows service` записывает идентичность, исходное рабочее пространство/монитор, геометрию, полноэкранный режим/максимизацию и состояние закрепления в реестре времени выполнения, специфичном для экземпляра композитора, под `$XDG_RUNTIME_DIR/argvus`. Записи сохраняются при перезапуске службы или перезагрузке конфигурации, но не переходят между сеансами композитора. Закрытие окна удаляет его запись. Если монитор исчезает, восстановление использует доступный выход. Отсутствие или сбой панели восстановления предотвращает новые минимизации; при сбое восстановления запись сохраняется, а панель восстановления сохраняется.

Сеанс владеет `argvus-windows.service` и `argvus-window-bar.service`. Последнее удерживает своего дочернего Waybar в спящем состоянии в Tile. Плагин hyprbars включен `argvus-hyprland`, собран для ABI Hyprland 0.57.0 на x86_64; он не компилируется в домашнем каталоге пользователя. Пересоберите плагин при обновлении ABI композитора.Команды: `argvus windows list --json`, `watch --json`, `position top|bottom`, `restore-all` и `minimize|restore|activate|maximize|close ADDRESS`. Адреса окон берутся из списка. `position top --persist` сохраняет/проецирует предпочтения без перезапуска основной панели. Детали конфигурации и ошибок во время выполнения записываются в журнал; видимые сбои действий также показывают переведённое уведомление.

В **Spaced + Floating** окна учитывают внешние зазоры и зоны, зарезервированные обеими панелями. Границы включают рамку и заголовок, который находится внутри той же рамки окна. Максимизация через ARGVUS контролы заполняет эту область с учётом полей; восстановление возвращает предыдущую геометрию, включая после перезапуска службы. Режим полноэкранного просмотра по-прежнему использует весь вывод. Плавающие окна могут перекрывать друг друга; внутренние зазоры для тайлинга их не разделяют.

Внутренние отступы, зарезервированные панелями, не учитываются дважды в наружных зазорах окна. При симметричном расположении видимое расстояние от окна до панели одинаково сверху и снизу, включая после перестановки панелей.

`SUPER + Alt + Space` переключает глобальный режим «Каскад/Плавающий», используя те же настройки, что и панель задач и Центр управления. Эквивалентная команда — `argvus config window-mode toggle`. Одновременные вызовы выполняются последовательно; переключение использует сохранённые настройки, даже когда приложение ожидает. Горячую клавишу можно изменить или отключить в «Сочетания клавиш»; `SUPER + Shift + Space` сохраняет действие для отдельного окна.

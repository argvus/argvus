ARGVUS распространяется как пакет Arch Linux через официальный репозиторий пакетов ARGVUS.

## Перед установкой

Включите официальный репозиторий Arch Linux `multilib` перед установкой ARGVUS. Отредактируйте `/etc/pacman.conf` и раскомментируйте как секцию `[multilib]`, так и её строку `Include`:

```ini
[multilib]
Include = /etc/pacman.d/mirrorlist
```
Затем синхронизируйте базы данных пакетов и выполните полное обновление системы:

```sh
sudo pacman -Syu
```
Быстрый установщик настраивает репозиторий ARGVUS, но не активирует `multilib` за вас.

## Быстрая установка

На свежей установке Arch Linux вы можете установить ARGVUS напрямую из TTY без предварительной установки другой среды рабочего стола.

Выполните:

```sh
curl -fsSL https://argvus.github.io/install.sh | sh
```
Установщик:

1. Импортирует и локально подписывает ключ репозитория ARGVUS.
2. Настраивает репозиторий пакетов ARGVUS.
3. Обновляет базу данных пакетов.
4. Устанавливает пакет `argvus` и его зависимости.

После установки выйдите из системы и выберите **ARGVUS** в вашем дисплей-менеджере.

> **Примечание:** Быстрый установщик требует `curl`, `sudo` и стандартные инструменты управления пакетами Arch Linux.

## Настройка только репозитория

Чтобы настроить репозиторий пакетов ARGVUS без установки рабочего стола, выполните:

```sh
curl -fsSL https://argvus.github.io/repo-install.sh | sh
```
Установите ARGVUS вручную после этого:

```sh
sudo pacman -Syu argvus
```
## Ручная установка

Если вы предпочитаете настраивать репозиторий шаг за шагом, используйте следующие команды.

### 1. Скачайте ключ подписи репозитория

```sh
curl -fsSLo /tmp/argvus.gpg https://argvus.github.io/packages/arch/argvus.gpg
```
### 2. Импортировать ключ подписи

```sh
sudo pacman-key --add /tmp/argvus.gpg
```
### 3. Локальная подпись ключа

```sh
ARGVUS_KEY="$(gpg --show-keys --with-colons /tmp/argvus.gpg | grep '^pub:' | head -n1 | cut -d: -f5)"
sudo pacman-key --lsign-key "$ARGVUS_KEY"
```
### 4. Настройте репозиторий ARGVUS

```sh
curl -fsSL https://argvus.github.io/packages/arch/argvus.conf \
  | sudo tee /etc/pacman.d/argvus.conf
```
Добавьте конфигурацию репозитория в `/etc/pacman.conf`:

```sh
echo "Include = /etc/pacman.d/argvus.conf" \
  | sudo tee -a /etc/pacman.conf
```
Конфигурация репозитория включает репозитории ARGVUS, включая `argvus` и `argvus-extras`, с `SigLevel = Required TrustedOnly`. Pacman принимает пакеты только тогда, когда их подписи действительны и доверены локальным ключевым кольцом.

### 5. Установка ARGVUS

```sh
sudo pacman -Syu argvus
```
После установки выйдите из системы и выберите **ARGVUS** в вашем дисплейном менеджере.

## Обновление

Обновляйте ARGVUS вместе с остальной системой Arch Linux:

```sh
sudo pacman -Syu
```
Чтобы обновить только пакет ARGVUS:

```sh
sudo pacman -S argvus
```

> **Рекомендация:** Arch Linux обычно рекомендует полное обновление системы с `sudo pacman -Syu` вместо обновления отдельных пакетов.

## Удаление ARGVUS

Удалите ARGVUS, сохранив зависимости, которые все еще требуются другими установленными пакетами:

```sh
sudo pacman -R argvus
```
Удалите ARGVUS и зависимости, которые больше не требуются ни одному установленному пакету:

```sh
sudo pacman -Rns argvus
```
### Удаление репозитория ARGVUS

Если вы также хотите удалить репозиторий пакетов, удалите его конфигурацию:

```sh
sudo rm /etc/pacman.d/argvus.conf
```
Затем удалите соответствующую строку из `/etc/pacman.conf`:

```text
Include = /etc/pacman.d/argvus.conf
```
Вы можете редактировать файл с помощью:

```sh
sudo nano /etc/pacman.conf
```
### Удаление ключа подписи

Чтобы удалить ключ подписи репозитория ARGVUS из связки ключей pacman, сначала перечислите ключи:

```sh
sudo pacman-key --list
```
Затем удалите ключ ARGVUS с его идентификатором ключа:

```sh
sudo pacman-key --delete KEY_ID
```
Замените `KEY_ID` на идентификатор ключа подписи ARGVUS.

> **Внимание:** Удаляйте этот ключ только тогда, когда вы также удаляете репозиторий ARGVUS. Не удаляйте ключи, которые все еще требуются другими репозиториями.

## Конфигурация пользователя

Установка пакета не записывает конфигурацию в `$HOME`. ARGVUS читает стандартные значения пакета из `/usr/share/argvus` и работает без копирования их в ваш домашний каталог.

Время выполнения конфигурации подчиняется следующему общему приоритету:

```text
~/.config/argvus/data/generated/<app>  ->  ~/.config/argvus/data/<component>/<app>  ->  $XDG_CONFIG_HOME/<app>  ->  /usr/share/argvus/<app>  ->  upstream defaults
```
`argvus-config` — это единственный компонент, который записывает `~/.config/argvus/data/generated/`, и эта проекция является активным слоем: управляемая или нативная копия имеет эффект только пока отсутствует соответствующий сгенерированный файл.

Управляемая конфигурация ARGVUS находится под `~/.config/argvus/`. Необязательный переопределяющий файл `$XDG_CONFIG_HOME/<app>` остается доступным для приложений, которые поддерживают нативную пользовательскую конфигурацию.

Диспетчер `argvus --setup` является необязательным и предназначен для явных ручных переопределений, а не для восстановления. Если `~/.config/argvus` удаляется, `SUPER + SHIFT + R` воссоздает канонический профиль и сгенерированное состояние выполнения через обычный процесс перезагрузки.

```sh
argvus --setup --copy foot-tui
argvus --setup --copy kitty-tui
argvus --setup --copy-all
```
`--copy-all` является явным списком разрешенных файлов поддерживаемого профиля TUI; он не клонирует `/usr/share/argvus` и не копирует скрипты, сервисы, ресурсы, сгенерированные файлы или `config.json`. Запустите `argvus --setup --help`, чтобы увидеть текущие опции. После копирования файлы становятся принадлежностью пользователя, и обновления пакета их не заменяют.

Чтобы заменить существующую скопированную конфигурацию, используйте `--force`. ARGVUS создает резервную копию с отметкой времени перед ее заменой:

```sh
argvus --setup --copy <app> --force
```
## Пользовательские настройки Hyprland

Для полного руководства по настройкам Hyprland, включая различие между полной нативной конфигурацией и инкрементальными фрагментами ARGVUS, см. [Hyprland overrides](/docs/argvus-hyprland/hyprland-overrides/).

```sh
mkdir -p ~/.config/argvus/data/hypr
nano ~/.config/argvus/data/hypr/user.lua
```
### Резервный режим виртуальной машины

Некоторые виртуальные машины могут испытывать проблемы с отображением в Hyprland, Kitty или Quickshell. ARGVUS обнаруживает виртуальные машины с использованием графического драйвера `vmwgfx` и при необходимости включает программный рендеринг.

Если обнаружение не срабатывает на вашей виртуальной машине, включите резервный режим вручную в `user.lua`:

```lua
-- Virtual machine compatibility
hl.env("LIBGL_ALWAYS_SOFTWARE", "1")
```
После создания или изменения `user.lua` выйдите из Hyprland и войдите снова, чтобы переменная применялась к приложениям, запущенным в сессии.

Проверьте это с помощью:

```sh
echo $LIBGL_ALWAYS_SOFTWARE
```
Ожидаемый результат:

```text
1
```

> **Примечание:** `LIBGL_ALWAYS_SOFTWARE=1` заставляет приложения Mesa/OpenGL использовать программное рендеринг, обычно через `llvmpipe`. Это может снизить графическую производительность и должно использоваться как резервный вариант для затронутых виртуальных машин.

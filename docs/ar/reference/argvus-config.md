يحتفظ ARGVUS بتفضيلات المستخدم المُدارة في ملفات JSON المعيارية ضمن `$XDG_CONFIG_HOME/argvus/config/` (عادةً `~/.config/argvus/config/`). إنها تشكل النموذج المنطقي الأساسي للتفضيلات التي يديرها ARGVUS، و`argvus-config` هو المكون الوحيد الذي يكتب الملفات أسفل `data/generated/`. تظل الملفات الأصلية والملفات التي تم إنشاؤها بمثابة توقعات توافق أو تجاوزات خاصة بالتطبيق.

## دليل المستخدم: البدء السريع

بالنسبة لمعظم المستخدمين، يتم التكوين من خلال مركز التحكم ARGVUS أو أداة سطر الأوامر هذه:

```sh
# View your configuration location and validate it
argvus config path
argvus config validate

# Get a specific value
argvus config get /appearance/theme
argvus config get /appearance/theme --raw    # Without JSON formatting

# Set a value (must be valid JSON)
argvus config set /appearance/theme '"gruvbox-dark"'

# Apply changes to reload the session
argvus config apply
```

بالنسبة للمسؤولين والتكوين المتقدم، تابع القراءة أدناه.

يحتوي جذر المستخدم فقط على المستند الأساسي والبيانات المُدارة:

```text
~/.config/argvus/
├── config.json
└── data/
```

تتم كتابة الملف ذريًا، ويظل خاصًا للمستخدم، ومحميًا بواسطة `.config.lock`، خارج شجرة `data/` التي يمكن تبديلها أثناء العرض. يتم تخزين الإصدار السابق في `data/backups/config.json.bak`.

## سطر الأوامر

يتم توفير الأمر الفرعي `argvus config` أثناء العملية بواسطة الحزمة `argvus`:

```sh
argvus config path
argvus config validate
argvus config ensure
argvus config migrate
argvus config status
argvus config explain /layout/gaps_out
argvus config get /appearance/theme --effective --raw
argvus config set /appearance/accent '"#61AFEF"'
argvus config patch appearance-patch.json
argvus config audio volume +5
argvus config audio mute toggle
argvus config apply-theme universe --variant sticky --accent '#EEEEEE' --gtk-mode dark
argvus config apply-theme universe-spaced --variant spaced --accent '#EEEEEE' --gtk-mode dark
argvus config theme-manifest universe-spaced
argvus config unset /appearance/accent
argvus config apply
argvus config rebuild
argvus config project
argvus config project --force
```

`ensure` يجسد `config.json` جديد باستخدام الإعدادات الافتراضية للمخطط، أو عمليات التعبئة
الحقول المفقودة دون استبدال القيم الصريحة. فشل في JSON المشوه.
يقوم `migrate` باستيراد حالة المظهر القديم الموجودة بدون استبدال القيم
موجود بالفعل في `config.json`. `argvus sessionctl` يقوم بتشغيل `recover`، `ensure`،
`migrate` و`project` قبل تطبيق إعادة التحميل بعد تغييرات التكوين:

```sh
argvus sessionctl apply-config
```

`apply` و`rebuild` هي أسماء مستعارة لإعادة بناء كل عرض من
`config.json`; `project` هو التهجئة التاريخية ويقبل `--force`.
يقوم `apply` أيضًا بتفويض إعادة تحميل وقت التشغيل بعد الالتزام إلى `argvus sessionctl`.
قم بتعيين `ARGVUS_NO_RUNTIME=1` للتحضير أو الاختبارات المعزولة.
يحدث الإنشاء في التدريج ويتم تبديل شجرة `data/` فقط بعد كل شيء
تنجح أجهزة العرض. ولذلك حذف `data/generated/` وتشغيله
`argvus config apply` عبارة عن إعادة بناء قابلة للتكرار دون نشر جزء منها
تسلسل مخرجات Hyprland أو شريط المهام. سجلات الأمر المشتقة
تجزئات القسم وقرار وقت التشغيل في
`$XDG_STATE_HOME/argvus/config-projection.json` (عادة
`~/.local/state/argvus/config-projection.json`). لا البيان ولا
الملفات التي تم إنشاؤها هي مصادر الحقيقة. يقوم `apply` بإجراء إعادة التحميل بعد الالتزام
من خلال `argvus sessionctl`؛ يظل `project` مخصصًا للعرض فقط من أجل التوافق.

تستخدم كل طفرة مستمرة نفس القاعدة: إذا تغيرت الوثيقة الأساسية،
تستدعي واجهة سطر الأوامر (CLI) `argvus sessionctl reload` مركزيًا واحدًا بعد الالتزام. ال
يتم تسجيل نتيجة إعادة التحميل في `data/internal/last-reload.json`.

وبالتالي فإن `argvus sessionctl reload` هي خطوة *تطبيق*، وليست خطوة إسقاط.
عندما يبلغ البيان الوارد عن العمل المعلق فإنه يستعيد الهدف
المستهلكين الموصوفين في الخطة ولا يتصلون بـ `argvus config project` مرة أخرى؛
سيؤدي إعادة الإسقاط إلى إعادة بناء شجرة متطابقة وتجاهل خطة الطفرة
أنتجت للتو. ولا يعود إلى الهجرة والإسقاط إلا عند عدم الالتزام
الخطة موجودة، على سبيل المثال أثناء بدء تشغيل الجلسة.

### إعادة تحميل الأهداف

`argvus config session-plan` يجيب على إعادة التحميل بأهداف
الأقسام التي تغيرت، ويقوم `argvus sessionctl` بتشغيل تلك الأقسام فقط. البقعة
يغطي إعادة التحميل فقط عندما يقوم الهدف بإعادة إنشاء سطح ما: شريط الطريق أو شريط الطريق
تعمل لوحة التحكم التي تتحرك للخلف على الشاشة على تغيير كل نافذة. كل شيء آخر
يعيد في المكان.

| التغيير | الأهداف | سبلاش |
| --- | --- | --- |
| السمة أو لون التمييز أو وضع GTK | `hyprland`، `consumers`، `wallpaper`، `polkit` | لا |
| ورق جدران فقط | `wallpaper` (hyprpaper IPC؛ يتم إعادة تشغيل الخدمة فقط لـ swaybg) | لا |
| `effects` (التمويه، الرسوم المتحركة، الشفافية، الظل) | `hyprland`, `consumers` | لا || `layout` للنوافذ (الفجوات والحدود) | `hyprland` | لا |
| `layout.taskbar` (الموضع، الهوامش) | `hyprland`، `taskbar`، `widget_telemetry` | نعم |
| `fonts` | `consumers` | لا |
| `control_panel` (سويتش، بطاقات) | `control_panel` | نعم |
| `default_apps`، `keyboard_shortcuts`، `hyprland`، `displays` | `hyprland` | لا |
| `power` | `hypridle` | لا |

يقوم `consumers` بتشغيل `argvus config theme-runtime consumers` (أوراق أنماط الشريط،
لوحة التحكم عبر IPC، وألوان Hyprland، وإعادة تحميل سمة Dunst، وbtop و
كيتي). تؤجل Dunst إعادة تحميل السمة الخاصة بها أثناء تفعيل ميزة "عدم الإزعاج".
يقوم `wallpaper` بتشغيل `argvus config theme-runtime wallpaper`، والذي يُظهر
فعالة `/appearance/wallpaper`. يتم الاحتفاظ بتجزئة `layout.taskbar`
بصرف النظر عن تخطيط النافذة في بيان الإسقاط، فإن تغيير الفجوة يحدث
عدم إعادة تشغيل القضبان. الخطة الاحتياطية `full`، تستخدم عند عدم وجود خطة ملتزم بها
موجود، يعيد تشغيل كل سطح تحت البقعة.

كل تكوين فعال له جيل تشغيلي. يتم تخزينه في
`data/internal/generation.json` وفي بيان الإسقاط تحت
`$XDG_STATE_HOME/argvus/config-projection.json`; فهو ليس جزءًا من ملفات النقاط
التكوين. إعادة تطبيق التكوين الفعال دون تغيير يحافظ على
جيل. يقوم `status` بالإبلاغ عما إذا كان تجزئة البيان وبيانات تعريف الإنشاء و
توافق جميع الملفات التي تم إنشاؤها؛ يقوم `apply` بإصلاح الإسقاط القديم أو غير المكتمل.

`explain /path` يقرأ المحلل مباشرة ويطبع القيمة الفعالة،
المصدر والموضوع والبديل. لا يقوم بتحليل الملفات التي تم إنشاؤها أو إنشاء ملف ثانٍ
قاعدة الأسبقية.

يتم تنفيذ عرض السمة والتأثيرات في `argvus-config` نفسها.
لا يتم عرض معاملة السمة (`argvus theme-switch`، التي تقوم بتشغيل `theme-apply`)، و`argvus config accent`، و`argvus effects-toggle`:
يقومون بالتحقق من صحة، وقفل، والالتزام من خلال واجهة سطر الأوامر (CLI) هذه وبعد ذلكالتوفيق بين المستهلكين الخارجيين الذين لا يستطيعون قراءة `config.json`. `argvus effects-toggle`
هو مندوب رفيع ليس له مخرجات خاصة به. مساعدو المظهر ليسوا أبدا
يتم استدعاؤها بواسطة جهاز العرض، ويجب ألا يكتبوا مطلقًا تحت `data/generated/`.

يعد اختيار كتلة القياس عن بعد لعنصر واجهة المستخدم أمرًا أساسيًا في
`/control_panel/widget_telemetry_blocks`، مصفوفة من أسماء الكتل السبعة
(`system`، `cpu_gpu`، `memory`، `storage`، `processes`، `network`، `keys`). ال
تتم قراءة ملف `$XDG_STATE_HOME/argvus/widget-telemetry-blocks` القديم كملف
احتياطي الهجرة ولا يتم كتابته أبدًا. `كتل تبديل أدوات القياس عن بعد لـ argvus
يقوم set` and ` بحظر جميع تصحيحات المصفوفة الأساسية في كتابة ذرية واحدة، و
يفترض `apply-state` أن التحديد قد تم بالفعل بواسطة المتصل به.

تتبع تباعد Hyprland وتفضيلات الحدود نفس الحدود. ال
مساحات تكوين argvus وأوامر حدود تكوين argvus (وملفاتها التاريخية
أغلفة التوافق) التحديث/التخطيط؛ يولد الصدأ
data/generated/spaces-efficiency.conf وdata/generated/borders-efficiency.conf
ويمتلك التحقق من الصحة وتطبيق hyprctl المباشر. . المسافات و . الحدود هي
دولة الهجرة فقط وليست مصدر الحقيقة أبدًا.

تستخدم حالة وضع Accent وGTK نفس حدود Rust. استخدم "argvus-config
لهجة COLOR` or `argvus لهجة التكوين --theme-default` لملكية اللهجة،
و`argvus config mode toggle|set dark|light` لوضع GTK. التاريخية
تعتبر البرامج النصية الخاصة باللكنة والوضع عبارة عن أغلفة توافقية؛ `.accent-color`,
`.accent-custom` و`.gtk-mode` عبارة عن ملفات ترحيل/عرض فقط.

يتم أيضًا حل مسارات ARGVUS المنطقية بواسطة `argvus config paths`. الإرث
يعرض ملف `paths.sh` وظائف التوافق فقط؛ التجاوزات الأصلية، المستخدم
يتم حل البيانات والبيانات التي تم إنشاؤها والنظام الاحتياطي من خلال نموذج مسار Rust.

يقوم `audio` بتغيير مصدر الإخراج الافتراضي ويسجل النتيجة في `/audio` في خطوة واحدة: `argvus config audio volume <N|+N|-N> [--limit PERCENT]` و`argvus config audio mute <on|off|toggle>`. يقوم بكتابة المخزن دون إعادة تحميل التكوين، لأن قيمة PipeWire موجودة بالفعل. تستخدمها وحدة حجم Waybar ومفاتيح وسائط Hyprland ولوحة التحكم، لذا فإن `argvus config project`، الذي يعرض `/audio` على الحوض، لا يستعيد أبدًا حجمًا قديمًا. يتم تخزين الحجم الذي يزيد عن 100% (تسمح مفاتيح Hyprland بما يصل إلى 150%) على أنه 100.

يطبق `patch` كائن JSON الذي تكون مفاتيحه عبارة عن مؤشرات JSON في كائن مقفل
عملية القراءة والتعديل والكتابة. `apply-theme` ينفذ الذرة المكافئة
معاملة السمة واستبدال أقسام المظهر المُدار من ملف
ملف تعريف المظهر الاختياري للموضوع أو الإعدادات الافتراضية المجمعة.
أوامر التحويل تقوم ببناء `NextUserConfig`، وحل مرحلة `EffectiveConfig`
جميع أجهزة العرض، وبعد ذلك فقط نشر JSON الكنسي. عملية
تتيح علامة `.config-transaction.json` لـ `argvus config recover` إعادة العرض
التكوين السابق بعد حدوث عطل بين البيانات ونشر JSON.
يتم الإعلان عن الإعدادات الافتراضية للموضوع من خلال بيان كل سمة
(`themes/<theme>/theme.toml`): التمييز الافتراضي (`palette.accent`)، نظام ألوان GTK
وورق الجدران. يتم عرض ملفات CSS وLua وRasi وQt منه في بنية السمة.

يؤدي تغيير السمة، بما في ذلك فاتح/داكن، إلى إعادة تعيين لون التمييز إلى اللون الافتراضي للسمة،
حتى عندما يختار المستخدم لونًا مخصصًا: يتم الاحتفاظ باللون المخصص فقط حتى السمة التالية
التغيير. استخدم `argvus config accent` بعد تغيير السمة لتعيينها مرة أخرى. تطبيق أ
السمة مع `argvus config theme-apply` تكتب `/appearance/accent` و`/appearance/gtk_mode`
من البيان، ويقوم `argvus config accent` بكتابة اللون المختار باستخدام `accent_custom`
تعيين، في أمر واحد.

يأخذ `apply-theme` المتغير بشكل صريح كـ `--variant sticky|spaced` و
يحل الاسم المطلوب من خلال البيان، لذلك لا يمكن للطلب أبدًا
حل لأصول البديل الآخر. `theme-manifest THEME` هو نفسه
الدقة المكشوفة للقراءة فقط: تقوم بطباعة إدخال البيان مع الملف
`asset_id` و`layout_variant` تم حلها، وهو ما يحتاج المتصل إلى فعله
معالجة الأصول المعبأة. Sticky هو المعرف غير المُلحق ولا يحمل سوى Spacedلاحقة `-spaced`، لذا فإن `dracula-sticky` و`argvus-dark-dracula-sticky` هما
تم قبوله وتطبيعه إلى `dracula`.

باستخدام `--raw`، تتم طباعة قيم السلسلة بدون علامات اقتباس JSON، بينما تظل الكائنات والمصفوفات قيم JSON. لم تعد ملفات النقاط الخاصة بالموضوع والتخطيط تتم كتابتها بواسطة مساعد العرض؛ يظل `config.json` هو المصدر الدائم الوحيد لتلك التفضيلات. إذا فشل العرض، فستتوقف إعادة تحميل الجلسة قبل إعادة تشغيل أسطح سطح المكتب، لذلك لا يتم عرض السمة الجزئية الأقدم على أنها حالية.

## التصدير والاستيراد

يتم استخدام نفس النموذج المنطقي لتبادل الملفات الشخصية:

```sh
argvus config export --scope appearance --output appearance.json
argvus config import --scope appearance appearance.json
```

استخدم `--scope desktop` للحصول على نموذج سطح المكتب المُدار الكامل. تستخدم الحقول المفقودة إعدادات ARGVUS الافتراضية؛ لا ينبغي تحرير المخرجات التي تم إنشاؤها مباشرة.

يقوم تصدير واستيراد سمة مركز التحكم بتبادل السمة وملف التعريف المرئي الخاص بها: يحتوي الأرشيف على دليل سمة المخطط 2 (`<id>/theme.toml`، `appearance.json` الاختياري و`effects.conf`، `overrides/`، خلفية الشاشة) التي يتم تثبيتها تحت `$XDG_DATA_HOME/argvus/themes/`. يحتوي الملف الشخصي على المظهر وهندسة التخطيط والمؤثرات المرئية والخطوط وعرض اللوحة. يظل الصوت ولوحة المفاتيح والشبكة والتفضيلات غير المرئية الأخرى خارج السمات. استخدم نطاق `appearance` أعلاه لنقل تكوين المظهر الكامل، ونطاق `desktop` للنسخ الاحتياطي الكامل للتكوين.

يقوم المخطط الحالي بتجميع التفضيلات ضمن `appearance`، `layout`، `effects`، `fonts`، `control_panel`، `default_apps`، `keyboard_shortcuts`، و`hyprland`، و`displays`، و`power`، و`session`، و`calendar`، و`removable_devices`. `default_apps` هو المصدر المستمر الوحيد للتطبيقات المفضلة، ويقوم `keyboard_shortcuts` بتخزين المفاتيح الإنجليزية المستقرة والمستقلة عن الإعدادات المحلية مع قيم السلسلة أو `null` للارتباطات المعطلة.

يقرأ مركز التحكم قيم المظهر الأساسية عندما يفتح صفحة المظهر ويكتب التغييرات من خلال `argvus-config`. تظل ملفات الحالة الأصلية الموجودة بمثابة إسقاطات لنصوص المظهر والتثبيتات الأقدم.

تستخدم لوحة التحكم `control_panel.cards` لطلب البطاقة وإمكانية رؤيتها، و`control_panel.enabled` للمفتاح الرئيسي للوحة. ويتم الاحتفاظ بملفات `control-panel/cards.json` و`state/control-panel` كإسقاطات توافق. وبالتالي فإن التغييرات التي تم إجراؤها في لوحة التحكم تعد جزءًا من نطاق التصدير `desktop`.

تستخدم تفضيلات الخط `fonts.targets` لعائلة ونمط وحجم شريط المهام والقياس عن بعد ولوحة التحكم والنظام والتطبيقات والمحطة الطرفية وأهداف المتصفح. يقوم `fonts.rendering` بتخزين الحواف والتلميحات وترتيب البكسل الفرعي وتفضيلات DPI. `fonts.conf` وقاعدة تكوين الخط وإعدادات سطح المكتب وكتل الخطوط المُدارة داخل أوراق أنماط Waybar هي إسقاطات: يستمر مركز التحكم في `/fonts/targets/*` حتى `argvus-config`، ويعيد جهاز العرض كتابة الكتلة المحددة الخاصة به فقط.

تستخدم تفضيلات Hyprland `keyboard_shortcuts` للاختصارات، و`hyprland.input` لإعدادات الماوس ولوحة اللمس، و`hyprland.keyboard` لتخطيط XKB ومتغيره وخياراته. يتم تعيين معرف ربط البيان إلى `config_key` المستقر (على سبيل المثال `window.close` → `close_window` و`window.drag_mouse` → `drag_window__floating_window_only`). تستخدم تفضيلات العرض `displays.monitors`، و`displays.workspaces`، و`displays.primary_monitor`. تظل ملفات TOML الأصلية وملفات Lua التي تم إنشاؤها ضمن `data/generated/` إسقاطات تستهلكها Hyprland. يتم تمكين كل محول `effects` بشكل افتراضي (الرسوم المتحركة، والتمويه، والقياس عن بعد لعنصر واجهة المستخدم وكل سطح شفاف)، على الأجهزة الافتراضية وجلسات الطاقة المنخفضة أيضًا؛ ظل النافذة (`shadow_enabled`) والتمايل (`wobble_enabled`) افتراضيًا على إيقاف التشغيل. تستخدم تفضيلات التأثير `effects` لمفتاح الرسوم المتحركة الرئيسي (`animations`، المطبق على `hyprland.lua` من `hypr/state.lua` المتوقع، بشكل مستقل عن مفتاح التأثيرات، وهو `blur_global_enabled` بالإضافة إلى `transparency_<surface>_enabled` من `taskbar`، و`control-panel`، و`widget-telemetry`، و`terminal`، و`launchers`، ويتم قراءته على أنه ممكّن عند تمكين أي منها؛ `argvus effects-toggle animations|effects` تبديلها)، مفتاح التمويه العالمي (`blur_global_enabled`)، معلمات Hyprland التمويه (`blur_size`، `blur_passes`، `blur_brightness`، `blur_noise`، `blur_contrast`، `blur_vibrancy`، `blur_vibrancy_darkness`)، ظل النافذة (`shadow_enabled`، `shadow_sharp`، `shadow_color`، `shadow_range`، `shadow_render_power`، `shadow_offset_x`، `shadow_offset_y`، `shadow_scale`)، قيم الرسوم المتحركة (`animation_<leaf>_speed`، `_curve`، `_style`، `_popin` و`_enabled` لكل رسم متحرك، بالإضافة إلى `animation_bezier_x1` إلى `animation_bezier_y2` و`animation_spring_mass` و`animation_spring_stiffness` و`animation_spring_dampening` للتخصيص المنحنيات) وقيم الشفافية لكل سطح. التأثيرات مملوكة للموضوع، وليست مملوكة للمتغير: يستخدم Sticky وSpaced نفس إسقاط تأثيرات `<theme>.conf` بينما تختلف توقعات التخطيط الخاصة بهما. تشتمل الأسطح حاليًا على `taskbar` و`control-panel` و`widget-telemetry`؛ قيم الشفافية هي نسب مئوية من `0` إلى `100` (مركز التحكم وأسطح المشغل الافتراضية هي `15`، والأسطح الأخرى هي `50`)، ومعلمات التمويه هي أرقام ضمن النطاقات المعلنة في `schema.json`، والحالات الممكنة هي قيم منطقية. يتم التحقق من صحة قيم الرسوم المتحركة بواسطة `argvus-config` أيضًا: السرعات هي أرقام من `1` إلى `10` (مسموح بالأرقام العشرية)، والنسب المئوية المنبثقة هي أرقام صحيحة من `1` إلى `100`، ويجب أن تكون المنحنيات أسماء من الرسوم المتحركة الصفحة، يجب أن تكون الأنماط عبارة عن أسماء من صفحة الرسوم المتحركة وقبولها بواسطة صفحة الرسوم المتحركة الخاصة (على سبيل المثال، تم رفض `popin` لـ `animation_workspace_in_style`، ويتم قبول `gnomed` فقط لفتح النافذة وإغلاقها، ويتم رفض متغيرات الشريحة على النافذة وأوراق الطبقة)، وتبقى نقاط Bézier Y بين `-1` و`2`، ويوزع النطاق Hyprland 0.56.2 ومعلمات المنحنى الأخرى ضمن نطاقاتها الموثقة. لم يعد `layers` و`switching` موجودين، لذا فإن التكوينات المحفوظة قبل إزالتها تفقد مفاتيح `animation_layers_enabled` و`animation_layers_speed` و`animation_layers_curve` و`animation_switching_*` عند تحميلها. يتم إسقاط الأنماط خارج المجموعة الحالية ويتم تثبيت نقاط Bézier Y خارج `-1` إلى `2`، بحيث تنطبق الإعدادات الافتراضية المجمعة مرة أخرى على كل ما تمت إزالته.

تستخدم تفضيلات الطاقة `power.screen_off_minutes`، و`power.lock_minutes`، و`power.keep_awake`، وسياسات الغطاء/زر التشغيل. النماذج المسقطة هي `data/generated/hypr/hypridle.conf` والعلامة `data/power/keep-awake`؛ `.keep-awake` هو مدخل ترحيل فقط. تم إيقاف `session.language`: يتم تجاهل القيم الحالية، ويتم رفض عمليات الكتابة الجديدة، ولا يتم عرض أي ملف توافق لغة. قم بتعيين `LANG` في المستخدم `locale.conf` بدلاً من ذلك. تستخدم تفضيلات التقويم `calendar` ويتم عرضها على TOML مستخدم تقويم شريط المهام. تستخدم تفضيلات الجهاز القابل للإزالة `removable_devices`؛ يعامل تطبيق الأجهزة القابلة للإزالة هذا القسم باعتباره تجاوزًا للمستخدم للإعدادات الافتراضية المجمعة. يقوم `migrate` باستيراد الملفات والأقسام الجذرية القديمة مرة واحدة، مع الاحتفاظ بالقيمة الأساسية الموجودة. يتم نقل Legacy `defaults.json`، و`/defaults`، و`/hyprland/keybindings`، و`keybindings.toml`، وملفات النقاط، و`generated/` وأدلة المكونات إلى أسفل `data/`؛ لا تؤدي عمليات إعادة التحميل المتكررة إلى إعادة إنشاء تخطيط الجذر القديم. يعد تحديد السمة الحالية مرة أخرى أمرًا غير فعال: إذا كانت الحالة الأساسية والإسقاطات متفقة بالفعل، فإن خطة الإسقاط تشير إلى عدم وجود أقسام متغيرة وتتخطى الجلسة البداية وتتم إعادة تشغيل الخدمة.

تتبع الطاقة نفس عقد الإسقاط: يقوم مركز التحكم بكتابة `/power` في `config.json`، ويعرض `argvus config project` `data/hypr/hypridle.conf` ذريًا، وعندها فقط يمكن لـ `argvus sessionctl` إعادة تشغيل `argvus-hypridle.service`. يمكن استرداد هذا الملف باستخدام `argvus config project`؛ قيمة `0` تحذف المهلة المقابلة وتعني أبدًا.

يتم عرض مظهر شاشة القفل بواسطة Rust من السمة الأساسية، واللكنة،
التأثيرات وورق الحائط وحالة الخط في `data/hypr/hyprlock.conf`. التاريخية
نقطة الإدخال `hyprlock-theme.sh` هي نقطة توافق فقط ومفوضة إلى
`argvus config lock apply`; `--invalidate` يبطل فقط التشويش المشتق
ذاكرة التخزين المؤقت للخلفية.

تستخدم تغييرات مهلة الطاقة `/power/lock_minutes` و
`/power/screen_off_minutes` كمصدر الحقيقة. `argvus config project`
إعادة استخدام جهاز عرض Hypridle الموجود، ونقطة الدخول `idle-timeout.sh` هي
فقط محول التوافق؛ تظل إعادة تشغيل الخدمة مفوضة إلى
`argvus sessionctl`.

مظهر الإشعارات مشتق من السمة الأساسية واللكنة و
التأثيرات إلى `data/notifications/dunstrc`. الإخطارات التاريخية
يعرض ملف `theme.sh` فقط وظائف التوافق التي تستدعي
`argvus config notifications`; ولا يقوم بتحليل أو تغيير تكوين Dunst.

المحولات الموجهة نحو الأجهزة مثل اكتشاف العرض والتحكم عبر Bluetooth
تم استيراده الآن بواسطة مجال عرض Rust: `nwg-displays` هو مستورد خارجي،
بينما يظل `/displays` و`data/generated/hypr/monitors.lua` أساسيين و
الحالة المشتقة على التوالي. تقوم أدوات العرض بتغيير التخطيط باستخدام
`argvus config monitor-set`، `monitor-primary`، `monitor-workspaces` و`monitor-remove`؛ أوامر العرض هي `argvus config display status|list-modes|set|apply|apply-nwg|migrate-nwg|nwg-import|nwg-apply`. يتم عرض ملف Hyprland من `/displays`؛ لم يعد هناك برنامج نصي لشل يكتبه بعد الآن. اختيار ورق الحائط، ووضع مجموعة الأدوات المساعدة لشريط المهام،
ويستخدم البحث الافتراضي عن التطبيق أيضًا واجهات برمجة التطبيقات `argvus-config`؛ شلتهم التاريخية
نقاط الدخول هي واجهة المستخدم أو أغلفة التوافق. Keep Awake هو برنامج مثابر
تم عرض تفضيل `/power/keep_awake` على علامة `data/power/keep-awake`،
بينما يكون lock-DPMS في حالة وقت تشغيل الجلسة ضمن
`$XDG_CACHE_HOME/argvus/lock-dpms`. تخطيط لوحة المفاتيح مملوك الآن لشركة Rust
مساعد `argvus-keyboard-layout`: يأتي الترتيب الذي تم تكوينه من الملف الذي تم إنشاؤه
إسقاط إدخال Hyprland أو اللغة الاحتياطية، بينما يظل التخطيط النشط
تم اكتشاف حالة وقت تشغيل الجلسة من Hyprland. نقطة دخول الدورة و
البرنامج الخفي لتخطيط لوحة المفاتيح عبارة عن أغلفة توافقية فقط؛ يتم تشغيل خدمة المستخدم
برنامج Rust الخفي مباشرة و `argvus sessionctl keyboard-layout cycle` هو
أمر مستقر للمتصلين.

تتبع حالة وقت تشغيل Bluetooth حدود المحول الخارجي ولكنها ليست جزءًا
من `argvus-config`: يمتلك `argvus bluetooth` التحليل المكتوب و
التحقق من الصحة حول `bluetoothctl`، وإعادة المحاولة المحدودة، وفحوصات خدمة النظام و
حالة RFKill. `argvus bluetoothctl` هي نقطة الدخول. طاقة المحول والأجهزة المقترنة والأجهزة المتصلة
تظل حالة وقت تشغيل BlueZ بدلاً من حالة JSON الأساسية؛ الأجهزة الحية
يعتمد التحقق من صحة Bluetooth على البيئة.
## هوية وقت التشغيل والمصالحة

استخدم `argvus config status --verbose` لفحص الملف الثنائي الدقيق
الهوية وجذر التكوين والجذر الذي تم إنشاؤه وجذر الأصل ومصدر البيان و
الجيل النشط. يُبلغ عن `synchronized`، `stale`، `incomplete`، `legacy`
وحالات الإسقاط `pending-transaction`.

يقوم `argvus config --version` بالإبلاغ عن إصدار الحزمة، ومراجعة البناء عند توفيرهبواسطة بيئة البناء، والملف الشخصي. يجب أن تحقن اختبارات التطوير الخاصة بهم
الثنائية والأصول صراحة؛ يجب ألا يستخدموا `argvus config` بصمت
أو `~/.config/argvus`. يعمل `apply` على تطبيع المعرفات المجمعة القديمة بشكل آمن
مثل `argvus-dark-spaced` في سمة منفصلة وقيم متغيرة من قبل
إعادة بناء التوقعات. لم يتم تسجيل هوية الأصول المجمعة في بيان في هذا الإصدار.

### إعدادات التذبذب (Hyprland 0.57+)

`effects.wobble_enabled`، `wobble_stiffness`، `wobble_damping`، `wobble_mass`،
مشروع `wobble_intensity` و`wobble_mesh` مباشرة في `hypr/state.lua`.
استخدم `argvus effects-toggle wobble-settings get` لقراءتها، أو
`argvus effects-toggle wobble-settings set enabled=enabled stiffness=100 damping=10 mass=1 intensity=1 mesh=8`
لحفظ وطلب إعادة التحميل. يقوم `enabled=disabled` بإيقاف تشغيل التأثير.

يشارك مركز التحكم مسودة الرسوم المتحركة: `animations-settings get` أيضًا
تقوم بإرجاع إدخالات `wobble_*`، ويقبل `animations-settings set` هذه الأسماء الكاملة
إلى جانب وسيطات الرسوم المتحركة الموجودة بها. هذا يستمر في المسودة بأكملها في واحدة
تم التحقق من صحة التصحيح ويطلب إعادة تحميل واحدة. على سبيل المثال:

```sh
argvus effects-toggle animations-settings set enabled=enabled wobble_enabled=true wobble_intensity=0 wobble_mesh=8
```

يتحكم `enabled` العالمي في الرسوم المتحركة؛ `wobble_enabled` مستقل عنها
التفضيل. يؤدي تعطيل الرسوم المتحركة العالمية إلى منع التذبذب في Lua دون مسحه
هذا التفضيل. القيم غير الصالحة ترفض التصحيح بأكمله. تلقي المفاتيح المفقودة
يتم تعيين إعدادات ARGVUS الافتراضية دون استبدال الاختيارات الموجودة. انظر [المظهر](/docs/user-guide/appearance/#window-wobble)
للحدود والافتراضيات.


### اختصارات لوحة المفاتيح التي أنشأها المستخدم

يحتفظ `/keyboard_shortcuts` بقيم السلسلة أو القيم الخالية الحالية لإجراءات البيان الرسمية. تستخدم اختصارات لوحة المفاتيح العامة المخصصة كائن `/hyprland/custom_shortcuts` منفصل، مخزن في `config/hyprland.json`. معرفات `custom_` الثابتة مستقلة عن الأوصاف واللغات. يحتوي كل سجل على `description` و`keys` و`enabled` و`action` المكتوب:

```json
{
  "custom_editor": {
    "description": "Open my editor",
    "keys": "SUPER + CTRL + E",
    "enabled": true,
    "action": { "type": "command", "command": "editor --new-window" }
  },
  "custom_float": {
    "description": "Toggle floating",
    "keys": "SUPER + CTRL + F",
    "enabled": false,
    "action": {
      "type": "dispatcher",
      "dispatcher": "window.float",
      "arguments": { "action": "toggle" }
    }
  }
}
```

المثال هو قيمة `/hyprland/custom_shortcuts`، وليس مستند تكوين كامل. تأتي أسماء المرسلين من مصانع المرسلين المدعومة في Lua؛ الوسائط عبارة عن كائن JSON اختياري أو `null`، ولم يتم تقييمها مطلقًا. لا تحتوي الاختصارات المخصصة على خريطة فرعية أو ربط بالماوس أو علامات متقدمة. يقوم الإسقاط بكتابة `data/generated/hypr/custom-shortcuts.lua` كجدول بيانات تم تجاوزه، بما في ذلك جدول فارغ عند إزالة السجل الأخير. يقوم كل من الإسقاط الكامل و`project --only keyboard_shortcuts` بإنشائه. تقوم Hyprland بتسجيل الإدخالات الممكّنة باستخدام `hl.bind`؛ يتم احتواء وتسجيل الملفات الاختيارية وحالات فشل التسجيل الفردي.

يقوم مركز التحكم بإنشاء/تحرير السجلات وتعطيل التعارضات المؤكدة باستخدام معاملة `argvus config patch` واحدة. يتم حفظه قبل التقديم من خلال خدمة التكوين الموجودة. لا يؤدي التطبيق الفاشل إلى التراجع عن الحفظ الناجح. تؤدي استعادة الإعدادات الافتراضية الرسمية إلى الاحتفاظ بالسجلات المخصصة ويتم رفضها إذا كانت ستتعارض مع اختصار مخصص نشط. تظل أوصاف المستخدم نصًا حرفيًا في جميع اللغات وورقة الغش الفعالة التي تم إنشاؤها.

## وضع النافذة العالمية

افتح **مركز التحكم → سطح المكتب والإدخال → Hyprland → Windows → الوضع** وحدد **تجانب النوافذ (افتراضي)** أو **النوافذ العائمة**. يتوفر نفس المحدد من أيقونة وضع النافذة في مجموعة الأدوات المساعدة لشريط المهام.

ينطبق التفضيل على كل شاشة ومساحة عمل ويتم تذكره بعد تسجيل الخروج. يقوم العائم بتحويل نوافذ التطبيقات الموجودة والنوافذ المفتوحة حديثًا. يقوم Tile باستعادة النوافذ التي حولتها هذه السياسة فقط؛ تظل مربعات الحوار والنوافذ الأخرى التي كانت عائمة بالفعل عائمة. تظل النافذة المثبتة بشكل صريح أثناء تنشيط Floating عائمة أيضًا للحفاظ على رقم التعريف الشخصي الخاص بها. تتم إعادة حساب التخطيط المتجانب؛ لم تتم استعادة شجرتها المنقسمة السابقة بالضبط. يحافظ `SUPER + SHIFT + Space` على سلوكه الطبيعي لكل نافذة في Tile. في الوضع العائم، لا يؤدي ذلك إلى إعادة النافذة إلى التبليط. اللوحات وشريط المهام والإشعارات عبارة عن أسطح ذات طبقات ولا تتأثر. يستمر ملء الشاشة والتكبير في استخدام سلوك Hyprland الطبيعي.

التفضيل المتعارف عليه هو `/hyprland/window_mode` في `$XDG_CONFIG_HOME/argvus/config/hyprland.json`. الإسقاط الذي تم إنشاؤه هو `data/generated/hypr/window-mode.lua`؛ لا تقم بتحريره. يقع سجل الاستعادة لكل نافذة تحت `$XDG_RUNTIME_DIR/argvus`، ويمتد إلى مثيل المنضد، ويستمر في عمليات إعادة تحميل التكوين. ولا يتم إعادة استخدامه في جلسة جديدة.

إذا كان التطبيق معلقًا أو فشل، فإن الواجهة تميز ذلك عن التفضيل المحفوظ. حدد الخيار مرة أخرى لإعادة المحاولة. بدون منسق، يتم حفظ التفضيل لتسجيل الدخول التالي.

```sh
argvus config window-mode get
argvus config window-mode status --json
argvus config window-mode set floating
argvus config window-mode set tile
argvus config window-mode toggle
```

## أزرار النافذة وشريط التطبيقات

يضيف الوضع العائم شريط عنوان ARGVUS مع **تصغير**، **تكبير / استعادة**، و**إغلاق** إلى نوافذ التطبيق العادية. يؤدي النقر المزدوج على شريط العنوان إلى تبديل التكبير. الزخرفة الإضافية مخفية في البلاط وفي وضع ملء الشاشة. قد تعرض التطبيقات التي ترسم عناصر التحكم الخاصة بها كلا الشريطين؛ ضوابط ARGVUS الموحدة مقصودة.

يظهر شريط الطريق الثاني على كل شاشة، على الحافة المقابلة لشريط المهام الرئيسي. فهو يسرد فقط النوافذ التي تنتمي إلى مساحة العمل الحالية لجهاز العرض، بما في ذلك النوافذ المصغرة من مساحة العمل تلك. مساحة العمل الخاصة المفتوحة لها الأسبقية. تظل النوافذ المثبتة مرئية؛ لا تؤدي علامات تبويب المجموعة المخفية إلى إنشاء إدخالات إضافية، وتشتمل المجموعة المصغرة على إدخال استرداد واحد. لا يتم تعداد علامات التبويب الموجودة داخل التطبيق بشكل منفصل. تحتفظ الإدخالات المصغرة باقتران الشاشة/مساحة العمل الأصلية الخاصة بها. انقر فوق نافذة غير نشطة لتنشيطها، أو نافذة نشطة لتصغيرها، أو نافذة مصغرة لاستعادتها؛ توفر قائمة السياق الخاصة بها الاستعادة والتصغير والتكبير/الاستعادة والإغلاق. تعود أيقونات التطبيقات غير المعروفة إلى رمز النافذة. يؤدي تنشيط إدخال أو استعادته إلى الحفاظ على موضع المؤشر. يستخدم الشريط الثانوي لغة CSS الأساسية الفعالة (الألوان والخطوط والحدود والتقريب)، مع ارتفاعه وهوامشه المنعكسة على الحافة المقابلة.

يضع `SUPER + Alt + Up` الشريط الرئيسي في الأعلى وشريط النافذة في الأسفل. `SUPER + Alt + Down` يقوم بالعكس. تكرار الاتجاه يترك المواقف دون تغيير. يحتوي البلاط على الشريط الرئيسي فقط. تؤدي العودة إلى التجانب إلى استعادة جميع النوافذ المصغرة قبل إزالة شريط النافذة، ثم الحفاظ على سياسة التجانب/العائمة الأصلية.

يستخدم التصغير مساحة العمل المحجوزة `special:argvus-minimized`. لا تستخدم مساحة العمل هذه يدويًا. تسجل عملية `argvus windows service` الهوية ومساحة العمل/الشاشة الأصلية والشكل الهندسي وملء الشاشة/التكبير وحالة الدبوس في سجل وقت تشغيل خاص بمثيل المركبة ضمن `$XDG_RUNTIME_DIR/argvus`. تستمر السجلات في البقاء بعد إعادة تشغيل الخدمة أو إعادة تحميل التكوين، ولكنها لا تتقاطع مع جلسات عمل المُركب. يؤدي إغلاق النافذة إلى إزالة السجل الخاص بها. إذا اختفت الشاشة، فإن عملية الاستعادة تستخدم المخرجات المتوفرة. يمنع شريط الاسترداد المفقود أو الفاشل إجراء عمليات تصغير جديدة؛ تحتفظ عملية الاستعادة الفاشلة بشريط السجل والاسترداد.

تمتلك الجلسة `argvus-windows.service` و`argvus-window-bar.service`. هذا الأخير يبقي طفل Waybar الخاص به خاملًا في Tile. تم تجميع البرنامج المساعد hyprbars بواسطة `argvus-hyprland`، المصمم لـ Hyprland 0.57.0 ABI على x86_64؛ لم يتم تجميعه في الدليل الرئيسي للمستخدم. أعد بناء المكوّن الإضافي باستخدام تحديث ABI للمركب.

الأوامر: `argvus windows list --json`، و`watch --json`، و`position top|bottom`، و`restore-all`، و`minimize|restore|activate|maximize|close ADDRESS`. عناوين النافذة تأتي من القائمة. يقوم `position top --persist` بتخزين/عرض التفضيلات دون إعادة تشغيل الشريط الرئيسي. تتم كتابة تفاصيل أخطاء التكوين ووقت التشغيل إلى المجلة؛ تُظهر حالات فشل الإجراء المرئي أيضًا إشعارًا مترجمًا. في **المتباعدة + العائمة**، تحترم النوافذ الفجوات الخارجية والمناطق المحجوزة بواسطة كلا الشريطين. تتضمن الحدود الحد والعنوان الموجود داخل حدود النافذة نفسها. يؤدي تعظيم عناصر تحكم ARGVUS إلى ملء هذه المنطقة بالهوامش؛ تعمل عملية الاستعادة على استعادة الشكل الهندسي السابق، بما في ذلك بعد إعادة تشغيل الخدمة. لا يزال ملء الشاشة يستخدم الإخراج بالكامل. قد تتداخل النوافذ العائمة؛ تبليط الفجوات الداخلية لا يفصل بينهما.

لا يتم احتساب الهوامش الداخلية المحفوظة بواسطة الأشرطة مرتين في الفجوات الخارجية للنافذة. مع التباعد المتماثل، تكون المسافة المرئية من النافذة إلى الشريط متساوية في الأعلى والأسفل، بما في ذلك بعد تبديل الأشرطة.

يقوم `SUPER + Alt + Space` بتبديل وضع التجانب/العائم العام، باستخدام نفس التفضيلات مثل شريط المهام ومركز التحكم. الأمر المكافئ هو `argvus config window-mode toggle`. يتم إجراء تسلسل الاستدعاءات المتزامنة؛ يستخدم التبديل التفضيل المحفوظ حتى عندما يكون التطبيق معلقًا. يمكن تغيير الاختصار أو تعطيله في اختصارات لوحة المفاتيح؛ يحتفظ `SUPER + Shift + Space` بعمل النافذة الفردية.

**کنٹرول سینٹر> ڈیسک ٹاپ اور ان پٹ> ڈسپلے> نائٹ لائٹ** کھولیں، **نائٹ لائٹ** تلاش کریں، یا `argvus control-center displays night-light` چلائیں۔

نائٹ لائٹ اور اس کا شیڈول ابتدائی طور پر بند ہے۔ **1000 سے 20000 Kelvin** (پہلے سے طے شدہ **4500 K**) کے درمیان درجہ حرارت کا انتخاب کریں۔ نچلی قدریں گرم رنگ دیتی ہیں۔ صفحہ محفوظ شدہ دستی ایکٹیویشن، موثر حالت اور اگلی منتقلی دکھاتا ہے۔ ایک قدر میں ترمیم کریں Esc اسے منسوخ کرتا ہے یا ڈسپلے پر واپس آتا ہے۔ غلط اقدار کو بچانے سے پہلے انکار کر دیا جاتا ہے۔ تبدیلیاں محفوظ کریں اور فوری طور پر لاگو کریں۔ اگر محفوظ کرنے کے بعد اپلائی کرنا ناکام ہوجاتا ہے، تو محفوظ شدہ ترجیح اصل موثر حالت اور خرابی کے ساتھ ساتھ نظر آتی ہے۔

## شیڈول اور فوری اقدامات

مقررہ شیڈول موجودہ مقامی ٹائم زون کا استعمال کرتا ہے۔ آغاز شامل ہے اور اختتام کو خارج کر دیا گیا ہے۔ **20:00–07:00** آدھی رات کو کراس کرتا ہے۔ شروع اور اختتام میں فرق ہونا چاہیے اور `HH:MM` استعمال کریں۔ کوئی مقام یا شمسی کیلکولیشن استعمال نہیں کیا جاتا ہے۔

فوری ٹوگلز کے لیے کنٹرول پینل کا **ڈسپلے** کارڈ یا **SUPER+Shift+B** استعمال کریں۔ برائٹنس سلیکٹر اپنی تمام برائٹنس ایکشنز کو برقرار رکھتا ہے اور بیک اینڈ دستیاب ہونے پر نائٹ لائٹ شامل کرتا ہے، بشمول برائٹنس بیک اینڈ کے بغیر ڈسپلے پر۔ کوئی مستقل ٹاسک بار ماڈیول نہیں ہے۔

شیڈولنگ آف کے ساتھ، دستی ایکٹیویشن مستقل ہے۔ شیڈولنگ آن کے ساتھ، ایک فوری ٹوگل اگلی طے شدہ منتقلی تک رن ٹائم اوور رائیڈ بناتا ہے۔ شیڈول یا درجہ حرارت کو تبدیل کرنے سے وہ اوور رائڈ ہو جاتا ہے۔ لاگ آؤٹ، ایک نیا کمپوزیٹر مثال یا تبدیل شدہ اگلی منتقلی (بشمول ٹائم زون کی تبدیلی) بھی اسے باطل کر دیتی ہے۔

## احکامات اور ریاست

تمام انٹرفیس ایک ہی عوامی کمانڈ استعمال کرتے ہیں:

```sh
argvus config display night-light status
argvus config display night-light enable
argvus config display night-light disable
argvus config display night-light toggle
argvus config display night-light temperature 4500
argvus config display night-light schedule on 20:00 07:00
argvus config display night-light schedule off 20:00 07:00
argvus config display night-light apply
argvus config display night-light apply-schedule
```

`status` returns JSON schema version 1: `available`, `unavailable_reason`, `settings` (enabled, temperature, schedule_enabled, start, end), `active`, `effective_temperature`, `mode` (`manual` or `scheduled`), `manual_override`,`next_transition` (آفسیٹ کے ساتھ ISO 8601)، `minimum_temperature` اور `maximum_temperature`۔ جب دستیاب نہ ہوں تو موثر فیلڈز کالعدم ہو جاتے ہیں۔ جب شناخت فعال ہو تو موثر درجہ حرارت کالعدم ہے۔ دستیابی کی ناکامیوں کی حالت میں اطلاع دی جاتی ہے؛ کارروائی کی ناکامی a کے ساتھ غیر صفر واپس آتی ہے۔تشخیصیکینونیکل ترجیح `/displays/night_light` ہے، `argvus config` کے ذریعے `$XDG_CONFIG_HOME/argvus/config/displays.json` میں جوہری طور پر ذخیرہ کیا گیا ہے۔ غیر مستحکم اوور رائیڈز اور ایکشن لاک `$XDG_RUNTIME_DIR/argvus/night-light/` کے تحت رہتا ہے۔ تیار کردہ مانیٹر فائلیں آزاد ہیں۔ اس خصوصیت کو ترتیب دینے کے لیے تیار کردہ فائلوں میں ترمیم نہ کریں۔

## رن ٹائمHyprland اور **hyprsunset >= 0.4.0** کی ضرورت ہے۔ سیشن اپ اسٹریم `hyprsunset.service` کو ایک بار شروع کرتا ہے، `argvus-night-light-init.service` کے ذریعے محفوظ شدہ حالت کا اطلاق کرتا ہے، اور `argvus-night-light.timer` اور `argvus-night-light.service` کے ذریعے ہر منٹ کے شیڈول کا جائزہ لیتا ہے۔ گھڑی اور ٹائم زون کی تبدیلیاں بھی تشخیص کو متحرک کرتی ہیں۔ شیڈولنگ آف کے ساتھ، متواتر آپریشن صرف دستی حالت کو چھوڑ دیتا ہے۔ بار بار ایپلی کیشنز موثر شناخت/درجہ حرارت سے استفسار کرتی ہیں اور غیر تبدیل شدہ تحریروں کو چھوڑ دیتی ہیں۔ کمپوزیٹر کو دوبارہ لوڈ کرنے کی ضرورت نہیں ہے۔ARGVUS اپ اسٹریم سروس کے لیے ایک سسٹمڈ ڈراپ ان بھیجتا ہے: یہ `--identity` سے شروع ہوتا ہے اور اپنی کنفیگریشن دریافت کو `/usr/share/argvus/session/config/night-light` پر الگ کرتا ہے۔ یہ مسابقتی مقامی پروفائلز سے بچتا ہے اور ذاتی `hyprsunset.conf` فائلوں کو اچھوتا چھوڑ دیتا ہے۔ ڈراپ ان اپ اسٹریم سروس پر لاگو ہوتا ہے جب کہ ARGVUS سیشن ہوتا ہے۔پیکیج انسٹال ہے، بشمول ARGVUS سے باہر شروع ہوتا ہے۔ موجودہ صارف کے سسٹمڈ اوور رائیڈز کو فوقیت مل سکتی ہے۔ اس صورت حال کی تشخیص کرتے وقت `systemctl --user cat hyprsunset.service` کا معائنہ کریں۔ Hyprsunset 0.4.0 `--config` کے علیحدہ راستے کی دلیل کو مسترد کرتا ہے، لہذا کنفگ ڈسکوری کو سروس-لوکل XDG متغیرات سے الگ کر دیا جاتا ہے۔اس کے بجائےبیک اینڈ باونڈڈ I/O کے ساتھ آفیشل Hyprsunset IPC (`temperature`, `identity`, `identity get`) کا استعمال کرتا ہے اور تبدیلیوں کے بعد ریڈ بیک۔ کوئی شیڈر، متبادل کمپوزر بیک اینڈ، سسٹم کنفیگریشن رائٹ یا استحقاق میں اضافہ استعمال نہیں کیا جاتا ہے۔ غیر دستیاب کنٹرول کنٹرول سینٹر میں غیر فعال ہیں اور ڈسپلے کارڈ میں چھپے ہوئے ہیں۔

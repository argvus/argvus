---
title: تھیم اور وال پیپر کی خرابیوں کا سراغ لگانا
description: تھیم کی تشہیر اور پیدا ہونے والی ظاہری فائلوں کی تشخیص کریں۔
---

$XDG_CONFIG_HOME/argvus/config.json میں کینونیکل `appearance ` سیکشن چیک کریں، پھر  `$XDG_CONFIG_HOME/argvus/config.json ` `$XDG_CONFIG_HOME/argvus/data/generated` کے تحت تیار کردہ فائلوں کا معائنہ کریں۔ Legacy dot-files صرف منتقلی کے ان پٹ ہیں۔

`argvus-config ` ` data/generated/` کے نیچے واحد مصنف ہے۔ ٹوٹے ہوئے کو بحال کرنے کے لیے
تھیم یا وال پیپر، کیننیکل دستاویز سے پوری نسل کو دوبارہ بنائیں اور
پیدا کردہ صارفین کو براہ راست ترمیم کرنے کے بجائے نتیجہ کا اطلاق کریں:

```sh
argvus config validate
argvus config apply
argvus sessionctl reload
```

`argvus theme-switch ` (جو ` argvus config theme-apply ` چلاتا ہے) اور ` argvus config accent`
آرکیسٹریٹر ہیں: وہ توثیق کرتے ہیں، تالا لگاتے ہیں، سپلیش دکھاتے ہیں، اس کے ذریعے کمٹ کرتے ہیں۔
`argvus-config` اور پھر ان بیرونی صارفین سے صلح کریں جو پڑھ نہیں سکتے
`config.json `۔ وہ کبھی بھی ` data/generated/` نہیں لکھتے، اور تھیم کا لین دین ہوتا ہے۔
GTK، اسٹوریج یا `mode.css` فائلوں کو علیحدہ اسکرپٹ کے ذریعے نہ لکھیں۔
`argvus config accent --apply` استعمال کریں صرف لہجے کی مصالحت کو دوبارہ چلانے کے لیے۔

سرکاری تھیم کی تبدیلیاں ان کی محفوظ کردہ ظاہری اقدار کو لاگو کرتی ہیں اور متاثرہ رن ٹائم صارفین کو اپ ڈیٹ کرتی ہیں۔ اپنی مرضی کے مطابق تھیم لگانے سے ٹاسک بار، ہائپر لینڈ ری لوڈ، وال پیپر اور کنٹرول پینل سروسز دوبارہ شروع ہو جاتی ہیں۔ چسپاں یا اسپیسڈ کو تبدیل کرنے سے اس موڈ کی اسپیسنگ، بارڈرز اور ٹاسک بار کے مارجن دوبارہ لاگو ہوتے ہیں، پھر ٹاسک بار، ٹیلی میٹری اور ہائپر لینڈ ری لوڈ سروسز کو دوبارہ شروع کرتا ہے۔ ڈنسٹ کے نوٹیفکیشن کے رنگ مستثنیٰ ہیں جبکہ ڈو ناٹ ڈسٹرب فعال ہے: ان کا دوبارہ لوڈ اس وقت تک موخر کر دیا جاتا ہے جب تک کہ DND بند نہ ہو جائے۔ اگر کوئی اور سطح پرانے رنگوں کو برقرار رکھتی ہے، تو چیک کریں کہ تھیم کی تعمیر فعال ہے اور یہ وہی تھیم ہے جسے آپ نے منتخب کیا ہے، پھر دوبارہ لوڈز کو چلائیں:

```sh
cat "${XDG_CONFIG_HOME:-$HOME/.config}/argvus/data/generated/theme/current/build.toml"
argvus config theme-runtime consumers
```

ہر تھیم والی فائل بلڈ سے آتی ہے: ایک تھیم جو انسٹال نہیں ہے (`theme.toml ` `/usr/share/argvus/themes/` یا `~/.local/share/argvus/themes/` کے تحت کوئی theme.toml نہیں ہے) یا رینڈر نہیں کیا جاتا ہے، اور پچھلا تھیم برقرار رہتا ہے۔ ` argvus theme check DIRECTORY ` ہر رینڈر کی غلطی کی ٹیمپلیٹ اور لائن دکھاتا ہے۔ ایک Waybar بار اپنے JSONC میں صرف ` reload_style_on_change ` کے ساتھ اپنے رنگوں کو دوبارہ لوڈ کرتا ہے۔ اگر کوئی سوئچ پھنسا لگتا ہے، تو چیک کریں کہ آیا یہ اب بھی چل رہا ہے۔ یہ اپنے تالے کے ساتھ ` theme-switch.active` میں خود کو ریکارڈ کرتا ہے:

```sh
cat "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/theme-switch.active"
ps -ef | grep -E 'theme-switch|theme-apply'
```

مارکر میں ایک pid جو ابھی تک زندہ ہے اس کا مطلب ہے کہ سوئچ ختم نہیں ہوا ہے۔ ایک سوئچ تھیم لاک اور پروجیکشن کے لیے زیادہ سے زیادہ 60 سیکنڈز اور ری لوڈ کمانڈز کے لیے 5 سیکنڈ انتظار کرتا ہے۔ ایک مارکر جس کا عمل ختم ہو چکا ہے وہ باسی ہے اور اگلا سوئچ اسے نظر انداز کر دیتا ہے۔ مسئلہ کی اطلاع دیتے وقت اوپر دیے گئے کمانڈز کا آؤٹ پٹ شامل کریں۔

اگر صرف پری لاگ ان گریٹر سفید ہے یا فال بیک تھیم استعمال کرتا ہے، تو پرائیویٹ سورس کا عوامی پروجیکشن سے موازنہ کریں:

```sh
uid=$(id -u)
argvus config get /appearance/theme --raw
sudo cat "/var/lib/argvus/greeter/themes/$uid"
sudo cat "/var/lib/argvus/greeter/themes/$uid.accent" 2>/dev/null || true
```

گریٹیڈ کنفیگریشن کو تبدیل کیے بغیر پروجیکشن کی مرمت کریں:

```sh
sudo argvus greeter-setup --sync-themes
```

وہ فائل پیشگی آرکیسٹریٹر کے ذریعہ پہلے سے تصدیق کے لئے شائع کی گئی ہے۔
`data/generated/` سے باہر رہتا ہے، لہذا ایک سادہ ` argvus config apply` نہیں کرتا
اسے تازہ کریں.

اگر گریٹر `Invalid color name: 'null'` کٹی کیشے میں رپورٹ کرتا ہے، تو اپ ڈیٹ کریں
`argvus terminal` پیکج اور گریٹر کو دوبارہ کھول کر کیشے کو دوبارہ تخلیق کریں۔
غیر حاضر کینونیکل لہجہ ڈیفالٹ ہے، کٹی کلر نہیں۔ موجودہ ٹرمینل
لانچر لکھنے سے پہلے JSON `null` اور غلط میراثی اقدار کو مسترد کرتا ہے
`active_tab_foreground`۔

اگر پہلے سے طے شدہ ٹرمینل کئی تھیم کی تبدیلیوں کے بعد کھلنا بند کر دیتا ہے، تو دستی طور پر ترمیم کرنے کے بجائے اخذ کردہ کٹی کیشے کا معائنہ کریں:

```sh
argvus config get /appearance/theme --raw
ls -l "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/argvus-terminal"
argvus terminal --apply
argvus terminal --print-config
```

مندرجہ بالا کمانڈ کیننیکل ترجیح کو پڑھتی ہے۔ `.active-theme` صرف ایک ہے۔
مطابقت پروجیکشن. کیشے کو `argvus terminal` اور کے ذریعے دوبارہ تخلیق کیا گیا ہے۔
تھیم ایپلی کیشن کے ساتھ ہم آہنگ۔ گمشدہ یا باسی
`/usr/lib/argvus/loading-theme/splash` ایک نامکمل پیکیج اپ ڈیٹ کی نشاندہی کرتا ہے۔
لائیو سیشن کا فیصلہ کرنے سے پہلے مربوط پیکجوں کو دوبارہ بنائیں اور انسٹال کریں۔
نتیجہ

اگر ونڈو کی سرحدیں پچھلے تھیم کا رنگ رکھتی ہیں، تو Hyprland's Lua میں ترمیم نہ کریں۔
دستی طور پر فائل کریں. تھیم اور لہجے کی تبدیلیوں کا تخمینہ `config.json ` سے لگایا جاتا ہے۔` argvus sessionctl reload` Hyprland کو دوبارہ لوڈ کرتا ہے اور فعال، غیر فعال کو دوبارہ لاگو کرتا ہے،
اور سیشن لائف سائیکل کے ذریعے سرحدی رنگوں کو گروپ کریں:

```text
config.json → projection plan → Hyprland reload → hyprctl reapply of active/inactive/group borders
```

بارڈر *ترجیحات* کو `argvus config borders` (یا اس کے ذریعے تبدیل کیا جاتا ہے
`borders-switch.sh` مندوب) کنٹرول سینٹر اور کنٹرول پینل میں؛ دوبارہ لوڈ کریں
سیشن لائف سائیکل کے ذریعے پرعزم رنگوں کو دوبارہ لاگو کرتا ہے اور نہیں کرتا
انہیں دوبارہ حاصل کریں.

منصوبہ اور مؤثر کمپوزیٹر اقدار کا معائنہ کریں:

```sh
jq . "${XDG_STATE_HOME:-$HOME/.local/state}/argvus/config-projection.json"
hyprctl -j getoption general:col.active_border
hyprctl -j getoption general:col.inactive_border
argvus sessionctl reload
```

اگر `hyprctl` موجودہ ہائپرلینڈ ساکٹ تک نہیں پہنچ سکتا تو بارڈر پروجیکشن ہے
ناکام کے طور پر رپورٹ کیا گیا ہے اور منحصر اجزاء کو کامیابی سے نہیں سمجھا جاتا ہے۔
دوبارہ لوڈ دوبارہ کوشش کرنے سے پہلے صارف کے سیشن جرنل کو چیک کریں۔

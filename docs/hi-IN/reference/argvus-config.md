ARGVUS `$XDG_CONFIG_HOME/argvus/config/` (सामान्यतः `~/.config/argvus/config/`) के अंतर्गत मॉड्यूलर JSON फ़ाइलों में प्रबंधित उपयोगकर्ता प्राथमिकताओं को रखता है। वे ARGVUS द्वारा प्रबंधित प्राथमिकताओं के लिए विहित तार्किक मॉडल बनाते हैं, और `argvus-config` एकमात्र घटक है जो `data/generated/` के नीचे फ़ाइलें लिखता है। मूल फ़ाइलें और जेनरेट की गई फ़ाइलें संगतता अनुमान या एप्लिकेशन-विशिष्ट ओवरराइड बनी रहती हैं।

## उपयोगकर्ता मार्गदर्शिका: त्वरित शुरुआत

अधिकांश उपयोगकर्ताओं के लिए, कॉन्फ़िगरेशन ARGVUS नियंत्रण केंद्र या इस कमांड-लाइन टूल के माध्यम से होता है:

```sh
# View your configuration location and validate it
argvus config path
argvus config validate

# Get a specific value
argvus config get /appearance/theme
argvus config get /appearance/theme --raw    # Without JSON formatting

# Set a value (must be valid JSON)
argvus config set /appearance/theme '"gruvbox-dark"'

# Apply changes to reload the session
argvus config apply
```

व्यवस्थापकों और उन्नत कॉन्फ़िगरेशन के लिए, नीचे पढ़ना जारी रखें।

उपयोगकर्ता रूट में केवल विहित दस्तावेज़ और प्रबंधित डेटा होता है:

```text
~/.config/argvus/
├── config.json
└── data/
```

फ़ाइल को परमाणु रूप से लिखा जाता है, उपयोगकर्ता के लिए निजी रखा जाता है, और द्वारा संरक्षित किया जाता है

```sh
argvus config path
argvus config validate
argvus config ensure
argvus config migrate
argvus config status
argvus config explain /layout/gaps_out
argvus config get /appearance/theme --effective --raw
argvus config set /appearance/accent '"#61AFEF"'
argvus config patch appearance-patch.json
argvus config audio volume +5
argvus config audio mute toggle
argvus config apply-theme universe --variant sticky --accent '#EEEEEE' --gtk-mode dark
argvus config apply-theme universe-spaced --variant spaced --accent '#EEEEEE' --gtk-mode dark
argvus config theme-manifest universe-spaced
argvus config unset /appearance/accent
argvus config apply
argvus config rebuild
argvus config project
argvus config project --force
```

, outside the

```sh
argvus sessionctl apply-config
```

 वह पेड़ जिसे प्रक्षेपण के दौरान बदला जा सकता है। पिछला संस्करण यहां संग्रहीत है

.

`apply` पोस्ट-कमिट रनटाइम रीलोड को `argvus sessionctl` को भी सौंपता है।तैयारी या पृथक परीक्षणों के लिए `ARGVUS_NO_RUNTIME=1` सेट करें।
जेनरेशन स्टेजिंग में होता है और `data/` ट्री की अदला-बदली ही की जाती है
प्रोजेक्टर सफल होते हैं. इसलिए `data/generated/` हटाकर चल रहा हूं
`argvus config apply` आंशिक प्रकाशन के बिना एक प्रतिलिपि प्रस्तुत करने योग्य पुनर्निर्माण है
हाइप्रलैंड या टास्कबार आउटपुट का अनुक्रम। कमांड रिकॉर्ड प्राप्त हुआ
अनुभाग हैश और रनटाइम निर्णय
`$XDG_STATE_HOME/argvus/config-projection.json` (सामान्यतः
`~/.local/state/argvus/config-projection.json`). न प्रकट न
उत्पन्न फ़ाइलें सत्य के स्रोत हैं। `apply` पोस्ट-कमिट पुनः लोड करता है
`argvus sessionctl` के माध्यम से; `project` अनुकूलता के लिए केवल प्रक्षेपण बना हुआ है।

प्रत्येक लगातार उत्परिवर्तन एक ही नियम का उपयोग करता है: यदि विहित दस्तावेज़ बदल गया है,
CLI प्रतिबद्धता के बाद एक केंद्रीकृत `argvus sessionctl reload` को आमंत्रित करता है। द
पुनः लोड परिणाम `data/internal/last-reload.json` में दर्ज किया गया है।

इसलिए `argvus sessionctl reload` एक *लागू* कदम है, प्रक्षेपण कदम नहीं।
जब आने वाला मेनिफेस्ट लंबित कार्य की रिपोर्ट करता है तो यह लक्षित को पुनर्स्थापित करता है
योजना द्वारा वर्णित उपभोक्ता और दोबारा `argvus config project` पर कॉल नहीं करते हैं;
पुनर्प्रक्षेपण से एक समान वृक्ष का पुनर्निर्माण होगा और योजना उत्परिवर्तन को त्याग दिया जाएगा
अभी उत्पादित. यह माइग्रेशन और प्रक्षेपण पर तभी वापस आता है जब कोई प्रतिबद्ध नहीं होता है
योजना मौजूद है, उदाहरण के लिए सत्र स्टार्टअप के दौरान।

### लक्ष्य पुनः लोड करें

`argvus config session-plan` के लक्ष्य के साथ पुनः लोड का उत्तर देता है
अनुभाग जो बदल गए, और `argvus sessionctl` केवल उन्हीं को चलाता है। छपाक
रीलोड को केवल तभी कवर करता है जब कोई लक्ष्य किसी सतह को दोबारा बनाता है: एक वेबार बार या
नियंत्रण कक्ष स्क्रीन पर वापस जाने से प्रत्येक विंडो शिफ्ट हो जाती है। बाकी सब कुछ
जगह पर पुनः लोड करता है.

| परिवर्तन | लक्ष्य | छींटे |
| --- | --- | --- |
| थीम, हाइलाइट रंग या जीटीके मोड | `hyprland`, `consumers`, `wallpaper`, `polkit` | नहीं |
| केवल वॉलपेपर | `wallpaper` (हाइपरपेपर आईपीसी; सेवा केवल swaybg के लिए पुनरारंभ होती है) | नहीं || `effects` (धुंधला, एनिमेशन, पारदर्शिता, छाया) | `hyprland`, `consumers` | नहीं || विंडोज़ का `layout` (अंतराल, बॉर्डर) | `hyprland` | नहीं |
| `layout.taskbar` (स्थिति, मार्जिन) | `hyprland`, `taskbar`, `widget_telemetry` | हाँ |
| `fonts` | `consumers` | नहीं |
| `control_panel` (स्विच, कार्ड) | `control_panel` | हाँ |
| `default_apps`, `keyboard_shortcuts`, `hyprland`, `displays` | `hyprland` | नहीं |
| `power` | `hypridle` | नहीं |

`consumers` `argvus config theme-runtime consumers` (बार स्टाइलशीट) चलाता है
आईपीसी, हाइप्रलैंड रंग, डंस्ट की थीम पुनः लोड, बीटॉप और पर नियंत्रण कक्ष
बिल्ली)। डू नॉट डिस्टर्ब सक्रिय होने पर डंस्ट ने अपनी थीम पुनः लोड करना स्थगित कर दिया है।
`wallpaper` `argvus config theme-runtime wallpaper` चलाता है, जो दर्शाता है
प्रभावी `/appearance/wallpaper`। `layout.taskbar` हैश रखा गया है
प्रोजेक्शन मेनिफ़ेस्ट में विंडो लेआउट के अलावा, एक गैप परिवर्तन होता है
बार पुनः प्रारंभ न करें. फ़ॉलबैक `full` योजना, तब उपयोग की जाती है जब कोई प्रतिबद्ध योजना नहीं होती है
मौजूद है, स्पलैश के नीचे हर सतह को पुनः आरंभ करता है।

प्रत्येक प्रभावी कॉन्फ़िगरेशन में एक परिचालन पीढ़ी होती है। इसे संग्रहित किया जाता है
`data/internal/generation.json` और प्रक्षेपण मेनिफेस्ट के अंतर्गत
`$XDG_STATE_HOME/argvus/config-projection.json`; यह डॉटफ़ाइल्स का हिस्सा नहीं है
विन्यास. अपरिवर्तित प्रभावी कॉन्फ़िगरेशन को पुनः लागू करने से यह सुरक्षित रहता है
पीढ़ी. `status` रिपोर्ट करता है कि क्या मेनिफेस्ट हैश, जेनरेशन मेटाडेटा और
सभी जेनरेट की गई फ़ाइलें सहमत हैं; `apply` पुराने या अधूरे प्रक्षेपण की मरम्मत करता है।

`explain /path` रिज़ॉल्वर को सीधे पढ़ता है और प्रभावी मान प्रिंट करता है,
स्रोत, विषय और संस्करण। यह जेनरेट की गई फ़ाइलों को पार्स नहीं करता है या दूसरा नहीं बनाता है
पूर्वता नियम.

थीम और प्रभाव प्रक्षेपण `argvus-config` में ही लागू किए गए हैं।
थीम लेनदेन (`argvus theme-switch`, जो `theme-apply` चलाता है), `argvus config accent` और `argvus effects-toggle` प्रोजेक्ट नहीं करते हैं:
वे इस सीएलआई के माध्यम से सत्यापन करते हैं, लॉक करते हैं, प्रतिबद्ध होते हैं और फिर
उन बाहरी उपभोक्ताओं से मेल-मिलाप करें जो `config.json` नहीं पढ़ सकते हैं। `argvus effects-toggle`
यह एक पतला प्रतिनिधि है जिसका अपना कोई आउटपुट नहीं है। दिखावे कभी मददगार नहीं होते
प्रोजेक्टर द्वारा बुलाया जाता है, और उन्हें कभी भी `data/generated/` के नीचे नहीं लिखना चाहिए।

और GTK मोड के लिए `argvus config mode toggle|set dark|light`। ऐतिहासिक
एक्सेंट और मोड स्क्रिप्ट अनुकूलता आवरण हैं; `.accent-color`,
`.accent-custom` और `.gtk-mode` केवल माइग्रेशन/प्रोजेक्शन फ़ाइलें हैं।

तार्किक ARGVUS पथ भी `argvus config paths` द्वारा हल किए जाते हैं। विरासत
`paths.sh` फ़ाइल केवल संगतता कार्यों को उजागर करती है; मूल ओवरराइड, उपयोगकर्ता
डेटा, उत्पन्न डेटा और सिस्टम फ़ॉलबैक का समाधान रस्ट पथ मॉडल द्वारा किया जाता है।

`audio` डिफ़ॉल्ट आउटपुट सिंक को बदलता है और परिणाम को एक चरण में `/audio` में रिकॉर्ड करता है: `argvus config audio volume <N|+N|-N> [--limit PERCENT]` और `argvus config audio mute <on|off|toggle>`। यह कॉन्फ़िगरेशन को पुनः लोड किए बिना स्टोर लिखता है, क्योंकि पाइपवायर का मूल्य पहले से ही है। वेबार वॉल्यूम मॉड्यूल, हाइप्रलैंड मीडिया कुंजी और कंट्रोल पैनल इसका उपयोग करते हैं, इसलिए `argvus config project`, जो सिंक पर `/audio` प्रोजेक्ट करता है, कभी भी पुराने वॉल्यूम को पुनर्स्थापित नहीं करता है। 100% से ऊपर की मात्रा (हाइपरलैंड कुंजी 150% तक की अनुमति देती है) को 100 के रूप में संग्रहीत किया जाता है।

`patch` एक JSON ऑब्जेक्ट लागू करता है जिसकी कुंजियाँ एक लॉक में JSON पॉइंटर्स होती हैं
पढ़ना-संशोधित-लिखना ऑपरेशन। `apply-theme` समतुल्य परमाणु कार्य करता है
थीम लेनदेन और प्रबंधित उपस्थिति अनुभागों को प्रतिस्थापित करता है
थीम की वैकल्पिक उपस्थिति प्रोफ़ाइल या पैकेज्ड डिफ़ॉल्ट।
आदेशों को परिवर्तित करने से एक `NextUserConfig` बनता है, एक `EffectiveConfig` का समाधान होता है, चरण
सभी प्रोजेक्टर, और उसके बाद ही विहित JSON प्रकाशित करें। एक परिचालन
`.config-transaction.json` मार्कर `argvus config recover` को दोबारा प्रोजेक्ट करने की अनुमति देता है
डेटा और JSON प्रकाशन के बीच क्रैश के बाद पिछला कॉन्फ़िगरेशन।
थीम डिफ़ॉल्ट प्रत्येक थीम के मेनिफेस्ट द्वारा घोषित किए जाते हैं
(`themes/<theme>/theme.toml`): डिफ़ॉल्ट उच्चारण (`palette.accent`), GTK रंग योजना
और वॉलपेपर. सीएसएस, लुआ, रासी और क्यूटी फाइलों को थीम बिल्ड में प्रस्तुत किया गया है।

लाइट/डार्क सहित थीम बदलने से हाइलाइट रंग थीम के डिफ़ॉल्ट पर रीसेट हो जाता है,
तब भी जब उपयोगकर्ता ने कोई कस्टम रंग चुना हो: कस्टम रंग केवल अगली थीम तक ही रखा जाता है
परिवर्तन. थीम बदलने के बाद इसे दोबारा सेट करने के लिए `argvus config accent` का उपयोग करें। ए लगाना
`argvus config theme-apply` के साथ थीम `/appearance/accent` और `/appearance/gtk_mode` लिखता है
मैनिफ़ेस्ट से, और `argvus config accent` चुने हुए रंग को `accent_custom` के साथ लिखता है
सेट, एक आदेश में.

`apply-theme` स्पष्ट रूप से `--variant sticky|spaced` के रूप में संस्करण लेता है और
अनुरोधित नाम को मेनिफेस्ट के माध्यम से हल करता है, इसलिए अनुरोध कभी नहीं हो सकता
दूसरे प्रकार की संपत्तियों का समाधान करें। `theme-manifest THEME` वही है
रिज़ॉल्यूशन एक्सपोज़्ड-ओनली: यह मेनिफेस्ट प्रविष्टि को एक साथ प्रिंट करता है
`asset_id` और `layout_variant` ने इसे हल कर दिया, जो कि एक कॉल करने वाले को चाहिए
पैकेज्ड परिसंपत्तियों का पता। स्टिकी एक अप्रत्ययित आईडी है और केवल स्पेस्ड में एक होता है`-spaced` प्रत्यय, इसलिए `dracula-sticky` और `argvus-dark-dracula-sticky` हैं
स्वीकार किया गया और `dracula` को सामान्य किया गया।

`--raw` के साथ, स्ट्रिंग मान JSON उद्धरणों के बिना मुद्रित होते हैं, जबकि ऑब्जेक्ट और एरे JSON मान बने रहते हैं। थीम और लेआउट डॉट-फ़ाइलें अब प्रक्षेपण सहायक द्वारा नहीं लिखी जाती हैं; `config.json` उन प्राथमिकताओं के लिए एकमात्र स्थायी स्रोत बना हुआ है। यदि प्रक्षेपण विफल हो जाता है, तो डेस्कटॉप सतहों को पुनरारंभ करने से पहले सत्र पुनः लोड बंद हो जाता है, इसलिए पुराने आंशिक विषय को वर्तमान के रूप में प्रस्तुत नहीं किया जाता है।

## निर्यात और आयात

प्रोफ़ाइल विनिमय के लिए समान तार्किक मॉडल का उपयोग किया जाता है:

```sh
argvus config export --scope appearance --output appearance.json
argvus config import --scope appearance appearance.json
```

संपूर्ण प्रबंधित डेस्कटॉप मॉडल के लिए `--scope desktop` का उपयोग करें। गुम फ़ील्ड ARGVUS डिफ़ॉल्ट का उपयोग करते हैं; उत्पन्न आउटपुट को सीधे संपादित नहीं किया जाना चाहिए।

नियंत्रण केंद्र थीम निर्यात और आयात एक थीम और उसके दृश्य प्रोफ़ाइल का आदान-प्रदान करता है: संग्रह में एक स्कीमा 2 थीम निर्देशिका (`<id>/theme.toml`, वैकल्पिक `appearance.json` और `effects.conf`, `overrides/`, वॉलपेपर) होती है जो नीचे स्थापित होती है `$XDG_DATA_HOME/argvus/themes/`। प्रोफ़ाइल में उपस्थिति, लेआउट ज्यामिति, दृश्य प्रभाव, फ़ॉन्ट और पैनल प्रस्तुति शामिल है। ऑडियो, कीबोर्ड, नेटवर्क और अन्य गैर-दृश्य प्राथमिकताएं थीम से बाहर रहती हैं। संपूर्ण उपस्थिति कॉन्फ़िगरेशन को स्थानांतरित करने के लिए उपरोक्त `appearance` स्कोप का उपयोग करें, और पूर्ण कॉन्फ़िगरेशन बैकअप के लिए `desktop` स्कोप का उपयोग करें।

`appearance`, `layout`, `effects`, `fonts`, `control_panel`, `default_apps` के अंतर्गत वर्तमान स्कीमा समूह प्राथमिकताएँ `keyboard_shortcuts`, `hyprland`, `displays`, `power`, `session`, `calendar`, और `removable_devices`। `default_apps` पसंदीदा अनुप्रयोगों के लिए एकमात्र स्थायी स्रोत है, और `keyboard_shortcuts` स्थिर अंग्रेजी, स्ट्रिंग मानों के साथ स्थानीय-स्वतंत्र कुंजी या अक्षम बाइंडिंग के लिए `null` संग्रहीत करता है।

जब नियंत्रण केंद्र एक उपस्थिति पृष्ठ खोलता है तो विहित उपस्थिति मान पढ़ता है और `argvus-config` के माध्यम से परिवर्तन लिखता है। मौजूदा मूल स्थिति फ़ाइलें उपस्थिति स्क्रिप्ट और पुराने इंस्टॉलेशन के लिए अनुमान बनी हुई हैं।

नियंत्रण कक्ष कार्ड ऑर्डर और दृश्यता के लिए `control_panel.cards` और पैनल मास्टर स्विच के लिए `control_panel.enabled` का उपयोग करता है। इसकी `control-panel/cards.json` और `state/control-panel` फ़ाइलें संगतता अनुमान के रूप में रखी गई हैं। इसलिए नियंत्रण कक्ष में किए गए परिवर्तन `desktop` निर्यात दायरे का हिस्सा हैं।

फ़ॉन्ट प्राथमिकताएं टास्कबार, टेलीमेट्री, कंट्रोल पैनल, सिस्टम, एप्लिकेशन, टर्मिनल और ब्राउज़र लक्ष्यों के परिवार, शैली और आकार के लिए `fonts.targets` का उपयोग करती हैं। `fonts.rendering` एंटीएलियासिंग, हिंटिंग, सबपिक्सल ऑर्डर और डीपीआई प्राथमिकताओं को संग्रहीत करता है। `fonts.conf`, फॉन्टकॉन्फ़िग नियम, डेस्कटॉप सेटिंग्स और वेबार स्टाइलशीट के अंदर प्रबंधित फ़ॉन्ट ब्लॉक अनुमान हैं: नियंत्रण केंद्र argvus-config के माध्यम से `/fonts/targets/*` को बनाए रखता है, और प्रोजेक्टर केवल इसके सीमांकित ब्लॉक को फिर से लिखता है।

हाइपरलैंड प्राथमिकताएं शॉर्टकट के लिए  `argvus-config` `keyboard_shortcuts`, माउस और टचपैड सेटिंग्स के लिए `hyprland.input` और XKB लेआउट, वेरिएंट और विकल्पों के लिए `hyprland.keyboard` का उपयोग करती हैं। एक मेनिफेस्ट बाइंडिंग आईडी एक स्थिर `config_key` पर मैप करता है (उदाहरण के लिए `window.close` → `close_window` और `window.drag_mouse` → `drag_window__floating_window_only`)। प्रदर्शन प्राथमिकताएँ `displays.monitors`, `displays.workspaces`, और `displays.primary_monitor` का उपयोग करती हैं। `data/generated/` के अंतर्गत मूल TOML फ़ाइलें और जेनरेट की गई Lua फ़ाइलें Hyprland द्वारा उपभोग किए गए अनुमान बनी हुई हैं।वर्चुअल मशीनों और कम-शक्ति सत्रों पर भी प्रत्येक `effects` स्विच डिफॉल्ट रूप से सक्षम (एनिमेशन, ब्लर, विजेट टेलीमेट्री और प्रत्येक पारदर्शिता सतह) पर स्विच करता है; विंडो शैडो (`shadow_enabled`) और डगमगाने वाला (`wobble_enabled`) डिफ़ॉल्ट रूप से बंद है। प्रभाव प्राथमिकताएं एनिमेशन मास्टर स्विच के लिए `effects` का उपयोग करती हैं (`animations`, अनुमानित hypr/state.lua से `hyprland.lua` पर लागू होता है, प्रभाव स्विच से स्वतंत्र, जो  `hypr/state.lua` `blur_global_enabled` प्लस है  `transparency_<surface>_enabled` `taskbar`, `control-panel`, `widget-telemetry`, `terminal` और `launchers` में से transparency_<surface>_enabled, और उनमें से कोई भी होने पर सक्षम के रूप में पढ़ता है; `argvus effects-toggle animations|effects` उन्हें स्विच करें), ग्लोबल ब्लर स्विच (`blur_global_enabled`), हाइपरलैंड ब्लर पैरामीटर (`blur_size`, `blur_passes`, `blur_brightness`, `blur_noise`, `blur_contrast`, `blur_vibrancy`, `blur_vibrancy_darkness`), विंडो छाया (`shadow_enabled`, `shadow_sharp`, `shadow_color`, `shadow_range`, `shadow_render_power`, `shadow_offset_x`, `shadow_offset_y`, `shadow_scale`, एनिमेशन मान (`animation_<leaf>_speed`, प्रत्येक एनीमेशन के लिए `_curve`, `_style`, `_popin` और `_enabled`, प्लस `animation_bezier_x1` से `animation_bezier_y2` और कस्टम वक्रों के लिए `animation_spring_mass`, `animation_spring_stiffness` और `animation_spring_dampening`) और प्रति-सतह पारदर्शिता मान। प्रभाव थीम-स्वामित्व वाले होते हैं, वैरिएंट-स्वामित्व वाले नहीं: स्टिकी और स्पेस्ड समान `<theme>.conf` प्रभाव प्रक्षेपण का उपयोग करते हैं जबकि उनके लेआउट अनुमान भिन्न होते हैं। सतहों में वर्तमान में `taskbar`, `control-panel`, और `widget-telemetry` शामिल हैं; पारदर्शिता मान `0` से `100` तक प्रतिशत हैं (नियंत्रण केंद्र और लॉन्चर सतह `15` पर डिफ़ॉल्ट हैं, अन्य `50` पर हैं), ब्लर पैरामीटर `schema.json` में घोषित सीमाओं के भीतर संख्याएं हैं, और सक्षम राज्य हैं बूलियन्स. एनिमेशन मान `argvus-config` द्वारा भी मान्य हैं: गति `1` से `10` (दशमलव अनुमत) तक की संख्याएँ हैं, पॉप-इन प्रतिशत `1` से `100` तक पूर्ण संख्याएँ हैं, वक्र अवश्य होने चाहिए एनिमेशन पृष्ठ से नाम होना चाहिए, शैलियों को एनिमेशन पृष्ठ से नाम होना चाहिए और एनीमेशन के स्वयं के पत्ते द्वारा स्वीकार किया जाना चाहिए (उदाहरण के लिए `popin` को `animation_workspace_in_style` के लिए अस्वीकार कर दिया गया है, `gnomed` केवल विंडो खोलने और बंद करने के लिए स्वीकार किया जाता है, और स्लाइड वेरिएंट को विंडो और परत के पत्तों पर अस्वीकार कर दिया जाता है), बेज़ियर वाई अंक बीच में रहते हैं `-1` और `2`, रेंज हाइप्रलैंड 0.56.2 पार्स, और अन्य वक्र पैरामीटर उनकी प्रलेखित सीमाओं के भीतर रहते हैं। `layers` और `switching` पत्तियां अब मौजूद नहीं हैं, इसलिए उनके हटाने से पहले सहेजे गए कॉन्फ़िगरेशन `animation_layers_enabled`, `animation_layers_speed`, `animation_layers_curve` और `animation_switching_*` कुंजी खो देते हैं जब वे लोड होते हैं. वर्तमान सेट के बाहर की शैलियों को हटा दिया गया है और `-1` से `2` के बाहर बेज़ियर Y बिंदुओं को क्लैंप किया गया है, इसलिए जो कुछ भी हटाया गया था उस पर पैक किए गए डिफ़ॉल्ट फिर से लागू होते हैं।

पावर प्राथमिकताएँ `power.screen_off_minutes`, `power.lock_minutes`, `power.keep_awake` और ढक्कन/पावर-बटन नीतियों का उपयोग करती हैं। अनुमानित प्रपत्र `data/generated/hypr/hypridle.conf` और मार्कर `data/power/keep-awake` हैं; `.keep-awake` केवल माइग्रेशन इनपुट है। `session.language` को हटा दिया गया है: मौजूदा मानों को नजरअंदाज कर दिया गया है, नए लेखन को अस्वीकार कर दिया गया है, और कोई भाषा संगतता फ़ाइल प्रक्षेपित नहीं की गई है। इसके बजाय उपयोगकर्ता locale.conf में `LANG` सेट करें। कैलेंडर प्राथमिकताएँ  `locale.conf` `calendar` का उपयोग करती हैं और टास्कबार-कैलेंडर उपयोगकर्ता TOML पर प्रक्षेपित की जाती हैं। हटाने योग्य-डिवाइस प्राथमिकताएँ `removable_devices` का उपयोग करती हैं; रिमूवेबल-डिवाइस एप्लिकेशन इस सेक्शन को पैकेज्ड डिफॉल्ट्स पर उपयोगकर्ता ओवरराइड के रूप में मानता है।`migrate` मौजूदा कैनोनिकल मान को संरक्षित करते हुए पुरानी रूट फ़ाइलों और अनुभागों को एक बार आयात करता है। लीगेसी `defaults.json`, `/defaults`, `/hyprland/keybindings`, `keybindings.toml`, डॉट-फ़ाइलें, `generated/` और घटक निर्देशिकाएँ `data/` से नीचे ले जाया गया है; बार-बार पुनः लोड करने से पुराना रूट लेआउट दोबारा नहीं बनता है। वर्तमान थीम को फिर से चुनना निरर्थक है: यदि विहित स्थिति और अनुमान पहले से ही सहमत हैं, तो प्रक्षेपण योजना कोई परिवर्तित अनुभाग नहीं होने की रिपोर्ट करती है और सत्र स्पलैश छोड़ देता है और सेवा पुनरारंभ हो जाती है।

### उपयोगकर्ता द्वारा निर्मित कीबोर्ड शॉर्टकट

`/keyboard_shortcuts` आधिकारिक प्रकट क्रियाओं के लिए अपने मौजूदा स्ट्रिंग-या-शून्य मान को बरकरार रखता है। कस्टम वैश्विक कीबोर्ड शॉर्टकट एक अलग `/hyprland/custom_shortcuts` ऑब्जेक्ट का उपयोग करते हैं, जो `config/hyprland.json` में संग्रहीत है। इसकी स्थिर `custom_` आईडी विवरण और स्थानों से स्वतंत्र हैं। प्रत्येक रिकॉर्ड में `description`, `keys`, `enabled` और एक टाइप किया हुआ `action` है:

```json
{
  "custom_editor": {
    "description": "Open my editor",
    "keys": "SUPER + CTRL + E",
    "enabled": true,
    "action": { "type": "command", "command": "editor --new-window" }
  },
  "custom_float": {
    "description": "Toggle floating",
    "keys": "SUPER + CTRL + F",
    "enabled": false,
    "action": {
      "type": "dispatcher",
      "dispatcher": "window.float",
      "arguments": { "action": "toggle" }
    }
  }
}
```

उदाहरण `/hyprland/custom_shortcuts` का मान है, पूर्ण कॉन्फ़िगरेशन दस्तावेज़ नहीं। डिस्पैचर नाम समर्थित लुआ डिस्पैचर कारखानों से आते हैं; तर्क एक वैकल्पिक JSON ऑब्जेक्ट या `null` हैं, जिनका कभी मूल्यांकन नहीं किया गया कोड। कस्टम शॉर्टकट में कोई सबमैप, माउस बाइंडिंग या उन्नत फ़्लैग नहीं होते हैं। प्रक्षेपण `data/generated/hypr/custom-shortcuts.lua` को एक बची हुई डेटा तालिका के रूप में लिखता है, जिसमें अंतिम रिकॉर्ड हटाए जाने पर एक खाली तालिका भी शामिल है। पूर्ण प्रक्षेपण और `project --only keyboard_shortcuts` दोनों इसे उत्पन्न करते हैं। हाइप्रलैंड `hl.bind` के साथ सक्षम प्रविष्टियों को पंजीकृत करता है; वैकल्पिक फ़ाइल और व्यक्तिगत पंजीकरण विफलताएँ समाहित और लॉग की जाती हैं।

नियंत्रण केंद्र एक `argvus config patch` लेनदेन का उपयोग करके रिकॉर्ड बनाता/संपादित करता है और पुष्टि किए गए विरोधों को अक्षम करता है। यह मौजूदा कॉन्फ़िगरेशन सेवा के माध्यम से आवेदन करने से पहले सहेजता है। एक असफल आवेदन सफल सेव को पूर्ववत नहीं करता है। आधिकारिक डिफ़ॉल्ट को पुनर्स्थापित करना कस्टम रिकॉर्ड को संरक्षित करता है और यदि यह सक्रिय कस्टम शॉर्टकट से टकराता है तो इसे अस्वीकार कर दिया जाता है। उपयोगकर्ता विवरण सभी स्थानों में शाब्दिक पाठ और प्रभावी जेनरेटेड चीटशीट बने रहते हैं।

## ग्लोबल विंडो मोड

**कंट्रोल सेंटर → डेस्कटॉप और इनपुट → हाइप्रलैंड → विंडोज़ → मोड** खोलें और **टाइल विंडोज़ (डिफ़ॉल्ट)** या **फ़्लोटिंग विंडोज़** चुनें। वही चयनकर्ता टास्कबार उपयोगिता समूह में विंडो-मोड आइकन से उपलब्ध है।

प्राथमिकता प्रत्येक मॉनिटर और कार्यक्षेत्र पर लागू होती है और लॉगआउट के बाद याद रखी जाती है। फ़्लोटिंग मौजूदा एप्लिकेशन विंडो और नई खुली हुई विंडो को परिवर्तित करता है। टाइल केवल उन्हीं विंडो को पुनर्स्थापित करती है जिन्हें इस नीति द्वारा परिवर्तित किया गया है; संवाद और अन्य विंडो जो पहले से ही तैर रहे थे, तैरते ही रहते हैं। फ़्लोटिंग सक्रिय होने पर स्पष्ट रूप से पिन की गई एक विंडो भी अपने पिन को संरक्षित करने के लिए फ्लोटिंग रहती है। टाइल वाले लेआउट की पुनर्गणना की गई है; इसके ठीक पिछले विभाजित पेड़ को बहाल नहीं किया गया है।`SUPER + SHIFT + Space` टाइल में अपना सामान्य प्रति-विंडो व्यवहार रखता है। फ़्लोटिंग में यह विंडो को वापस टाइलिंग पर स्विच नहीं करता है। पैनल, टास्कबार और नोटिफिकेशन लेयर-शेल सतह हैं और प्रभावित नहीं होते हैं। फ़ुलस्क्रीन और अधिकतमीकरण हाइप्रलैंड के सामान्य व्यवहार का उपयोग जारी रखता है।

$XDG_CONFIG_HOME/argvus/config/hyprland.json में विहित प्राथमिकता `/hyprland/window_mode` है। इसका उत्पन्न प्रक्षेपण  `$XDG_CONFIG_HOME/argvus/config/hyprland.json` `data/generated/hypr/window-mode.lua` है; इसे संपादित न करें. प्रति-विंडो पुनर्स्थापना रजिस्ट्री `$XDG_RUNTIME_DIR/argvus` के अंतर्गत रहती है, कंपोजिटर इंस्टेंस के दायरे में रहती है, और कॉन्फ़िगरेशन पुनः लोड होने से बची रहती है। नए सत्र में इसका पुन: उपयोग नहीं किया जाता है।

यदि एप्लिकेशन लंबित है या विफल रहता है, तो इंटरफ़ेस इसे सहेजी गई प्राथमिकता से अलग करता है। पुनः प्रयास करने के लिए फिर से विकल्प चुनें। कंपोज़िटर के बिना, प्राथमिकता अगले लॉगिन के लिए सहेजी जाती है।

```sh
argvus config window-mode get
argvus config window-mode status --json
argvus config window-mode set floating
argvus config window-mode set tile
argvus config window-mode toggle
```

## विंडो बटन और एप्लिकेशन बार

फ़्लोटिंग मोड सामान्य एप्लिकेशन विंडो में **छोटा करें**, **अधिकतम करें/पुनर्स्थापित करें**, और **बंद करें** के साथ एक ARGVUS टाइटल बार जोड़ता है। शीर्षक पट्टी पर डबल-क्लिक करने से अधिकतमकरण टॉगल हो जाता है। अतिरिक्त सजावट टाइल और फ़ुलस्क्रीन में छिपी हुई है। जो एप्लिकेशन अपने स्वयं के नियंत्रण बनाते हैं वे दोनों बार प्रदर्शित कर सकते हैं; एकसमान ARGVUS नियंत्रण जानबूझकर किए गए हैं।

प्रत्येक मॉनीटर पर मुख्य टास्कबार के सामने किनारे पर एक दूसरा वेबार दिखाई देता है। यह केवल उस मॉनिटर के वर्तमान कार्यक्षेत्र से संबंधित विंडोज़ को सूचीबद्ध करता है, जिसमें उस कार्यक्षेत्र से न्यूनतम की गई विंडो भी शामिल है। एक खुले विशेष कार्यक्षेत्र को प्राथमिकता दी जाती है। पिन की गई खिड़कियाँ दृश्यमान रहती हैं; छिपे हुए समूह टैब अतिरिक्त प्रविष्टियाँ नहीं बनाते हैं, और एक न्यूनतम समूह में एक पुनर्प्राप्ति प्रविष्टि होती है। किसी एप्लिकेशन के अंदर टैब की अलग से गणना नहीं की जाती है। न्यूनतम प्रविष्टियाँ अपने मूल मॉनिटर/कार्यस्थान संबंध को बरकरार रखती हैं। इसे सक्रिय करने के लिए एक निष्क्रिय विंडो पर क्लिक करें, इसे छोटा करने के लिए एक सक्रिय विंडो पर क्लिक करें, या इसे पुनर्स्थापित करने के लिए एक छोटी विंडो पर क्लिक करें; इसका संदर्भ मेनू पुनर्स्थापना, न्यूनतम, अधिकतम/पुनर्स्थापना और बंद करने की पेशकश करता है। अज्ञात एप्लिकेशन आइकन वापस विंडो प्रतीक पर आ जाते हैं। किसी प्रविष्टि को सक्रिय या पुनर्स्थापित करने से सूचक स्थिति सुरक्षित रहती है। द्वितीयक बार प्रभावी प्राथमिक सीएसएस (रंग, फ़ॉन्ट, बॉर्डर और गोलाई) का उपयोग करता है, इसकी ऊंचाई और विपरीत किनारे पर प्रतिबिंबित मार्जिन होता है।

`SUPER + Alt + Up` मुख्य बार को शीर्ष पर और विंडो बार को नीचे रखता है। `SUPER + Alt + Down` इसका उलटा करता है। किसी दिशा को दोहराने से स्थितियाँ अपरिवर्तित रह जाती हैं। टाइल में केवल मुख्य पट्टी होती है। टाइल पर लौटने से विंडो बार को हटाने से पहले सभी न्यूनतम विंडो को पुनर्स्थापित किया जाता है, और फिर मूल टाइल/फ़्लोटिंग नीति को संरक्षित किया जाता है।

न्यूनतमकरण आरक्षित `special:argvus-minimized` कार्यस्थान का उपयोग करता है। उस कार्यस्थान का मैन्युअल रूप से उपयोग न करें. `argvus windows service` प्रक्रिया `$XDG_RUNTIME_DIR/argvus` के तहत एक कंपोजिटर-इंस्टेंस-विशिष्ट रनटाइम रजिस्ट्री में पहचान, मूल कार्यक्षेत्र/मॉनिटर, ज्यामिति, पूर्णस्क्रीन/अधिकतमकरण और पिन स्थिति को रिकॉर्ड करती है। रिकॉर्ड सेवा पुनरारंभ या कॉन्फ़िगरेशन पुनः लोड से बचे रहते हैं, लेकिन कंपोज़िटर सत्रों को पार नहीं करते हैं। विंडो बंद करने से उसका रिकॉर्ड हट जाता है। यदि कोई मॉनिटर गायब हो जाता है, तो पुनर्स्थापना उपलब्ध आउटपुट का उपयोग करती है। एक गुम या विफल पुनर्प्राप्ति बार नए न्यूनतमकरण को रोकता है; असफल पुनर्स्थापना रिकॉर्ड और पुनर्प्राप्ति बार को बरकरार रखती है।

सत्र `argvus-windows.service` और `argvus-window-bar.service` का मालिक है। उत्तरार्द्ध अपने वेबार बच्चे को टाइल में निष्क्रिय रखता है। हाइपरबार्स प्लगइन को `argvus-hyprland` द्वारा बंडल किया गया है, जो x86_64 पर हाइपरलैंड 0.57.0 ABI के लिए बनाया गया है; यह उपयोगकर्ता की होम निर्देशिका में संकलित नहीं है। कंपोज़िटर एबीआई अपडेट के साथ प्लगइन का पुनर्निर्माण करें।

कमांड: `argvus windows list --json`, `watch --json`, `position top|bottom`, `restore-all`, और `minimize|restore|activate|maximize|close ADDRESS`। विंडो पते सूची से आते हैं. `position top --persist` मुख्य बार को पुनरारंभ किए बिना प्राथमिकता को संग्रहीत/प्रोजेक्ट करता है। कॉन्फ़िगरेशन और रनटाइम त्रुटि विवरण जर्नल में लिखे गए हैं; दृश्यमान क्रिया विफलताएँ एक अनुवादित अधिसूचना भी दिखाती हैं।**स्पेस्ड + फ्लोटिंग** में, खिड़कियां बाहरी अंतराल और दोनों बार द्वारा आरक्षित क्षेत्रों का सम्मान करती हैं। सीमाओं में बॉर्डर और शीर्षक शामिल हैं, जो एक ही विंडो बॉर्डर के अंदर स्थित हैं। ARGVUS नियंत्रणों के माध्यम से अधिकतमीकरण इस क्षेत्र को मार्जिन से भर देता है; पुनर्स्थापना पिछली ज्यामिति को पुनः प्राप्त करती है, जिसमें सेवा पुनरारंभ के बाद भी शामिल है। फ़ुलस्क्रीन अभी भी संपूर्ण आउटपुट का उपयोग करता है। फ्लोटिंग खिड़कियाँ ओवरलैप हो सकती हैं; भीतरी अंतरालों पर टाइल लगाने से वे अलग नहीं होते।

सलाखों द्वारा आरक्षित आंतरिक मार्जिन को खिड़की के बाहरी अंतराल में दो बार नहीं गिना जाता है। सममित रिक्ति के साथ, दृश्यमान विंडो-टू-बार दूरी ऊपर और नीचे बराबर होती है, जिसमें बार की अदला-बदली भी शामिल है।

`SUPER + Alt + Space` टास्कबार और कंट्रोल सेंटर के समान प्राथमिकता का उपयोग करके वैश्विक टाइल/फ्लोटिंग मोड को टॉगल करता है। समतुल्य कमांड `argvus config window-mode toggle` है। समवर्ती आह्वान क्रमबद्ध हैं; एप्लिकेशन लंबित होने पर भी टॉगलिंग सहेजी गई प्राथमिकता का उपयोग करता है। कीबोर्ड शॉर्टकट में शॉर्टकट को बदला या अक्षम किया जा सकता है; `SUPER + Shift + Space` अपनी व्यक्तिगत-विंडो क्रिया रखता है।

控制中心是 ARGVUS 的以键盘为优先的设置应用程序。当你想配置桌面而不是执行一次性操作时，请使用它。

## 控制中心与控制面板

| 使用… | 用于… |
| --- | --- |
| **控制中心** | 主题、壁纸、效果、布局、任务栏行为、字体、默认应用程序、键盘和输入设置、语言、区域及系统配置。 |
| **控制面板** | 当前状态和常用操作，如音量、亮度、网络、通知、电源和会话控制。 |

控制面板可以提供对在控制中心永久配置的设置的快速控制。例如，当你想快速进行外观或显示操作时使用控制面板，而当你想更改其背后的桌面配置时使用控制中心。参见控制面板和[配置位置](/docs/user-guide/where-to-configure/)。

## 主要区域

当前的控制中心主页提供以下几个区域：

主页是按六张卡片分组的目的地目录。每个目的地打开其页面，搜索功能可以在任何卡片下找到它。

- **外观** — 自定义桌面：桌面样式（主题、外观模式、强调色、壁纸、图标和字体）、应用程序样式（终端和启动器透明度）、任务栏、控制面板和小部件遥测。
- **桌面与输入** — 配置工作区：Hyprland（Windows：规则、空间和模式、动画、模糊、边框、阴影及已安装版本）、显示器、键盘与快捷键以及鼠标与触控板。
- **偏好设置** — 个人和区域设置：语言与地区（语言、时区、格式和键盘布局中心）、日期与时间、默认应用程序、电源与会话。
- **硬件与连接** — 设备与连接：硬件概览、网络与 Wi-Fi、蓝牙、音频和存储。
- **系统管理** — 管理操作系统：软件包、服务、启动、主机名、用户与组、防火墙及通知（请勿打扰模式）。
- **设置** — 控制中心本身，在卡片之后列出：语言（用户语言）和风格（装饰图标和透明度）。按下 `s` 打开它。
- **工具与诊断** — 开发和维护工具：ARGVUS 欢迎页、项目、代码片段（为 `argvus snippets` 保存的文本，通过 `SUPER + ALT + N` 输入）、SSH 密钥（`~/.ssh` 中的密钥对，由 `argvus keys` 管理）、GPG 密钥（密钥环由 `argvus gpg` 管理；gpg-agent 使用 pinentry-gtk）、开发服务、系统医生和关于 ARGVUS。

当启用“请勿打扰”时，通知弹窗会被关闭，新通知会被保留以便稍后查看。控制面板会隐藏其通知历史，直到“请勿打扰”被禁用。

## ARGVUS 欢迎页

在 **工具与诊断** 下选择 **Open ARGVUS Welcome**，搜索 `welcome`，或运行 `argvus welcome`。Welcome 集成在控制中心中，并使用其单一窗口。按 Enter 打开所选设置页面；完成后，按 Esc 返回指南。F6 Next 会勾选当前步骤并在同一窗口打开下一步。Esc 仅返回，而在清单上按 Enter 始终打开所选页面。O 再次查看步骤，S 跳过而不勾选，F 即使有可选步骤未完成也完成指南。取消或返回不会完成步骤。现有进度将被保留。

该指南涵盖语言和地区、显示器、硬件和驱动程序、网络、音频、蓝牙、外观、电源、默认应用程序以及会话启动。它从不安装驱动程序或软件包，也不会自行应用系统更改。进度存储在 `$XDG_STATE_HOME/argvus/welcome/progress.json`（或 `~/.local/state/argvus/welcome/progress.json`）。

桌面准备好后，会话会运行 `argvus welcome --if-needed` 来处理 TTY、ARGVUS 欢迎程序和其他登录管理器。除非每个用户的进度记录 `opened` 表示完成或已关闭，否则它会打开欢迎界面。首次成功渲染会将 `opened` 保存到 `${XDG_STATE_HOME:-$HOME/.local/state}/argvus/welcome/progress.json`，从而防止在以后登录时重新打开。它不依赖于 `/etc/skel`。现有账户如果没有该记录，也会收到一次自动打开的机会。渲染前的失败允许在下次登录时再次尝试。手动 `argvus welcome` 仍然可用。

确切的提供程序页面可能取决于已安装的软件包和权限。不要认为缺少可选域就是控制中心损坏。

当网格中的条目多于屏幕能显示的数量时，右侧会出现滚动条，以显示下面还有内容。

## 查找设置

主屏幕按标题、类别、标识符和关键字注册设置。搜索不区分重音，并接受实际术语，如 `theme`、`wallpaper`、`shortcut`、`mouse`、`monitor`、`network`、`user` 和 `DPI`。精确标题匹配排名第一，其次是标题前缀、标题或类别中包含所输入文本的任何单词，最后是关键字匹配 —— 因此输入单词的任何部分（不仅是开头）仍然可以找到目标。

可见的菜单具有能力感知功能。当其提供者未安装、硬件不可用或当前会话无法提供所需功能时，某条路由可能会缺失。因此，搜索也是发现此安装可以配置的内容的一个有用方式。

当前主要设置树包括：

| 区域 | 当前目的地 |
| --- | --- |
| 外观 | 桌面风格：主题、外观模式、强调色、壁纸、图标和字体；应用风格：终端和启动器透明度；任务栏；控制面板；小部件遥测 |
| 桌面与输入 | Hyprland（窗口：规则、空间与模式、动画、模糊、边框和阴影）、显示器、键盘与快捷键、鼠标与触控板 |
| 首选项 | 语言与区域（语言、时区、格式、系统区域设置和键盘布局）、日期与时间、默认应用、电源、会话 |
| 硬件与连接 | 硬件概述（摘要、CPU、GPU、内存、设备）、网络与Wi-Fi、蓝牙、音频、存储 |
| 系统管理 | 软件包、服务、启动、主机名、用户与组、防火墙、通知 |
| 设置 | 语言（用户语言）、样式（图标和透明度） |
| 工具与诊断 | 项目、代码片段、SSH 密钥、GPG 密钥、开发服务、系统医生、关于 ARGVUS |

其中一些是完整页面，一些是通过搜索或域摘要访问的子页面。确切列表由已安装的 ARGVUS 提供程序确定。

每个页面在标题中显示其路径，例如 `Control Center > Hardware & Connectivity > Audio`。路径以列出该页面的首页卡片开始，因此无论从首页、搜索还是 CLI 访问，同一页面显示相同。根目录和卡片名称已翻译：葡萄牙语界面中显示 `Central de Controle > Hardware e conectividade > Áudio`。

## 每个区域的用途

### 外观

外观是主要的自定义区域。它的桌面组包含主题（及其粘滞或间隔模式）、外观模式、强调色、壁纸、图标主题和字体页面，而其应用程序样式组则包含终端和启动器的透明度。任务栏、控制面板和小部件遥测直接列在主页的外观下，并重用外观的共享透明度页面作为它们自己的界面。模糊是一个全局设置，在 Hyprland > 模糊 下，并且它适用于所有启用模糊的 ARGVUS 界面。该页面编辑其启用开关和 Hyprland 模糊值（大小、通过、亮度、噪点、对比度、鲜艳度和鲜艳度暗值）作为草稿，直到选择 **应用** 才会生效。动画在 Hyprland > 动画 下的工作方式相同：其启用开关、自定义曲线（贝塞尔、弹簧、线性和缓出）以及五个动画类别构成一个草稿，该草稿 与 **应用** 一起使用。Bézier（贝塞尔）和 Spring（弹簧）有可编辑的参数（贝塞尔点以及弹簧的质量、刚度和阻尼）；Linear（线性）和 Ease-out（缓出）是固定曲线，所以它们的页面只列出控制点，无法编辑。样式选择遵循 Hyprland 0.56.2 的绘制方式：Opening（打开）和 Closing（关闭）提供 slide（滑动）、popin（弹入）和 gnomed（小人化）；layer entrance（图层进入）和 exit（图层退出）提供 slide、popin 和 fade（淡出）；workspace leaves（工作区离开）提供 slide、fade、slidefade、slidevert 和 slidefadevert。这些控制与外观和会话组件协调，而不仅仅改变控制中心窗口。

### 任务栏

任务栏配置面板的位置、面板及其窗口周围的间距、高度和边框、实用程序图标组以及日期/时间模块，同时还包括它自身的透明度。在首页的 **外观** 下列出。在 Sticky 模式下，**Spaces > Bottom** 默认值为 `2`；Spaced 保持其 `18` 像素基线。

**高度** 可以选择 24、28（默认）、32 或 36 像素。**边框** 有一个 **启用** 开关和一个 1 到 3 像素的 **厚度**，默认是 1。关闭边框时，任务栏窗口、右侧组和 MPRIS 播放器没有边框。这些更改在选择 **应用** 之前都是草稿。应用后，高度和边框将在更换主题时保留；在应用之前，主题会决定它们。

**图标** 页面打开 **可选模块**、**工作区展示**、**启动器** 和 **实用工具**。可选模块可以单独显示或隐藏：音频播放器、专注模式、启动器、网络、电源配置文件、键盘布局、内存、CPU 和温度读数、日期、时钟、电池、系统托盘、通知、可移动设备、录音、蓝牙、音频输入/输出以及保持唤醒。工作区始终可用，并且可以显示其名称（默认）或应用程序图标。焦点窗口标题、设置和电源操作始终可用。启动器的可见性由可选模块控制；其子菜单可以更改自定义图标。更改在点击 **应用** 后生效，这会重新启动任务栏。

### 控制面板

控制面板可配置其快速操作卡片的可见性和顺序，以及其自身的会话和透明度。

页面在读取卡片设置后立即打开并接受输入。依赖硬件的卡片（蓝牙和亮度）会在后台进行检查：在检查完成之前，它们保持在此窗口中最后看到的可用性，并且当结果到达时列表会自动更新。

### 小部件遥测

小部件遥测配置系统信息小部件的会话和透明度。

### 字体

字体可通过 **外观 > 桌面风格 > 字体** 进入。它允许您为任务栏、遥测/系统信息、控制面板、ARGVUS 系统界面、应用程序、终端和浏览器选择字体系列和大小。同时还提供字体渲染设置，如抗锯齿、提示、子像素模式和 DPI。默认主要字体系列是 IBM Plex Mono；各个目标可以独立更改，并可在字体页面恢复。

### 默认应用程序

默认应用程序为终端、文件管理器、文本编辑器、终端编辑器、浏览器、图像查看器、PDF 查看器、视频播放器、音频播放器、压缩工具和启动器等角色选择已安装的程序。选择由 ARGVUS 保存，并可能更新标准的 XDG 关联。TUI 文件管理器在打开文本文件时使用所选择的终端编辑器；图形文本编辑器仍然是桌面文件关联的默认编辑器。

### 片段

片段是 `argvus snippets` 使用 `SUPER + ALT + N` 输入文本的页面。它位于 **工具与诊断 → 片段**（搜索 `snippets` 或运行 `argvus control-center snippets`）。

- **新片段** — 输入一个 **名称** 和 **内容**，然后点击 **保存片段**。已存在的名称会替换该片段的内容。
- **已保存片段** — 以其位置（`1  email`）和单行内容列出。在内容上输入进行编辑。**类型** 会输入片段，**移除** 会要求确认。
- **打开选择器** — 打开与 `SUPER + ALT + N` 相同的选择器。

输入在按下回车后三秒开始，因为此时控制中心本身具有焦点。在这段时间内点击应接收文本的字段。页面只编辑单行内容；可在终端使用 `argvus snippets add` 创建多行片段。

页面从 `argvus-config` 读取条目，并通过 `argvus snippets` 写入，因此启动器保持验证。当未安装 `argvus snippets` 时，页面会提示。

### SSH 密钥

SSH 密钥是 `argvus keys` 管理的密钥对页面。它位于 **工具与诊断 → SSH 密钥**（搜索 `ssh keys` 或运行 `argvus control-center ssh-keys`）。

页面从上到下有四个部分：

```
Search        filters the key pairs by name or comment
Generate      name, type and the Generate key pair action
Keys          one block per key pair; a scrollbar appears when they do not fit
Actions       Refresh and Unload all keys from agent
```
#### 如何使用它

1. 打开 **控制中心 → 工具与诊断 → SSH 密钥**。在主页上，你也可以搜索 `ssh keys`。
2. **查找密钥：** 按 `/`，然后输入以仅显示名称或注释匹配的密钥对。`Enter` 结束搜索并运行高亮行，就像在其他列表中一样，所以在按下它之前请检查该行；`Esc` 清除搜索。
3. **创建密钥对：** 在 **生成** 中，选择 **名称**，按 `Enter`，输入名称，然后再次按 `Enter`。选择 **类型** 并按 `Enter` 在 `ed25519` 和 `rsa` 之间切换。选择 **生成密钥对** 并按 `Enter`。新密钥对会立即出现在 **密钥** 下，无需输入密码短语。
4. **复制公钥：**在密钥对的区块中，选择 **复制公钥** 并按下 `Enter`。`.pub` 文件的内容会被发送到 Wayland 剪贴板，准备粘贴到服务器的 `authorized_keys` 或 Git 主机中。私钥从不被复制。这需要 `wl-clipboard` (`wl-copy`)；没有它，页面会显示密钥未被复制。
5. **将密钥对加载到代理：**在密钥对的区块中，选择 **加载到代理** 并按下 `Enter`。没有密码短语的密钥会立即加载，不会弹出窗口。带有密码短语的密钥会打开一个 ARGVUS 终端，OpenSSH 会在其中请求密码；当提示密钥已加载时，用 `Enter` 关闭终端。页面在终端打开期间每隔几秒检查一次代理，因此行会自动变为 **从代理卸载**。若要立即更新，请在 **操作** 中使用 **刷新**。
6. **从代理中删除密钥：** 在配对的块中，选择 **从代理卸载**。要删除每个密钥，请使用 **操作** 中的 **从代理卸载所有密钥**。密钥文件保留在磁盘上。
7. **删除对：** 在对的块中，选择 **删除** 并按 `Enter`。确认的重点是**取消**，所以流浪的`Enter`什么也不做。按 `y` 确认，或按 `n`/`Esc` 取消。 Agent中加载的密钥不可删除；先卸载它。

四处移动：`↑`/`↓` 或 `j`/`k` 在列表中移动，`Enter` 激活一行，`Esc` 返回，`?` 显示帮助。 `Tab` 将焦点移至 **操作**，其中 `←`/`→` 选择一个按钮，然后 `Enter` 运行该按钮。 `↑`/`↓` 将焦点带回列表。

密码短语永远不会输入到控制中心，也不会作为命令参数传递。该页通过 `argvus keys list` 读取列表，仅通过 `argvus keys` 写入。当`argvus-keys`没有安装时，页面是这样说的。

#### 排查故障

| 现象 | 原因和解决方法 |
| --- | --- |
| 在 **Load into agent** 后出现 `Could not open a connection to your authentication agent` | 终端未收到代理套接字。Hyprland 保留它启动时的环境，而代理可能稍后才启动。更新 `argvus-launcher`，它回退到 `$XDG_RUNTIME_DIR/ssh-agent.socket`，并检查 `systemctl --user status argvus-ssh-agent.service`。 |
| **Agent** 显示 `Agent unavailable` | 启动器无法连接代理。按上述方式检查服务。 |
| 页面显示 `argvus-keys is not installed` | 更新 `argvus` 软件包：`argvus keys` 是其子命令。 |
| **Delete** 显示错误 | 密钥已加载在代理中并被保留。先卸载它，然后再删除一次。 |

### GPG 密钥

GPG 密钥是 `argvus gpg` 管理的密钥环页面。它位于 **工具与诊断 → GPG 密钥**（搜索 `gpg keys` 或运行 `argvus control-center gpg-keys`）。

页面从上到下有以下部分：

```
Pinentry         the pinentry gpg-agent uses, for information only: pinentry-gtk
Generate key ▾   full name, e-mail, comment, algorithm, key strength, expiration date,
                 passphrase, and the Generate key and Cancel actions (expanded at first)
Import ▾         Import public key… and Import private key… (expanded at first)
Keys ›           the keyring, on its own page, with the search at the top
```
`▾` 表示已展开的部分，`▸` 表示已折叠的部分。`Enter` 或 `Space` 用于展开或折叠它。

#### 使用方法

1. 打开 **控制中心 → 工具与诊断 → GPG 密钥**。在主页中，你也可以搜索 `gpg keys`。
2. **Pinentry** 被固定为 `pinentry-gtk`。页面只能显示它。第一次生成密钥时，ARGVUS 会将该 pinentry 写入 `gpg-agent.conf`，放在它自己的标记行之间，并保留你其他的行。如果你已经在这些标记之外写了 `pinentry-program` 行，生成会因错误而停止，这样你可以删除那一行。
3. **创建密钥：**在 **生成密钥 ▾** 中输入 **全名** 和 **电子邮件**。两者都是必填项，并且在两者都有内容之前 **生成密钥** 会保持禁用。**注释**是可选的。用户 ID 变为 `Name (comment) <e-mail>`。
   - **算法** 可以在 **RSA** 和 **DSA ElGamal** 之间切换。DSA 密钥会获得一个 ElGamal 加密子密钥；RSA 密钥会获得一个 RSA 子密钥。
   - **密钥强度** 循环显示算法的大小：RSA 1024、2048 和 4096；DSA 1024、2048 和 3072。gpg 不创建超过 3072 位的 DSA 密钥，因此 DSA 不提供 4096 位选项。
   - **到期日期** 会打开自己的页面。按照您语言的格式输入日期：葡萄牙语、西班牙语、法语、意大利语、德语和俄语为 `DD/MM/YYYY`；英语、中文、日语和韩语为 `YYYY/MM/DD`。日期必须晚于今天。开启 **永不过期** 可以使密钥永久有效；此时日期字段将被禁用并且不使用。
   - **密码短语** 会打开自己的页面。默认开启 **使用密码短语保护**；输入 **密码短语** 然后确认 **确认密码短语**。两者必须匹配。关闭保护会清空两个字段，并且页面会在生成未保护密钥前要求确认。
4. 选择 **生成密钥** 并输入 `Enter`。该密钥会生成一个签名密钥和一个加密子密钥。口令会通过标准输入发送到启动器，而不是作为命令参数。如果生成失败，其他字段保持不变，但口令会被清除，必须重新输入。
5. **取消** 会清除表单的所有字段，并将日期和大小恢复为默认值。
6. **导入:** 在 **导入 ▾** 中，选择 **导入公钥…** 或 **导入私钥…**。文件管理器会打开以便选择文件。私钥在导入前会要求确认，并且在使用该密钥时，gpg 会要求输入其口令。如果文件管理器是图形化的，它无法向页面报告文件；此时页面会打开一个字段，供您输入路径。
7. **密钥 ›** 打开密钥环。每个密钥显示其身份、指纹、类型、到期时间以及私钥是否在密钥环中。每个密钥有以下操作:
   - **编辑密钥 ›** 打开该密钥的详细页面（如下所述）。
   - **导出公钥…** 会要求提供文件路径，初始建议为 `~/<fingerprint>.asc`。文件将以 `600` 模式创建。现有文件不会被替换。
   - **导出私钥…** 仅对含有私钥部分的密钥显示。它先要求确认，然后要求提供文件路径，初始建议为 `~/<fingerprint>-private.asc`。文件将以 `600` 模式创建。
   - **复制公钥** 和 **复制指纹** 会将内容复制到 Wayland 剪贴板，使用 `wl-copy`。
   - **删除密钥…** 会要求确认，焦点默认在取消上。它会删除该密钥及其私钥部分。
8. **查找密钥：** 在 **密钥** 页面，顶部的搜索栏可用于筛选密钥。输入内容以缩小列表；搜索将匹配身份（包括备注）和指纹。`Esc` 清除搜索。
9. **编辑密钥 ›** 显示密钥详细信息，然后提供以下操作：
   - **到期日期 ›** 更改密钥及其各子密钥的到期时间。使用 **永不过期** 可移除到期时间。**应用** 保存更改。
- **更改密码** 在 pinentry 窗口中要求输入旧密码和新密码。
- **使用 › 签署密钥** 使用您拥有私钥的其他密钥来认证此密钥。将要求输入签名者的密码。此页面会先请求确认。
- **撤销密钥 ›** 列出原因：无原因、密钥被泄露、密钥已被替代、密钥不再使用。每个选项都需要确认。撤销的密钥将无法再使用。
- **信任** 设置您对密钥的信任程度：未设定、边缘、完全或终极。
- **发布到密钥服务器…** 在确认后将公钥发送到 `gpg.conf` 中设置的密钥服务器。**从密钥服务器获取** 从该密钥服务器下载密钥。

移动操作：`↑`/`↓` 或 `j`/`k` 在列表中移动，`Enter` 激活一行，`Esc` 返回，`?` 显示帮助。

口令只输入在口令页面的隐藏字段中，或者输入到 pinentry 窗口。该页面通过标准输入将生成口令发送给 `argvus gpg`，启动程序通过文件描述符传递给 gpg，因此口令从不出现在进程列表、命令参数或日志中。密钥更改在后台运行；当一个密钥更改运行时，其它操作会等待。页面使用 `argvus gpg list` 读取密钥环，仅通过 `argvus gpg` 写入。当 `argvus gpg` 未安装时，页面会提示。

页面尚不支持：通过姓名或电子邮箱在密钥服务器搜索密钥。请使用 **从密钥服务器获取** 并提供已知指纹。

#### 故障排除

| 症状 | 原因和解决方法 |
| --- | --- |
| 页面显示 `argvus gpg is not available` | 已安装的 `argvus-launcher` 早于 GPG 命令。请在终端运行 `argvus gpg list`：`unknown command` 意味着必须重新构建并安装该软件包。密钥也需要 `gnupg`。 |

| **Pinentry** 显示 `Not set` | gpg-agent 使用内置默认值，直到页面上生成第一个密钥。 |

| 文件管理器打开，但页面要求输入路径 | 文件管理器是图形界面的，无法报告所选文件。在字段中输入路径。 |

| **编辑密钥 ›** 显示密钥不再在密钥环中 | 自页面打开以来密钥环已更改。返回 **密钥 ›** 并刷新。 |
| 状态行显示 `argvus-gpg: ...` | 启动器拒绝了该操作，文本给出了原因，例如过期无效、文件已存在或缺少 `--yes`。 |

| 导入被拒绝 | 文件中不包含所选类型的密钥。公钥通过 **导入公钥…** 导入；私钥通过 **导入私钥…** 导入。 |

#### 连接，灵感来自 nmtui

**网络和 Wi-Fi > 连接** 列出每个 NetworkManager 连接配置文件，按类型分组，并显示其所在设备（`★ Active · eno1`）、是否为桥接、绑定或团队的端口，以及是否为只读。`Enter` 在编辑器中打开配置文件，`a` 连接或断开连接，`/` 按名称过滤，`r` 刷新。**激活连接** 是相同的列表，其中 `Enter` 使配置文件启用或禁用，如同 `nmtui`。接口、保存的 Wi-Fi 网络和 VPN 的详细页面都有一个 **编辑连接** 行，可打开其配置文件。

**添加连接** 可创建以太网、Wi-Fi、移动热点、DSL（PPPoE）、桥接、绑定、团队、VLAN、IP 隧道、回环和 WireGuard 配置文件，以及每个已安装的 NetworkManager VPN 插件的一个 VPN 配置文件（OpenVPN 有自己的表单；其他插件作为 `key=value` 条目编辑其设置）。它还可以导入 WireGuard `.conf` 或插件文件，例如 `.ovpn`（`nmcli connection import`）。团队需要 `libteam` 软件包，DSL 需要 `ppp`，VPN 需要其插件（例如 `networkmanager-openvpn`）；没有这些时，行会被禁用并提示安装内容。不提供 WEP、InfiniBand、MACsec 和 Open vSwitch。

编辑器是一个可折叠部分的列表：**常规**（名称、界面、自动连接、优先级、对所有用户可用、计量），类型自身的设置，**IPv4** 和 **IPv6**（方法、地址、网关、DNS 服务器、搜索域、路由、忽略自动 DNS 或路由、从不作为默认路由、路由度量、隐私扩展、地址生成）。选项和数字会随 `←/→` 变化；`Enter` 输入一个值；列表（地址、DNS、路由、允许的 IP）会打开自己的页面，`Enter` 可编辑条目，清除则删除它，**添加条目** 则追加一个。对于所选方法不适用的字段会显示为禁用。桥接、绑定或团队在子页面选择其以太网 **端口**；WireGuard 在子页面编辑其 **节点** 并可以 **生成密钥对**（使用 `wg`，从 `wireguard-tools`，这是 `argvus` 包的依赖）；私钥的公钥显示在其下方。

在点击 **保存** 之前，任何内容都不会发送到 NetworkManager，当没有更改或某个字段无效时，保存按钮保持禁用状态，并会提示哪个字段存在问题及原因。只有更改过的设置会被写入。保存一个已激活的连接会先询问，然后重新连接，使新设置立即生效（这可能会短暂中断网络）。对 `Esc` 未保存的更改会在放弃前进行询问。**删除连接** 位于危险区域，会要求确认并默认焦点在取消；删除桥接、绑定或团队连接时也会同时删除其端口。

密码、私钥和预共享密钥永远不会被读取回：它们的行显示为*未更改*，直到输入新的值，新值会以掩码形式显示。它们通过`nmcli connection edit`的标准输入写入，绝不是作为命令参数。更改以会话用户身份运行：`wheel`的本地成员根据NetworkManager的polkit规则被允许操作，其他用户会被会话的polkit代理要求输入管理员密码。

### 系统工具

系统部分可以显示启动信息、软件包、服务、存储、诊断、用户/组管理和系统信息。这些都是管理或诊断工具；页面可能是只读的，也可能根据操作需要授权。

**服务** 有四个页面：系统单元、用户单元、失败单元和日志。每个单元列表显示一行 `Filter:`，该 `f` 循环，带边框的 `Search:` 框，可通过 `/` 打开。每个单元显示其活动和启用状态为实心或空心点。在日志中，`b` 在当前启动和上一次启动之间切换，`u` 循环单元，`p` 循环优先级；`Filter:` 行显示正在使用的值。`Enter` 打开一个单元或日志条目。

**开发服务** 在一个只读页面中报告三个面向开发的来源：当前用户的 systemd 服务、当前监听的 TCP 端口 (`ss`) 以及任何已安装容器运行时（Podman、Docker）正在运行的容器。仅当系统上至少存在其中之一时，它才会出现在首页网格上 —— 没有 systemd 用户会话、没有 Podman 也没有 Docker 的机器不会显示该入口。`r` 独立刷新这三个来源，因此一个缓慢或失败的来源（例如停止响应的容器运行时）不会阻止其他来源显示其数据。

**软件包**按来源分组。**官方仓库**，以及当安装了 AUR 助手（`paru` 或 `yay`）时，**AUR（Arch 用户仓库）**各自展开 **安装**、**移除** 和 **更新**；随后是 **缓存**、**历史**、**降级** 和 **镜像**。这三个任务共用一个界面：固定在顶部的 **搜索** 框接受你输入的字母，软件包列在其下方的 **结果** 区块（更新任务时显示 **更新**），如果列表为空，会显示原因（例如 **无结果**、**无匹配项目** 或 **无待更新项目**）。**安装**在搜索时会查找官方仓库（`pacman -Ss`）或当你在顶部搜索栏按 `Enter` 时查找 AUR；**移除**列出已安装的软件包（AUR 列表显示在仓库之外构建的软件包，`pacman -Qm`，并且在显示 AUR 菜单时，它们会从官方列表中移出）；**更新**列出待更新的软件包（`pacman -Qu`，或者 AUR 使用 `paru -Qua`/`yay -Qua`）。在 包，`Enter` 运行屏幕任务，`→` 打开包页面，带有**安装**（或**重新安装**），并在其**危险区域**中**删除**； `←` 或 `Esc` 返回。 **官方存储库 → 删除**以 **Orphans** 开头，其中 `Space` 标记软件包 (`[x]`)，`Enter` 打开一个软件包，然后 **删除标记** 将它们一起删除。从更新结果列表中，`Tab` 移至列表下的 **操作** 栏（**升级全部**和 **刷新数据库**，或 **升级 AUR 上的全部 (AUR)**），`←`/`→` 在其按钮之间移动，`Enter` 运行焦点按钮并`↑`/`↓`（或键入）将焦点带回列表； **全部升级** 会变暗并被跳过，但未列出任何更新。面包屑和全局搜索遵循相同的路径，例如 **Packages > 官方存储库 > 删除 > Orphans**。缓存清理位于缓存页面的危险区域，**镜像→配置镜像**设置之前的反射器选项 **生成预览**。每个软件包操作都会显示其计划，或者对于 AUR，会显示 PKGBUILD 警告，并在执行前要求确认（`y` 确认，`n` 或 `Esc` 取消），其输出将在运行时显示。AUR 操作以你的用户身份运行助手（`-S <package>` 用于安装或更新单个软件包，`-Sua` 用于更新所有软件包）；AUR 卸载使用与官方软件包相同的 `pacman -Rns`。当其他已安装的软件包依赖你要卸载的软件包（官方或 AUR）时，确认会列出它们并提供两种方式：**仅卸载**所选软件包（`pacman -Rdd`，会跳过依赖检查，因此需要它的包可能会停止工作）或**连同依赖包一起卸载**（`pacman -Rcns`，并显示要删除的软件包数量）。焦点将默认在**取消**上，这会保留所有软件包；`Enter` 执行当前焦点的操作，并且在此选项中没有 `y` 快捷键。

顶部的**搜索**栏拥有包查询。 `/` 聚焦它而不清除其文本；打字也会将焦点移到那里。使用箭头键、`Home`、`End`、`Backspace`、`Delete` 进行编辑或粘贴。在 **Install** 中，即使以前的结果存在，`Enter` 也会提交存储库/AUR 查询，然后将焦点移至结果；官方搜索需要非空查询，AUR 搜索需要至少两个字符。编辑安装查询会取消其挂起的请求并清除其旧结果；新请求等待 `Enter`。在**删除**、**更新**和**孤立**中，编辑会立即过滤加载的列表，而无需再次进行存储库查询。 `↓` 从搜索移动到结果，第一个结果上的 `↑` 返回到搜索，搜索中的 `Esc` 返回到列表，同时保留查询。 `Enter` 对结果执行该包的操作。 `Tab` 仍然可以访问“更新”操作栏，并且 `/` 从该操作栏返回到“搜索”。

**Packages**中的所有操作都会打开一个集成的交互式终端：官方包、AUR、缓存清理、镜像和存储库/密钥更改。通过键入并按 `Enter` 来回答程序的提示； pacman 在此终端中运行时没有 `--noconfirm`。 `Esc` 隐藏视图并保持进程运行。 `F8` 从任何“包”页面重新打开同一会话； **显示终端**也可以在其菜单中找到。页脚显示事务是否正在运行、已完成或失败。成功执行命令后，`Done!` 在其最终输出后出现在终端内，包括隐藏终端时。 `Shift+PageUp` / `Shift+PageDown` 滚动历史记录，`Shift+End` 返回实时输出，`Ctrl+C` 向子进程发送中断。当终端处于焦点状态时，`q` 和 `?` 是输入而不是全局快捷方式。输出、ANSI 颜色和光标将被保留，并且调整大小会更新子终端。历史 在下一次操作或应用程序退出之前，最多保留10,000行。一次只能运行一个事务；隐藏其终端并不允许应用程序在其运行时退出。不会打开自由的终端。

升级预览会读取现有的同步数据库（`pacman -Su --print`），不会更改它们，也不需要 root 权限。确认后，完整升级通过带有 pkexec 的特权助手运行 `pacman -Syyu`；同步可以显示额外的更新。软件包安装、卸载、数据库刷新、缓存清理、降级、仓库/密钥更改以及镜像写入也使用该特权助手。AUR 助手仍然以你的用户身份进行构建。

**官方存储库 → 存储库** 添加和管理非官方 pacman 存储库。 **Add** 是一个草稿：选择配置的 **Source**（ `pkexec` `.conf` 文件的 **URL**，在多行编辑器中键入或粘贴的 **Text**，或在 Arch Wiki 布局中编写的带有 **Name**、**Server** 和 **SigLevel** 的 **Form**），以及在 **Signing key** 下，来自 **URL** 或 **Text** 的 **Key**（或 **None**）。选择随 `←`/`→` 或 `Enter` 移动；文本字段打开一个编辑器，其中 `Enter` 保存单行，`Ctrl+S` 保存多行，粘贴工作，`Esc` 取消。下载仅接受 `https://` 地址。 **审查和添加** 以您的用户身份下载并检查所有内容，然后要求确认，以四组为一组列出存储库、服务器和 SigLevel 以及密钥的用户 ID 和指纹，以与存储库发布的进行比较。确认导入密钥并在本地对其进行签名（`pacman-key --add`、`--lsign-key`），写道 `/etc/pacman.d/<name>.conf`（以其第一个部分命名）并添加 `Include = /etc/pacman.d/<name>.conf` 到 `/etc/pacman.conf`（同一文件的现有注释行被启用）。之后，控制中心提供 `pacman -Syyu`，因此新的数据库在没有部分升级的情况下同步。将 **Add** 保持为草稿状态会在放弃之前进行询问。**List** 显示每个非官方仓库，无论是直接写在 `pacman.conf` 中还是从 `/etc/pacman.d/` 包含的，启用或禁用状态；官方部分永远不会列出。仓库页面显示其文件、SigLevel、服务器和记录的密钥，一个 **Enabled** 切换按钮，在 **Danger zone** 区域有 **Remove**。禁用会注释 `Include` 行，或在内联部分的每一行前加上 `#argvus-off ` 前缀；移除会删除该行或整段及被包含的文件。同一包含文件的仓库会一起启用、禁用或移除。当控制中心 导入了密钥，**移除** 还提供从 pacman 的密钥环中移除它（`pacman-key --delete`）。对 `/etc/pacman.conf` 的每次更改都会在旁边保留一个备份（`pacman.conf.argvus-backup-…`），已安装的软件包永远不会被删除。

### 用户和组

当账户提供者可用时，打开 **控制中心 → 系统管理 → 用户和组 → 用户** 或搜索 **用户**。该界面可以列出普通和系统账户，创建用户，编辑账户元数据，管理附加和主组，更改或锁定密码，解锁密码，要求下次登录更改密码，设置或移除头像，以及启用自动登录。

创建用户时需要输入用户名、全名、shell、附加组以及一个可选的密码确认。空密码会创建一个密码被锁定的账户；它不会悄悄创建一个可用的密码。用户页面将账户字段（全名、shell、主要和附加组，随后是**保存更改**）、**自动登录**切换按钮、**密码**操作（更改、锁定、解锁、下次登录时要求更改）和**头像**操作分组显示。用户名、UID / GID和主目录仅用于参考。最后的**危险区域**包含单独的破坏性操作，可以在保留主目录的情况下删除账户，或者连主目录一起删除。在选择后一种操作之前，请仔细阅读确认文本。账户操作需要特权，可能会打开系统授权提示。头像可以通过账户的标准头像被登录界面使用。 图像集成。

**自动登录** 会在下次启动时直接启动所选账户的会话，而不会显示登录界面，这与 GNOME、LightDM 和 SDDM 在此功能上的惯例相同：不会在任何地方存储密码。为一个账户启用自动登录会禁用之前配置的任何账户（一次只能自动登录一个账户）。该功能只在下次启动时生效；手动注销后，在本次会话的剩余时间里将恢复正常的登录界面。切换此功能会立即生效，并会有确认提示，仅管理员可用。

群组有自己的列表和编辑页面，包括成员管理和群组删除。控制中心并不取代系统的账户策略：受保护的系统账户以及需要授权的操作仍然受操作系统限制。

### 控制中心设置

**设置** 是主界面的最后一项。其 **语言** 页面通过 locale.conf 设置用户语言，其 **风格** 页面控制装饰图标和控制中心的透明度。风格不包含模糊效果：模糊是全局 Hyprland 设置，位于 Hyprland > 模糊。风格页面更改的是设置应用的显示效果；它不是禁用 ARGVUS 服务或移除设置提供者的开关。保存图标可能需要授权，而视觉更改会应用于当前应用。风格页面按 Esc 返回设置页面，设置页面按 Esc 返回主界面。

### 关于 ARGVUS

**关于 ARGVUS** 位于 **工具与诊断 → 关于 ARGVUS**（搜索 `about`、`hardware` 或 `firmware`，或运行 `argvus control-center about`）。它有五个选项卡，可通过 `Tab`/`Shift+Tab`、`←`/`→` 或 `h`/`l` 切换：**系统与硬件**、**关于**、**捐赠**、**致谢** 和 **版权**。标题显示完整路径，例如 `Control Center > Tools & Diagnostics > About ARGVUS > System & Hardware`。

**系统与硬件** 为只读，并将此机器的信息分为三个部分，数值在一列中对齐：

| 部分 | 字段 |
| --- | --- |
| 启动 | 固件（厂商、版本和日期）、类型（UEFI 或 传统 BIOS）、安全启动（仅 UEFI）、虚拟化、引导加载程序 |
| 系统 | ARGVUS、主机名、操作系统、发行商、内核、架构、窗口管理器（Hyprland）、合成器（Wayland）、GPU 驱动、GTK、主题（含深色或浅色）、显示器（每个显示器一行）、音频（PipeWire）、Shell（Quickshell）、登录（greetd）、初始化（systemd）、软件包、运行时间、本地化 |
| 硬件 | 电池（每块电池一行）、CPU（含最大频率）、线程、核心、GPU、内存（已用/总计）、交换空间、存储、型号（仅当与主板不同）、主板 |

每个值均从运行中的系统读取，无需特权，并且该页面在任何机器上都能正常工作。无法读取的值显示为 `N/A`，不适用的行将被省略：

- **固件**、**型号** 和 **主板** 来自 DMI (`/sys/class/dmi/id`)；类似 `To be filled by O.E.M.` 的占位符值会被忽略。**类型** 和 **安全启动** 来自 `/sys/firmware/efi`，而 **虚拟化** 来自 `systemd-detect-virt`。
- **引导加载程序** 从 `LoaderInfo` EFI 变量读取，systemd-boot、Limine 以及其他遵循 Boot Loader Interface 的引导加载程序会发布该变量。GRUB 不发布，因此由 `/boot/grub`（或 `/efi/grub`）识别，并显示 `grub` 包的版本。
- ARGVUS、Wayland、Mesa、PipeWire、Quickshell、greetd、systemd 和 GRUB 的版本来自一次 `pacman -Q` 查询，并显示时不带 epoch 和包发布版本（`1:25.2.3-1` 变为 `25.2.3`）。Hyprland 版本来自 `hyprctl version`，或者当没有会话回答时从包中获取。
- **GPU 驱动** 显示绑定到 `/sys/class/drm` 每张 DRM 显卡的驱动程序。专有驱动显示其模块版本（例如 `nvidia 580.82.07`）；内核驱动显示 Mesa 版本（例如 `amdgpu (Mesa 25.2.3)`）。
- **显示器** 列出来自 `hyprctl monitors -j` 的活动显示器：接口、分辨率、刷新率和缩放（当缩放为 1 时省略）。
- **软件包** 统计所有已安装的软件包、显式安装的软件包以及外部软件包（AUR 或本地构建），来自 `pacman -Qq`、`-Qqe` 和 `-Qqm`。
- **运行时间** 来自 `/proc/uptime`，为页面打开时的值。**语言环境** 来自 `LANG` 中的 `/etc/locale.conf`。
- **电池** 列出了来自 `/sys/class/power_supply` 计算机的电池，按类型选择，因此无线鼠标等外设不包含在内。每行显示电量、状态、电池健康状况（满容量与设计容量的比较）以及固件报告的充放电周期。没有电池的机器显示 **未检测到**。
- **CPU** 汇总了所有核心的最高最大频率（cpufreq），这是混合处理器的额定最高频率；在大多数虚拟机中，由于 cpufreq 不可用，因此省略。**线程数** 和 **核心数** 来自 `/proc/cpuinfo`。
- **内存** 和 **交换分区** 来自 `/proc/meminfo`（包括 zram）；没有交换分区的系统显示 **已禁用**。
- **存储** 描述了 `/` 下的磁盘：其型号、类型（NVMe、SSD、HDD 或 eMMC/SD；虚拟磁盘不显示类型）、文件系统以及已用空间和总空间。磁盘通过分区、LUKS 和 LVM 追溯到物理设备。

这些数值会在页面首次绘制时后台读取，因此控制中心启动或页面打开时不会等待它们；此期间标签页显示 **正在加载系统信息...**。在此标签页上按 `c` 可以将整个报告作为纯文本复制到剪贴板（使用 `wl-copy`），例如用于粘贴到错误报告中。

## 搜索及可选功能

主屏幕有一个可搜索的路线注册表。搜索词包括面向用户的概念，如外观、主题、壁纸、字体、键盘快捷键、鼠标、触控板、显示器、网络和会话。可选提供程序仅在其功能已编译且检测到运行时能力时才包括，因此可见菜单是刻意根据能力显示的。

在主页搜索处于活动状态时，可打印的键会被输入到查询中，包括 `j` 和 `k`；使用 `↑` 和 `↓` 箭头键浏览匹配的路线。按 `Enter` 打开选定的路线，`Backspace` 编辑查询，`Esc` 清除查询或退出搜索模式。

## 外观工作流程

打开 **外观** 查看集成的视觉控制。它的分组包括:

- **桌面** — **主题**（选择一个捆绑的系列及其粘性或间隔模式，或导出、导入、应用和删除您自己的主题，参见 [导入和导出主题](/docs/components/argvus-themes/import-and-export/))，**外观模式**（粘性或间隔，与主题独立），**强调色**（捆绑的强调色或有效的六位RGB颜色），**壁纸**（捆绑的壁纸或自定义文件），**图标**（已安装的图标主题：使用`/`搜索列表，通过空格键或回车键选择一个，然后选择 **应用**；在应用之前不会有变化），**字体**（字体目标和字体渲染设置，在字体页面打开）。
- **应用风格** — **终端**和**启动器**的透明度。

外观卡包含使用以下设置的界面：**Widget Telemetry**（启用遥测界面，选择其可用块并使用 `Shift+Up`/`Shift+Down` 在聚焦块上重新排序）和 **Control Panel**（启用、禁用及重新排序面板卡，使用 `Shift+Up`/`Shift+Down` 在聚焦卡上操作，通过相同原始方法立即应用，就像真实面板的拖放功能一样）。

这些操作会更新逻辑 ARGVUS 状态并应用受影响的运行时配置。参见 [Appearance](/docs/user-guide/appearance/)、[Themes](/docs/user-guide/appearance/) 和 [Windows and layout](/docs/argvus-hyprland/windows-and-layout/)。

## 键盘使用

设置应用程序支持键盘导航。每个页面都是一个列表：使用箭头键或 `j`/`k` 移动，`Enter` 打开或运行所选行，`Space` 切换，`Esc` 返回，`/` 搜索列表和`?` 寻求帮助；页脚显示适用于所选行的键。操作是列表的行，而不是按钮，`Tab` 不会移动到它们，除非列表下带有 **操作** 栏的页面（默认应用程序、时区、键盘布局、系统区域设置和 SSH 密钥以及创建/编辑快捷方式）。仅显示信息的行将被跳过。当文本字段、搜索或列表过滤器处于活动状态时，`q` 和 `?` 将作为文本键入，而不是退出或打开帮助。在“默认应用程序”上，“恢复默认值”是列表下“操作”栏中的按钮：`Tab` 或 `←/→` 将其聚焦，`Enter` 要求重置。其他页面上的 **重置默认值** 和 **恢复所有快捷方式** 是 **危险中的行 页面末尾的区域**； `r` 要求进行相同的重置，并在快捷方式列表中 `r` 确认后恢复所选快捷方式。在**语言和区域→键盘布局**上，`/` 聚焦页面顶部的**搜索**框，`Esc` 清除它； `●` 标记正在使用的布局。它遵循任务栏和循环布局的键盘快捷键，并且页面会在大约一秒钟内更新，而无需向配置写入任何内容。 `Enter` 设置默认布局，Hyprland 开头的第一个布局以及详细信息中标记为 `Default` 的布局； `Space` 添加或删除布局 (`[x]`)。这些键仅更改草稿，列表下 **操作** 栏中的 **应用** 按钮可一步将布局和默认值写入 Hyprland。从列表中，`Tab` 或 `←/→` 将焦点移动到该栏，同时启用 **应用**（然后页脚显示 `←/→ Actions`）； `←/→` 逐步浏览其按钮，然后 `↑/↓` 返回到 列表。离开未应用更改的页面需要先进行确认。在 **语言和区域 → 时区** 上，布局是相同的：`/` 将焦点放在顶部的 **搜索** 框，`Enter` 在草稿中选择一个区域（标有 `●`），列表下 **操作** 栏中的 **应用** 按钮将其保存在用户的`environment.d/20-timezone.conf`； `Tab`、`←/→` 和 `↑/↓` 与键盘布局相同。离开未应用的区域首先需要确认。在 **系统区域设置** 上，布局与时区相同：`/` 聚焦顶部的 **搜索** 框，`Enter` 或 `Space` 在草稿中标记或取消标记区域设置 (`[x]`)，列表下 **操作** 栏中的 **应用** 按钮将选择写入到`/etc/locale.gen` 并运行 `locale-gen`。因为这会重新生成系统区域设置，所以 **Apply** 首先要求确认； `Tab`、`←/→` 和 `↑/↓` 的工作方式与其他两个相同。在 **桌面和输入 → 键盘快捷键 → 全部 **快捷方式** 搜索框也位于顶部，`/` 用于聚焦它，但页面没有 **操作** 栏：其列表保留快捷方式部分和 **危险区**，页脚仅在列表本身上列出 `r Restore default`，而不是在 **编辑快捷方式** 上列出。

在保存之前收集更改的页面（用户、组、账户创建、密码更改和防火墙配置）会在该块的末尾显示一个 **保存** 或 **应用** 行，直到有更改之前该行会保持灰显状态。如果返回会丢失未保存的更改，控制中心会先进行提示。每次确认都会显示 **确认** 和 **取消** 两行，焦点在 **取消** 上：`Enter` 运行已聚焦的行，`y` 确认，`n` 或 `Esc` 取消。

**外观**中，每一页都是一个单独的列表：页脚只显示适用于所选行的键，并且 `Space` 也会打开或选择该行。需要在应用前收集更改的页面（任务栏、小部件遥测、控制面板和效果滑块）以 **应用** 行结尾，该行在有更改前保持灰显状态。选择 **应用** 时，仅在更改重新创建表面时才显示加载屏幕：任务栏高度、实用程序组、图标或日期和时间格式的更改会重启任务栏；打开或关闭小部件遥测，或更改其块或顺序会重启小部件；打开或关闭控制面板，或在开启时更改其卡片，会重启面板。屏幕随后会保持，直到页面的最后一次更改被应用，因此在此之前不会显示任何更改，表面只重启一次。边框、透明度、模糊、动画、间隙、字体、壁纸及其他设置会直接应用，无需 加载界面。在百分比行上，`←`/`→`（或 `+`/`-`）以 5 的步长更改数值，`Enter` 允许你输入数值；使用 `Esc` 返回。如果返回会丢弃尚未应用的更改，控制中心会先进行提示。删除自定义主题（`d`）或替换导入的主题会要求确认；焦点默认在**取消**，`y` 确认，`n` 或 `Esc` 取消。

## 持久性与重置

设置页面通过其所属的提供者应用更改，并保存所支持的用户状态。外观更改存储在规范配置中，`argvus-config` 是唯一在 `~/.config/argvus/data/generated/` 下写入派生用户文件的组件；这些生成的文件不是进行永久性编辑的地方。输入和按键绑定页面有其自身的持久状态和重置操作。其他系统更改可能需要权限或服务重载。

没有针对每个 ARGVUS 设置的全局重置。从拥有该设置的页面恢复更改，或者使用相关功能的文档中说明的恢复程序。

重置支持是按域故意设计的：

- **外观** 提供将高亮颜色重置为活动主题默认值的功能。它不提供单一的全局外观重置；其他外观值请从各自的控件中恢复。
- **字体** 可以恢复所有字体设置、一个目标或单个设置。
- **默认应用程序** 可以恢复所有默认值、一个类别或单个选择器。
- **键盘快捷键** 可以恢复一个绑定或所有绑定，然后重新加载生成的会话绑定。
- **窗口规则** 位于 **桌面与输入 → Hyprland → 窗口 → 规则**（搜索 `window rules` 或运行 `argvus control-center window-rules`）。每条规则都有一行 **工作区**（`Enter` 或 `←/→` 从 1 到 10 循环）和一行 **窗口类**，该行会打开一个文本字段，可输入以逗号分隔的正则表达式。**添加规则** 会创建 `rule-N`，并且工作区为 1 且没有类。每条规则的 **移除规则** 位于 **危险区** 并会要求确认。所有更改都会写入 `hyprland.window_rules` 并保存到 `argvus config` 中，配置会立即重新加载；无效的类模式会被拒绝并以错误形式显示。

- **项目** 位于 **工具与诊断 → 项目**（搜索 `projects` 或运行 `argvus control-center projects`）。**添加项目文件夹** 和 **添加根文件夹** 位于页面顶部，并打开一个带有路径的文本字段；启动器会检查它是否是一个目录，否则会显示错误，包括当该文件夹会将有效项目数量超过 9 时（`SUPER + CTRL + 1..9` 无法处理更多）。每个配置的文件夹，无论是标记为根（其子文件夹是项目）还是单个项目，都会在表单下面生成自己的区块，并带有一行 **删除**，需要确认。页面调用 `argvus-projects`，因此更改由启动器写入，并在下次运行 `SUPER + O` 或 `SUPER + CTRL + 1..9` 时生效。如果未安装 `argvus-projects`，页面会显示提示。
- **其他系统页面** 仅在底层提供程序支持时才显示重置、应用、删除或恢复操作。

删除用户偏好设置可以使提供程序回退到其打包/默认状态，但手动删除文件并不是通用的恢复程序。优先使用页面的重置操作或文档中描述的特定功能命令。

## CLI 入口点

该助手是 `argvus-control-center`，通过 `argvus control-center` 运行。它可以直接打开特定区域，例如：

```sh
argvus control-center appearance themes
argvus control-center appearance wallpapers
argvus control-center input
argvus control-center keybindings
```
运行 `argvus control-center --help` 以查看已安装版本中可用的路由。命令行路由是进入相同设置应用程序的快捷方式，而不是独立的配置系统。

有用的直接路线包括 `apps`、`window-rules`、`projects`、`snippets`、`ssh-keys`、`gpg-keys`、`firewall`、`fonts`、 `locale`、`input`、`keybindings`、`language`、`config`、`system`、`hardware`、`services`、 `dev-services`、`network`（页面为 `status`、`connections`、`activate`、`add`、`interfaces`、`wifi`、 `ethernet`、`vpn`、`dns` 和 `proxy`)、`audio`、`bluetooth`、`boot`、`packages`（带有页面`official`、`search`、`installed`、`updates`、`orphans`、`aur`、`aur-remove`、`aur-updates`、 `repositories`、`repositories-add`、`repositories-list`、`cache`、`history`、`downgrade` 和 `mirrors`)、`storage`、 `system-doctor`（`diagnostics` 和 `diagnostic` 仍为别名）、`about`（带有选项卡 `system`、`about`、`donate`、 `credits` 和 `copyright`)、`power`、`session`、`displays` 和 `appearance`。外观还接受`themes`、`wallpapers`、`icons`、`accents`、`effects`、`spaces`、`taskbar`等集中路线 `widget-telemetry`；显示接受 `resolution`、`refresh`、`scale`、`position`、`orientation`、`primary`、`vrr` 和 `hdr`。编写脚本时请使用已安装的 `--help` 输出，因为可用性仍取决于已安装的版本。

### 系统医生

打开 **工具和诊断 → 系统医生**，搜索它，或运行 `argvus control-center system-doctor`。之前的 `diagnostics` 和 `diagnostic` 路径及类别选择器仍然可用。按 `r` 刷新，Enter 检查某项，`o` 在某个详情中打开相关页面，Esc 返回。收集在后台运行且为只读。

检查使用 systemd failed-unit 计数、图形工具和存储快照来获取文件系统使用情况和 SMART 健康状况。问题需要证据；不可用的工具或无法访问的 SMART 数据显示为不可用，而探测失败或超时则为错误。没有收集到证据的类别并不意味着检查成功。软件包更新使用本地 pacman 数据库，不会同步仓库；锁文件可能过时，并不能证明操作正在运行。SMART 可能需要权限，但不请求提升访问权限。摘要以 Unix 时间记录最后完成的收集情况。

存储和系统诊断器共享一个内存快照，持续时间最长为 10 秒。按下 `r` 会显式收集新数据；并发请求会重用刚完成的收集。诊断和存储子进程的输出限制为每个流 1 MiB，超出大小的输出会被视为收集失败。

## 快照

打开 **控制中心 > 系统管理 > 快照**，搜索 `Snapper`，或运行 `argvus control-center snapshot`。`snapshot` Cargo 功能包含在 `full`（默认）中，并且独立于 `storage`。该页面标记为 **实验性**，因为该功能仍在开发中，可能不完整。

此页面仅管理现有的 Snapper 配置，其 `SUBVOLUME` 为 `/`，`FSTYPE` 为 `btrfs`。它检查包含 `/` 的挂载点，使用 `findmnt`；指向其他位置的名为 `root` 的配置不被接受。多个匹配的配置需要进行选择。`snapper` Arch 软件包是可选的，必须手动安装。Snapper 必须支持 `--jsonout` 以及显式的活动/默认列。不会自动创建配置。

在非 Btrfs 根目录上，页面显示 **此文件系统不是 Btrfs**，并且不提供快照操作。检测失败、缺少 Snapper、缺少根配置权限拒绝以及后端错误是不同状态。如果普通用户的查询被拒绝，按 **a — 授权** 请求 Polkit 访问权限。管理操作在受限的 `system-settings` 辅助程序中运行，而不是在提升权限的 TUI 中；稍后的查询可能会再次要求身份验证。身份验证需要现有的图形 Polkit 代理。

按键：**↑/↓** 选择，**Enter** 查看详细信息/配置，**c** 创建，**d** 删除，**p** 保留策略，**r** 刷新，**Esc** 返回，**?** 帮助。在保留视图中，**↑/↓** 选择策略，**e** 编辑，**c** 循环切换清理算法，**Enter** 打开确认。创建时可以输入可选描述（最多 256 个可打印字符）；空描述将使用“ARGVUS manual snapshot”。创建和删除都需要确认，初始焦点在取消。删除仅适用于选中的一个快照，并且会拒绝快照 0（当前活动快照和默认快照）。助手在调用 Snapper 前会重新检查这些条件。操作后列表会刷新；中断的操作不会自动重试。请先查看刷新后的列表。

要比较快照，先选择基准并按 **b**，然后选择不同的目标并按 **v**。页面显示按顺序排列的 ID、创建数量,
已删除和已修改的路径，以及 Snapper 的六个状态指示器。选择一个路径并按 **Enter** 请求其内容差异；按 **Esc** 返回已更改的路径，然后返回快照列表。指示器在第 1 位表示创建/删除或内容/类型，第 2 位表示权限，第 3 位表示所有者，第 4 位表示组，第 5 位表示扩展属性，第 6 位表示 ACL。点表示该位置没有变化。状态列出路径；diff 显示文本内容。二进制/非 UTF-8 的差异输出不会呈现。超过 256 KiB 的 diff 输出将被报告为已截断且不显示。模糊或格式错误的状态行将被拒绝。Snapper 的行格式无法明确表示包含换行符的路径；此类名称不受支持。权限错误可以通过 **a — 授权** 重试；已删除的快照或更改的根配置需要刷新列表。后台测试使用一个假的 `ProcessRunner`，并且不需要 Snapper、Btrfs 或 root。

从比较中，选择一个路径并按 **r** 来审查从目标快照恢复文件。助手会验证两个快照仍属于根配置，路径仍在比较中，并且源文件是 Snapper 标准 `/.snapshots/<id>/snapshot` 视图中的普通文件。当文本差异存在时显示受限的 Snapper 差异；对于二进制或超大差异，在未将其全部内容加载到 UI 中的情况下进行标识。**Enter** 会打开一个单独的确认窗口，显示源和目标；**Esc** 在不更改文件的情况下取消操作。确认操作会先创建一个 `single` 安全快照，然后仅使用 Snapper `undochange` 针对该路径检查其是否与所选快照匹配。安全快照 ID 会被报告，并且快照会被保留。恢复操作与 ARGVUS 软件包升级使用的锁共享，因此不能与官方控制中心 pacman 事务重叠。

第一个版本只接受在 root 拥有的父目录下由 root 拥有的常规文件，这些父目录不可被组或其他用户写入。它拒绝目录、符号链接、硬链接、特殊文件、挂载点/子卷、Snapper 的内部目录以及用户可写的位置。从所选快照中缺失的文件永远不会被删除。Snapper 的根 `undochange` 并不保证应用或数据库一致性，也不是原子操作；安全快照只是一个恢复点，而不是保证。Snapper 仅保留其构建支持的元数据。独立子卷和配置根之外的文件将保持在操作之外。

手动快照是 `single`，默认情况下 Snapper 为只读，此页面未分配清理算法。现有的 Snapper 定时器和外部操作仍然适用。快照不是完整系统镜像：独立子卷，
包括一个单独的 `/home`，不包含在内。此版本**不提供完整系统回滚、安装或 Snapper 配置创建**。在支持的根配置上按 **p** 查看已知的保留设置。缺失的值被标记为 ARGVUS 回退值，而非从已安装的 Snapper 创建模板中读取的值；未知键仅用于诊断。按 **e** 编辑支持的值。确认会显示旧值和新值；保存后，页面会再次读取配置并进行验证。按 **c** 循环清理算法，按 **Enter** 审查并确认。清理使用 Snapper 的官方算法；没有精确预览，报告的删除数量是通过执行后比较列表来测量的。Arch Snapper 0.13.2 提供 `snapper-timeline.timer` 和 `snapper-cleanup.timer`；时间线创建需要
时间线计时器和配置的清理策略在没有清理计划的情况下不会运行。此页面仅读取单元状态，并不启用计时器。空间限制需要配置 Btrfs qgroups，但在这里未显示。

### 软件包操作和快照

软件包安装、更新和删除不需要 Snapper、Btrfs 或快照配置。**全部升级** 通过特权助手运行 `pacman -Syyu` 和 `pkexec`；单个官方更新运行 `pacman -S <package>`。ARGVUS 不会为这些操作创建自动快照。快照页面保持独立，并保留自己的 Btrfs/Snapper 要求。pacman 中单独配置的钩子仍由系统控制。

### 手动验证

- 在 ext4/xfs 根目录上，用英语和葡萄牙语打开页面。在葡萄牙语中，确认精确信息 **Este sistema de arquivos não é Btrfs** 并确认 c/d 不会打开操作。
- 在可丢弃的 Btrfs 虚拟机中，测试 Snapper 不存在、Snapper 无根配置，以及名为 `root` 指向另一个子卷的配置。
- 在已有根配置的情况下，列出快照，打开详情，创建带空格/特殊字符的快照，取消删除，然后仅在确认其编号和描述后删除新创建的快照。
- 检查被拒绝/取消的认证，受保护的活动/默认快照，刷新，键盘导航，调整大小以及两种语言。不要测试对恢复所需快照的删除。

只有 `argvus` 软件包会更改。从 `de/argvus` 使用 `make build` 重新构建以生成 `.pkg.tar.zst` 软件包；安装它是另一个操作员操作。

“语言”下的“语言与区域”会将区域设置保存在用户配置文件中（`~/.config/locale.conf`），而不会更改 `/etc/locale.conf`。会话在再次登录后会使用此偏好。在欢迎界面，按 F6 或页脚的“下一步”按钮可以记录审核并前进；Shift+Tab 可聚焦该按钮，Enter 可激活，包括在信息页面上。

只有在控制中心检测到适配器时，蓝牙才会在欢迎界面出现。隐藏蓝牙步骤的现有进度会被保留。

语言和会话键盘布局是个人偏好，不需要管理员权限。新配置文件默认使用英语和美式键盘布局；现有的个人偏好会被保留。日期/时间、NTP、系统区域设置生成和控制台（TTY）键盘映射保留其系统范围的管理行为。

对于巴西会话键盘，选择 `br`，应用布局，然后在变体下选择 `abnt2`。这会在没有管理权限的情况下写入个人 Hyprland 配置；控制台键盘映射是独立的。ABNT2 使用死键：`~` 后跟 `a` 会生成 `ã`，而 `~` 后跟空格会生成 `~`。应用变体会激活其配置的默认布局；激活失败会有报告。

时区在没有授权的情况下将 TZ 保存在 `$XDG_CONFIG_HOME/environment.d/20-timezone.conf` 下。注销并重新登录以便应用程序继承它。日期和时间仍然显示并编辑系统时区中的系统时钟，需要管理权限；NTP 不变。

显示配置文件和工作区分配通过生成的 Lua 配置和 Hyprland 重载应用。显示器电源使用 Hyprland 0.56.2 支持的 Lua DPMS 调度器。

阴影渲染强度限制为 1–4（默认 4），以兼容 Hyprland 0.57。加载配置时，高于 4 的旧存储值会被限制。

## 窗口抖动

打开 **Desktop & Input → Hyprland → Animations → Windows** 并使用 **Wobble** 控件。搜索 `wobble`，或直接打开该页面：

```sh
argvus control-center hyprland animations windows
```
Wobble 默认情况下是禁用的。其 ARGVUS 默认值为：刚度 `100`、阻尼 `10`、质量 `1`、强度 `1` 和网格分辨率 `8`。刚度和质量接受 `0.0001–1000`，阻尼 `0–1000`，强度 `0–2`，网格为整数 `2–32`。更高的网格分辨率会增加渲染成本。使用箭头键调整数值，或按 Enter 键输入数值。**恢复 Wobble 默认值** 会更改草稿；**应用** 会保存所有待处理的动画修改并重新加载 Hyprland 一次，无需重启会话。在动画中返回时会保留共享草稿。

全局动画开关会在保留其单独设置的同时抑制 Wobble。标准值存储在 ARGVUS 状态的 `effects.wobble_*` 下；`hypr/state.lua` 是生成的，不可手动编辑。

这需要 Hyprland **0.57.0 或更高版本**，由 `argvus-hyprland` 的软件包依赖强制执行。版本 0.56 不支持此配置。强度最大值遵循 [发布的 0.57.0 源代码 ](https://github.com/hyprwm/Hyprland/blob/v0.57.0/src/config/values/ConfigValues.cpp)，将其限制为 `2`，即使较新的文档可能列出 `3`。

欢迎界面以 ARGVUS 标志和 WELCOME 开始。按 F6 下一步可以显示检查表而无需完成步骤。

新安装默认使用个人时区 `America/New_York`，并且仅启用 `us` 键盘布局。现有的个人设置将被保留；系统时区保持不变。

只有在检测到相应硬件时，任务栏模块的电池和蓝牙选项才会出现。隐藏“保持唤醒”会隐藏其指示器，但不会更改挂起抑制器。实用程序支持折叠的悬停抽屉。工作区图标显示打开窗口的图标；系统托盘控制后台应用程序图标。

键盘快捷键页面包括**AI 代理选择器（可选 argvus-ai 包）**，默认组合键为 SUPER + A。它使用 app.ai 目录 ID，因此重新映射和禁用遵循与其他条目相同的标准 keyboard_shortcuts 配置。其可执行的 Lua 绑定由 argvus-ai 提供；仅目录条目本身在没有该可选包的情况下无法激活它。


控制中心 > 外观 > 任务栏 > 图标 > 可选模块现在包括 **AI 代理**。默认启用，并存储在 /taskbar/icons/ai_agents_enabled。可在任务栏草稿中切换并点击应用以保持设置并重新生成实用程序组；禁用不会更改 SUPER + A 快捷键或应用启动器条目。

自动启动开关编辑用户的 `.desktop` 条目或创建系统条目的用户副本。名称、命令和启用标志来自 `[Desktop Entry]`；其他桌面操作组保持不变。

服务确认保留所选的用户/系统范围以及单元和操作。其他范围中同名的单元不能重定向已确认的操作；详细信息页面也保留原始范围。

存储包括来自文件系统清单的嵌套挂载点，如 `/home`、`/boot` 和 `/boot/efi`。诊断使用相同的清单来检查现有的 root 和 home 文件系统使用情况。

新的恢复安全快照使用 Snapper 的 `number` 清理算法。当清理运行时，它们的删除遵循已配置的保留数量策略。没有清理算法的现有快照不会被更改，手动创建的快照保持其现有策略。

快照比较会单独报告不支持的路径记录。有效文件仍可供审查；具有无效编码、控制字符或不受支持组件的路径不提供差异或恢复操作。

电源设置在 `[Login]` 下写入 ARGVUS logind 插入项，在需要时创建其目录。重新加载失败会被报告。电池盖行为映射到 `HandleLidSwitch`；旧的 `default` 上下文是一个别名，而 AC 和扩展坞的行为使用它们各自的 logind 键。

Mirrorlist 应用程序只接受注释、空行和 HTTP/HTTPS `Server` 条目。有效负载限制为 64 KiB，并在提权前及特权助手再次检查；像 `SigLevel` 和 `XferCommand` 这样的 pacman 指令会被拒绝。

已卸载软件包的缓存清理不会保留任何缓存版本。仓库操作拒绝被多个仓库段共享的 includes。带有前后空白的主机名和空的生成语言环境选择会被拒绝。设置文件写入会拒绝符号链接目标和现有的临时文件。

包搜索和页面加载会丢弃来自早期页面或查询的结果。当前页面随后会被重新加载，因此旧结果不能将不同的视图标记为最近刷新。 事务输出经过清理和限制。显示保留最多 10,000 行或 4 MiB，并报告被省略的输出。捕获的进程流遵循其配置的限制，实时执行默认限制为 8 MiB；超出部分的输出会在进程完成后被清理并报告。 启动清单读取 Arch 内核 `pkgbase` 以找到内核映像、initramfs 文件和 mkinitcpio 预设，同时单独显示内核版本。读取字面 mkinitcpio 数组时不包括其括号，也不执行配置。

只有在运行时操作成功后，盖子、电源按钮和保持唤醒的电源更改才会保存到规范配置中。取消授权会保留先前保存的值不变。当没有 ARGVUS logind 插入提供值时，会读取主 logind 配置作为后备。

在保留更改失败后，页面会重新读取当前设置，然后再次显示其值。配置选择从第一个条目开始。

ARGVUS 包操作与选择性恢复共享排他锁。在持有该锁期间，安装、移除、重新安装、降级、元数据刷新、缓存清理以及仓库或镜像更改都会被拒绝。该协调涵盖通过 ARGVUS 辅助程序启动的操作；外部 pacman 和 AUR 工具不使用此锁。

当后台操作正在应用更改时，`q` 和 `Ctrl+C` 会保持控制中心打开，并显示等待通知。这同样适用于在执行操作的页面导航离开之后。等待其结果，然后再次请求退出。普通的只读刷新不会阻止退出。

Wi-Fi 密码、手动 DNS 和网络搜索字段支持带括号的粘贴。粘贴的控件和换行符会被省略。不支持仅 Ctrl 或仅 Alt 的字符快捷键，这些快捷键不会插入字母。编辑器接受以 Ctrl+Alt 编码的可打印 AltGr 事件；Ctrl+S 仅在未按下 Alt 时保存。共享文本编辑器保持垂直列的导航，并对宽字符对齐水平滚动。

麦克风和非默认输出的音量和静音更改不再覆盖已保存的默认输出偏好。只有在后端能够将所选节点识别为当前默认输出时，才会保留这些偏好。页面显示由 PipeWire 报告的超过 100% 的放大音量；明确的音量编辑仍然限制在 0–100% 范围内。

硬件概览会将 GPU 型号与其 PCI 地址和设备类别分别识别，并在括号中保留商业名称。其摘要显示会话中查询到的 OpenGL 渲染器以及 Vulkan 探测返回的所有设备名称，包括软件设备。这些全局结果并不表示每个物理 GPU 的能力。

当管理员锁定或移除为自动登录配置的账户时，账户提供者会首先禁用其 greetd 自动登录条目。如果该清理操作失败，则账户操作会被拒绝。如果之后锁定或移除失败，自动登录仍然保持禁用状态。另一个账户的自动登录将被保留；解锁账户不会启用自动登录。现有会话不会被关闭，greetd 也不会重新启动。

## 创建和管理键盘快捷键

**桌面与输入 → 键盘快捷键** 打开一个菜单，其中有 **创建快捷键** 和 **所有快捷键**。现有的 CLI 别名（`keybindings`、`shortcuts`、`keyboard`）可以打开此菜单；添加 `create` 或 `list` 可以直接打开其子项。全局搜索也可以找到这两个子项。

**创建快捷方式** 会要求输入描述、键盘组合和操作类型。选择 **当前快捷方式** 并按 `Enter`，然后按所需的键盘组合。**更改快捷方式** 以相同的方式开始捕捉；两者都不会打开文本编辑器。捕捉的更改只会影响草稿。如果组合键已被使用，冲突会立即显示，即使描述和命令尚未填写。确认 **替换** 会选择该组合并记录你的选择；在点击 **创建**/**保存** 之前，它不会创建快捷方式或禁用其他快捷方式。取消冲突会保留之前的组合。**命令** 会在按下快捷方式时运行；创建快捷方式时不会运行它。**Hyprland 调度程序** 使用受支持的 Lua 调度程序名称，例如 `window.float`，可选参数为 JSON 对象，例如 `{"action":"toggle"}`。子映射、鼠标绑定和高级标志仍在此表单之外。

使用 `Tab` 在表单和 **操作** 之间切换，`←/→` 在 **创建** 和 **取消** 之间移动，`Enter` 运行所选操作。取消或 `Esc` 放弃草稿。创建后，**所有快捷方式** 将打开并选中新项目。自定义条目出现在 **自定义快捷方式** 中；搜索会匹配描述、按键和操作。`Enter` 编辑描述、操作和按键，`Space` 启用/禁用，选择 **删除** 行并按 `Enter` 会打开以取消为焦点的确认。确认后删除记录并返回刷新后的列表；取消则保留记录。

在相同上下文中启用的快捷键不能静默地重复使用同一组合：可配置的冲突需要确认才能替换，受保护的快捷键不能被替换。替换会在一次配置事务中保存新快捷键并禁用冲突。**恢复默认**仅适用于官方条目；**恢复所有快捷键**会保留自定义记录。如果恢复会与活动的自定义快捷键冲突，请先更改或禁用该自定义快捷键。

保存和应用在后台运行。如果保存失败，草稿仍可用。如果在保存后应用到会话失败，页面会显示已保存并保留相同ID以供重试。自定义记录存放在规范配置中的`/hyprland/custom_shortcuts`，并投影到`data/generated/hypr/custom-shortcuts.lua`；请勿编辑生成的文件。

快捷键错误保持在 TUI 内部：弹出窗口会根据换行消息自动调整大小，并保持 **Enter 确定** 可见。技术快捷键诊断信息会发送到本地日志 (`journalctl -t argvus-control-center`)，而不是 stdout/stderr。已保存但无法应用的删除操作会报告该区别；重新加载会话配置以移除之前的活动绑定。

在 **任务栏 → 图标 → 可选模块** 中的 **更新状态** 显示可用更新数量，并默认启用。**检查 AUR** 默认禁用，需要 `paru` 或 `yay`；应用任务栏草案以保存任一设置。检查操作在启动时及每小时运行一次；单击指示器会打开官方软件包更新页面。

## 全局窗口模式

打开 **控制中心 → 桌面与输入 → Hyprland → 窗口 → 模式** 并选择 **平铺窗口（默认）** 或 **浮动窗口**。同样的选择器也可以通过任务栏工具组中的窗口模式图标访问。

该偏好设置适用于每个显示器和工作区，并在注销后保留。浮动模式会转换现有的应用程序窗口和新打开的窗口。平铺模式只会还原该策略已转换的窗口；已经处于浮动的对话框和其他窗口将保持浮动。浮动模式下显式固定的窗口也会保持浮动，以保留其固定状态。平铺布局会重新计算；其之前的精确分割结构不会被恢复。

`SUPER + SHIFT + Space` 在平铺模式下保持其正常的每窗口行为。在浮动模式下，它不会将窗口切换回平铺模式。面板、任务栏和通知是层壳表面，不受影响。全屏和最大化继续使用 Hyprland 的正常行为。

规范首选项是在 $XDG_CONFIG_HOME/argvus/config/hyprland.json 中的 `/hyprland/window_mode`。其生成的投影为  `$XDG_CONFIG_HOME/argvus/config/hyprland.json` `data/generated/hypr/window-mode.lua`；请勿编辑。每窗口恢复注册表位于 `$XDG_RUNTIME_DIR/argvus` 下，作用范围为合成器实例，并且在配置重新加载后仍然保持。它不会在新会话中重复使用。

如果应用程序处于挂起状态或失败，界面会将其与已保存的首选项区分开。再次选择该选项以重试。没有合成器时，首选项会保存以供下次登录使用。

## 窗口按钮和应用程序栏

浮动模式在普通应用程序窗口上添加了一个 ARGVUS 标题栏，带有 **最小化**、**最大化 / 还原** 和 **关闭** 按钮。双击标题栏可以切换最大化。附加的装饰在平铺和全屏模式下会隐藏。自绘控件的应用程序可能会同时显示两条标题栏；统一的 ARGVUS 控件是故意设计的。

每个显示器上都会出现第二条 Waybar，在主任务栏的对边。它只列出该显示器当前工作区的窗口，包括最小化的窗口。隐藏的组标签不会产生额外条目。最小化的条目保留原有显示器/工作区的关联。点击非活动窗口可激活它，点击活动窗口可最小化它，点击最小化窗口可还原它；其上下文菜单提供还原、最小化、最大化/还原和关闭选项。未知的应用程序图标会回退显示为窗口符号。

`SUPER + Alt + Up` 将主栏放在顶部，窗口栏放在底部。`SUPER + Alt + Down` 则相反。重复一个方向将保持位置不变。平铺模式只有主栏。返回到平铺模式会在移除窗口栏之前恢复所有最小化的窗口，然后保留原来的平铺/浮动策略。

最小化使用保留的 `special:argvus-minimized` 工作区。不要手动使用该工作区。`argvus windows service` 进程在特定于合成器实例的运行时注册表中，在 `$XDG_RUNTIME_DIR/argvus` 下记录身份、原始工作区/显示器、几何形状、全屏/最大化和固定状态。记录在服务重启或配置重新加载后仍然存在，但不会跨合成器会话。关闭窗口会删除其记录。如果显示器消失，恢复将使用可用的输出。缺失或恢复条失败会阻止新的最小化；恢复失败会保留记录和恢复条。

会话拥有 `argvus-windows.service` 和 `argvus-window-bar.service`。后者保持其 Waybar 子项在 Tile 中处于休眠状态。hyprbars 插件由 `argvus-hyprland` 打包，为 x86_64 上的 Hyprland 0.57.0 ABI 构建；它未在用户的主目录中编译。更新合成器 ABI 后重新构建该插件。
命令：`argvus windows list --json`、`watch --json`、`position top|bottom`、`restore-all` 和 `minimize|restore|activate|maximize|close ADDRESS`。窗口地址来自列表。`position top --persist` 在不重启主栏的情况下存储/应用偏好设置。配置和运行时的错误细节会写入日志；可见的操作失败也会显示翻译后的通知。

## 窗口子菜单和关闭应用程序

**桌面与输入 → Hyprland → 窗口** 分组 **规则**、**空间** 和 **模式**。
规则用于编辑每个应用的放置位置；空间用于编辑内部和外部间距；模式包含即时平铺/浮动选择器，与规则表单分开。搜索打开相同的页面，返回则回到 Hyprland 之前的窗口。

直接路线是 `argvus control-center hyprland windows`，可选择随后使用 `rules`、`spaces` 或 `mode`。现有的 `window-rules` 和 `appearance window-spaces` 路线仍然是别名，并显示新的面包屑。

`SUPER + Q` 会立即关闭专用控制中心窗口，而无需 Kitty 的操作系统窗口确认。以这种方式关闭窗口时，未应用的草稿将被丢弃。该覆盖仅适用于 `argvus-control-center` 窗口类；常规终端和其他 TUI 保持其关闭确认策略。

`SUPER + Alt + Space` 切换全局平铺/浮动模式，使用与任务栏和控制中心相同的偏好设置。等效命令是 `argvus config window-mode toggle`。并发调用会序列化；即使应用程序待处理，切换也会使用已保存的偏好设置。快捷键可以在键盘快捷方式中更改或禁用；`SUPER + Shift + Space` 保持其单窗口操作。

## 从 Git 安装主题

通过 HTTPS 或 SSH 安装基于 skeleton 的仓库，使用已有 Git 凭据。主题按用户安装，不会自动应用。`--ref` 选择分支或标签；`--replace` 替换已有自定义主题。已安装的官方 ID 受到保护。

```sh
argvus theme install https://github.com/USER/argvus-theme-NAME.git
argvus theme install https://gitlab.com/USER/argvus-theme-NAME.git --ref v1.0
argvus theme install git@host:USER/argvus-theme-NAME.git --replace
argvus theme apply NAME
argvus theme uninstall NAME
```

主题显示在 **Custom themes** 中；按 `r` 刷新页面。通过 CLI 或 Control Center 删除当前主题前，先应用其他主题。替换后需重新应用。

---
title: ターミナル
description: ARGVUS端末と端末アプリケーションプロファイルを開きます。
---
設定されたターミナルを開くには:

```sh
argvus --terminal
```
`argvus terminal`（`argvus`のサブコマンド）は、端末の統合とKittyの設定を提供します。`argvus-app-profiles`は、SuperfileやYaziなどの端末アプリケーション向けのプロファイルを提供しますが、`argvus`ディスパッチャーは提供しません。

`argvus-config`はテーマを`data/generated/terminal/`に投影し、`argvus --yazi`および`argvus --spf`は、ホームディレクトリにコピーされたものではなく、投影された`data/generated/yazi/`および`data/generated/superfile/`のツリーから設定を読み取ります。アプリケーション自身の設定ディレクトリでの完全なネイティブオーバーライドは依然として優先されるため、投影されたツリーを自分自身の設定で置き換えることができます。

テーマの変更は`$XDG_CACHE_HOME/argvus/argvus-terminal`下のKittyの派生ファイルを再生成します。ジェネレーターは更新をシリアル化し、各ファイルを原子操作で置き換えます。もし端末がまだ開かない場合は、アクティブなテーマを確認し、キャッシュを再生成してください:

```sh
argvus config get /appearance/theme --raw
argvus terminal --apply
argvus terminal --print-config
```
ターミナルはまず`$XDG_CONFIG_HOME/argvus/config.json`から管理されたテーマとアクセントを読み取ります。古いインストール用には、従来の`.active-theme`および`.accent-color`ファイルがフォールバックとして残ります。

## 透過およびぼかし

**コントロールセンター → 外観 → ターミナル**で、**透過**と**ぼかし**を`0%`から`100%`とは独立して設定します。変更は**適用**ボタンで確定され、`$XDG_CACHE_HOME/argvus/argvus-terminal`の下でKittyプロファイルが再生成されます。既存のKittyウィンドウはリロードを通じて更新された設定を受け取ります。

`0%`の透過では背景が不透明のままで、`100%`では完全に透明になります。ぼかしはKittyがサポートする背景ぼかしの半径を使用し、ウィンドウが透明な場合にのみ視覚効果があります。

## 長時間実行されるコマンドの通知

30秒以上実行されるコマンドは、ターミナルウィンドウがフォーカスされていない場合に終了時に通知を送信します。通知はすでに有効になっているシェル統合と共にKittyの`notify_on_cmd_finish`を使用するため、`~/.zshrc`および`~/.bashrc`を変更する必要はありません。30秒の閾値はKittyの設定で固定されています。

## TUIアプリモード

ARGVUSコントロールセンターおよびタスクバーTUIポップアップは、専用のKittyアプリプロファイルとともに`argvus tui-terminal`を使用します。これはアクティブなARGVUSテーマとフォントを継承し、安定したウィンドウクラスを割り当て、シェルを開かずに子プロセスと共に終了します。コントロールセンターはタブを非表示にし、透明度とぼかしの値は独立しています。タスクバーモニターおよび温度ポップアップは、ローカライズされた`Press q to close`タイトル用に下部タブバーを使用します。ランチャーは`--title TITLE`を受け入れて、固定されたKittyウィンドウおよびタブタイトルを設定します。通常のターミナルはタブと設定を維持します。

ランチャー環境に LANG が存在しない場合、`argvus terminal` は Kitty がキーボード入力の組み合わせを初期化する前に、`$XDG_CONFIG_HOME/locale.conf` から個人用ロケール（デフォルトは英語）を提供します。既存のロケール環境の上書きは保持されます。更新後は Kitty を再起動してください：既存のシェル内で LANG をエクスポートしても、Kitty の組み合わせテーブルは再初期化されません。

セッション初期化から継承された空の LC_ALL および LC_CTYPE は、Kitty の子プロセス環境から削除されます。それ以外の場合、Kitty は空のロケールを明示的と見なし、有効な LANG があっても組み合わせテーブルを読み込むことができません。非空の上書きは保持されます。これは新しいプロファイルにも適用され、更新後はランチャーを再度開いて Kitty を再起動する必要があります。

専用のコントロールセンターウィンドウ（`argvus-control-center`）は、起動ごとのKittyオーバーライド`confirm_os_window_close=0`を受け取るため、コンポジターの閉じる操作は確認を求めません。このオーバーライドは共有ターミナルプロファイルには書き込まれず、他のTUIや通常のターミナルは既存のポリシーを維持します。

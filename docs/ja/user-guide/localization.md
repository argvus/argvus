`argvus-i18n` 共有カタログ、 `argvus i18n validate` コマンドとコマンド QML モジュール `org.argvus.i18n`お問い合わせ ARGVUS 船 18 インターフェイス言語: アラビア語、ベンガル語、ドイツ語、英語、スペイン語、フランス語、ヒンディー語、インドネシア語、イタリア語、日本語、韓国語、ブラジルポルトガル語、ヨーロッパポルトガル語、ロシア語、トルコ語、ウルドゥー語、ベトナム語、簡体中国語。

ネイティブ ARGVUS アプリケーションとシェルコンポーネントは、共有カタログを消費します。 翻訳された文字列は、複数のリポジトリで使用できます。 アラビア語とUrduは、サポートされた右から左のレイアウトを使用します GTK, Quickshell そしてターミナル インターフェイス。

** コントロール センター → 環境設定 → 言語 & 地域 → 言語** で選択 ARGVUS インターフェイス言語。 この書き込み `ARGVUS_LANGUAGE` お問い合わせ `$XDG_CONFIG_HOME/locale.conf` (通常) `~/.config/locale.conf`)。 例えば、 `ARGVUS_LANGUAGE=pt-PT` ヨーロッパのポルトガル語を選択します。 ブラジルポルトガル語 (ポルトガル語)`pt-BR`) は別のオプションです。 言語カタログがインストールされています ARGVUSですから、それに依存しません `locale-gen`お問い合わせ

コントロールパネルは、インターフェイス言語の変更後に自動的に再起動します。 セッションコンポーネントに適用する新しいセッションを開始します。 別の **Regional Locale** 設定 書き込み `LANG` 地域フォーマットおよびサードパーティのアプリケーションを制御します。 生成されたシステムロケールが必要です。 `/etc/locale.gen` ログイン `locale-gen` 管理者権限で。 キーボードレイアウト、バリアント、コンソールキーマップは別々の設定です。

## 環境変数が変更を上書きするとき

ARGVUS アプリケーション読み取り `ARGVUS_LANGUAGE` ユーザーから `locale.conf`. 不在の場合、地域を解決する `LANG` インストールしたカタログに値します。 継承された locale 変数は explicit を上書きしません `ARGVUS_LANGUAGE` 好み。 サードパーティのアプリケーションは、引き続きシステム地域のロケールを使用する。

効果的な値の特定:

```sh
systemctl --user show-environment | rg '^(LANG|LC_|ARGVUS)='
locale
printf '%s\n' "$LANG"
localectl status
```

チェックイン `~/.config/locale.conf` 有効なものを含む `ARGVUS_LANGUAGE=<catalog>` 値。 地域フォーマットやサードパーティのアプリケーション言語を変更するには、**Regional Locale** を使用し、生成されたロケールを選択します。 コントロールパネルは、設定の変更後に再起動されます。ログアウトし、他のセッションコンポーネントが古いインターフェイス言語をまだ表示している場合。 [環境変数]を参照してください。(/docs/reference/environment-variables/) 技術的な契約および優先事項のため。

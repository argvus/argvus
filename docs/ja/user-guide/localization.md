`argvus-i18n` は共有カタログを提供し、`argvus i18n validate` コマンドおよび QML モジュール `org.argvus.i18n` も提供します。ARGVUS は現在、英語およびポルトガル語のカタログを出荷しています。

ネイティブアプリケーションおよびシェルコンポーネントは共有カタログを利用します。そのため、翻訳された文字列は複数のリポジトリで使用される可能性があります。

**コントロールセンター → ロケールと地域** を使用して、言語、地域のロケール、生成されたシステムロケール、タイムゾーン、日付/時刻、キーボードを設定します。現在の ARGVUS カタログは英語およびポルトガル語を提供します。これは、オペレーティングシステムが生成したシステムロケールのリストとは別です。

表示言語を変更すると、ARGVUS の設定が保存され、`argvus-control-panel.service` が自動的に再起動されるため、コントロールパネルに変更が即座に反映されます。他のアプリケーションやシェル環境では、セッションのリロードまたは新しいセッションが必要になる場合があります。`/etc/locale.gen` エントリの生成や変更には認可が必要で、`locale-gen` が実行されます。生成されていないロケールを選択すると拒否されます。キーボードレイアウト、バリアントおよびコンソールキーマップは別の設定であり、インターフェース言語と混同しないでください。

## 環境変数が変更を上書きする場合

ARGVUS アプリケーションは、まず永続的な ARGVUS 言語ファイルから言語を検出し、その後 `LC_ALL`、`LC_MESSAGES`、`LANG` を確認します。そのため、ローカル環境変数によってコントロールセンターが言語変更を無視しているように見える場合があります。特にユーザーサービスやグラフィカルセッションが古い環境を保持している場合に顕著です。

有効な値を確認するには:

```sh
systemctl --user show-environment | rg '^(LANG|LC_|ARGVUS)='
locale
echo $LANG
localectl status
```
もし`~/.config/locale.conf`が存在し、`LANG`、`LC_ALL`、または`LC_MESSAGES`を定義している場合、それらの値を再導入しないように一時的に名前を変更してください。削除する代わりにバックアップを保持します:

```sh
mv ~/.config/locale.conf ~/.config/locale.conf.backup
```
**コントロールセンター → ロケールと地域** で再度言語を適用します。コントロールパネルは自動的に再起動します。他のコンポーネントがまだ以前の言語を表示する場合は、グラフィカルセッションと `systemd --user` が新しい環境を受け取るように、ログアウトして再ログインしてください。その後、診断コマンドを再度実行します。技術契約および優先順位については、[環境変数](/docs/reference/environment-variables/) を参照してください。

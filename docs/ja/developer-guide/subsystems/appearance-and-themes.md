`argvus-appearance` はテーマ、アクセント、壁紙、フォントの *状態* を所有しています。これは `argvus-wallpapers`、`argvus-fonts`、`argvus-icons` からアセットを消費しますが、テーマ出力は生成しません。Hyprland、GTK、Qt、Waybar、Quickshell、Dunst、Hyprlock、Yazi、Superfile、端末、ネイティブアプリケーション用の ARGVUS 所有の全ての消費者ファイルは `argvus-config` によって書かれた投影であり、Rofi を除きます：Rofi のファイルは `argvus-launcher` が所有し、`argvus-appearance` が `data/rofi/` の下でユーザーコピーを編集します。

コントロールセンターとコントロールパネルはユーザーインターフェイスであり、どちらもテーマ状態の唯一のソースではありません。

`argvus theme-switch`（`argvus theme apply`も同様）は、選択したテーマをレンダリングし、エクスポートされた外観プロファイル（またはパッケージ化されたデフォルト）を適用し、テーマのビルドおよびプロジェクトファイルを書き込み、その結果をセッションコントローラーを通じて適用します。公式テーマは、独立したビジュアルオーバーライドをプロファイルまたはデフォルトに置き換えます。カスタムユーザーテーマを適用すると、さらに`argvus-taskbar.service`、`argvus-hyprland.service`、`argvus-wallpaper.service`、`argvus-control-panel.service`が再起動されます。Sticky/Spacedモードの変更は常に、そのモードの間隔、ボーダー、およびタスクバーのジオメトリを再確認し、その後`argvus-taskbar.service`、`argvus-widget-telemetry.service`、`argvus-hyprland.service`を再起動します。これはモードが変更されていない場合でも行われます。モードのジオメトリはプロファイルのジオメトリより優先されます。ユーザーは、ビジュアル編集内容をカスタムテーマとしてエクスポートすることで保存できます。セッション対象自体は再起動されません。

`argvus-config`（`argvus theme-switch`）のテーマトランザクションは、`config.json`やその公開されたプロジェクションを自分で読めないすべてのコンシューマーを所有します — ネイティブQt6ctファイル、GTK `settings.ini`および`gsettings`のヒント、FootとKitty、グリーターテーマの状態、タスクバーのカレンダーキャッシュ、システムモニター、壁紙のランタイムおよびHyprtoolkitです。`argvus sessionctl reload`から実行されるので、テーマの切り替え、キーバインドの再読み込み、セッションの開始はすべて同じランタイム状態に達します。アダプターはコミットされた世代のみを読み取ります：それらは自分自身のコンシューマーファイルとキャッシュを書き込み、標準ドキュメントや`data/generated/`には決して書き込みません。ロック画面のぼかし壁紙は無効化されるだけで、再書き込みは行われません。なぜなら、すでにコミットされたプロジェクションの一部であるからです。`argvus config accent`は標準アクセントを記録し、再びビルドをレンダリングし、登録されたすべてのコンシューマーをその場で再読み込みするので、アクセントの変更とテーマの変更が意見の不一致を起こすことはありません。 バリアント。レガシーのタスクバー ユーティリティーグループマーカーはトランザクション内でインポートされ、`argvus config taskbar status` は世代を書き込むことなく有効値を報告します。

Hyprlandの`SUPER + Shift + T`バインディングは`theme-menu.sh`を開き、スクリプトを呼び出す前にテーマを選択します。スイッチが実行されている間、そのpidおよびプロセス開始時間とともに`theme-switch.active`をキャッシュディレクトリに保持します。スイッチが開始するプロジェクションはそのマーカーを読み取り、テーマをスイッチに残すため、ロックは二度取得されることはありません。ロックおよびプロジェクションの待機時間はそれぞれ60秒に制限されており、消費者のリロードコマンドは合わせて5秒です。直接の`argvus sessionctl reload`（`SUPER + Shift + R`を含む）は、再度プロジェクションせずにすでにコミットされた世代を適用し、また正規値が変更されていない場合には古いランタイムの消費者を修復します。`argvus terminal --apply`は、共有ロックとアトミックな置換を使用して、ユーザーのキャッシュ下に派生したKittyプロファイルを生成します。

## テーマビルド（`argvus-theme-core`）

`argvus-theme-core` はデータからテーマをレンダリングし、上記のトランザクションはアクティブなテーマのビルドを通じてそれらを適用します:

- **アクティブテーマのビルド。** `argvus theme-switch` はアクティブなテーマ（レイアウトやハイライトカラーを含む）をレンダリングし、`generated/theme/current` をそのビルドに向けます。`argvus config accent` は新しいカラーで再度レンダリングし、セッション開始時にもコピーされたファイルを書き換えます。ビルドは必須です: すべてのテーマ付きファイルはそこから来ます。コントロールセンターでエクスポートまたはインポートされたユーザーテーマも同様にレンダリングされます。
- **消費者はビルドを読み込みます。** 各消費者は自分のファイルを `current` から取得します：Waybar タスクバーとテレメトリ `@import` ビルドのスタイルシート；rofi の `theme.rasi` はビルドパレットをインポートします；qt6ct の `color_scheme_path` はそれを指します；Hyprtoolkit、アプリケーションスタイル、Yazi、Superfile、カレンダーキャッシュ、リムーバブルデバイスのスタイルシートはそこからコピーされます；`hyprland.lua`、コントロールパネル `Theme.qml`、ロック画面、および Dunst がそれを読み込みます；kitty はそれを含み、`argvus system-monitor` はそこから btop のテーマをビルドします；TUI パレットはユーザー自身のアクティブテーマにそれを使用します。テーマのビルドを持たないリーダーは、マニフェストからメモリ上にレンダリングします：グリーター（公式テーマのみ、ユーザーのホームを読むことができないため）、`argvus terminal` および `argvus system-monitor` は別のテーマ用、セッションは最初の切り替え前に。ビルドがない場合、`hyprland.lua` は ARGVUS Dark の色を使用し、コントロールパネルはその組み込みデフォルトを使用します。テーマごとの 古いスイッチ（`data/<app>/themes/`）のコピーは、一度`data/backups/theme-copies-<seconds>/`（`theme_migration`）に移動されます。
- **リロード。** 各レジストリエントリは、実行中のコンシューマーがどのようにリロードするか（`rewrite`、`signal`、または`command`；コマンドは`${ARGVUS_DATA_HOME}`および`${ARGVUS_CONFIG_HOME}`を使用することがあります）と、いつリロードするか（`reload_stage`）を宣言します。バーはスタイルシートの最初の行（`/* argvus theme build: <build> */`）を書き換え、それを`reload_style_on_change`がバーを再作成せずにスタイルリロードに変換します；コントロールパネルは`qs -c argvus-control-panel ipc call theme reload`で呼び出されます；Hyprlandはアクティブな`theme.lua`の色を評価します（`argvus config theme-runtime hyprland`、アクティブな境界線にユーザーのアクセントを適用）；Dunstは`argvus notifications theme reload`を通じてリロードし、Do Not Disturbが有効な間はリロードを保留し、DNDがオフになったときに適用します；btopはSIGUSR2を、kittyはSIGUSR1を受け取ります。`argvus config theme-runtime consumers`は、手動での各リロードを実行します。コントロールセンターは、ビルド時またはアクティブな場合にパレットを再読み込みします。 テーマの変更

- **テーママニフェスト。** テーマは`themes/<id>/theme.toml`で、`schema = 2`を持つ: `id`、`name`、`category`（`dark`または`light`）、オプションで`wallpaper`および`preview`（テーマディレクトリに対して相対的または絶対パス）、`[name_i18n]`、`[palette]`、オプションで`[ansi]`（`color0`から`color15`）、オプションで`[gtk] scheme`およびオプションで`[overrides]`を持つことができます。公式テーマは`/usr/share/argvus/themes/`の下にあり、ユーザーテーマは`$XDG_DATA_HOME/argvus/themes/`の下にあります。同じIDのユーザーテーマよりも公式テーマが優先され、ディレクトリ名はIDと同じでなければなりません。`argvus_theme_core::package`はコントロールセンターのユーザーテーマを作成・チェックします: `derive_manifest`はアクティブなテーマからエクスポートされたテーマのマニフェストを作成します（新しい`id`、`name`、`[name_i18n]`、実際のアクセントとしての`palette.accent`、その横の壁紙）、`check_theme_dir`はそれをロードして両方のレイアウトで全てのコンシューマーをレンダリングし、`install_user_theme`はチェック済みディレクトリを一時的にインストールします。 ディレクトリと名前の変更を行い、成功するまで置き換えたテーマをバックアップとして保持します。コントロールセンターは公式テーマのIDを持つアーカイブを拒否し、以前のバージョンの`profile.tar.gz`プロファイルを一度テーマに変換して`data/backups/theme-profiles-<seconds>/`に移動します。
- **パレット。** `bg`、`fg`、`accent`が必要です; 他の小文字の名前を追加することもできます。エントリは色（`#RGB`、`#RRGGBB`、`#RRGGBBAA`）か、他のエントリに基づいた式（`"@accent | alpha(0.13)"`など）です。ユーザーが選択したハイライトカラーは`accent`を置き換え、そのためそこから派生するエントリが続きます。サイクルや未知の名前はエラーです。
- **テンプレート。** `{{ expression }}`が置き換えられ、`\{{`が文字通り`{{`を書くテキストファイル。式は`palette.<name>`（または`@<name>`）、`ansi.colorN`、`layout.<name>`と`theme.id`、`theme.name`、`theme.category`、`theme.variant`、`theme.gtk_scheme`、`theme.wallpaper`を読み、続いてフィルターが続く：`hex`、`hexa`、`argb`（`#AARRGGBB`）、`bare`、`rgb`、`rgba`、`rgba_percent`、`rgb_hex`、`hypr`（`rgba(rrggbbaa)`）、`argb_int`（`0xAARRGGBB`）、`alpha(x)`、`mix(colour, x)`、`lighten(x)`、`darken(x)`、`contrast`、`upper`および`lower`。
- **コンシューマー登録。** 各コンポーネントは、`/usr/share/argvus/theme/consumers.d/<id>.toml` にテーマファイルを登録します：`template`（`/usr/share/argvus` に対する相対パス）、`output`（ビルドに対する相対パス）、および `[reload]` に `kind` `none`、`rewrite`（`path`）、`signal`（`process`、`signal`）または `command`（`argv`）。`reload_stage = "build"` はビルドがアクティブになるとすぐにコンシューマーをリロードします。デフォルトの `files` は、スイッチが読み取るファイルを書き込むまで待機します。テーマは `[overrides]` を通じて1つのテンプレートを置き換えることができます。`[palette]` は、テンプレートが読むトークンにデフォルトを提供し、パレット式（`btop_cpu_mid = "@fg | mix(@bg, 0.3)"`）として扱います。トークンを定義するテーマが優先され、2つのコンシューマーが同じトークンにデフォルトを設定する場合、同じ式にのみ設定できます。これらのデフォルトにより、テーマは `bg`、`fg`、および `accent` だけで済みます。
- **レイアウト。** `/usr/share/argvus/theme/layouts/{sticky,spaced}.toml`はジオメトリ値テンプレートを`layout.<name>`として保持するため、テーマはもはや`-spaced`のコピーを必要としません。  
- **ビルド。** ビルドはメモリ上でレンダリングされ、`~/.config/argvus/data/generated/theme/builds/<id>-<variant>-<hash>/`に一時ディレクトリを介して書き込まれ、名前変更され、その`build.toml`（テーマ、バリアント、カテゴリ、GTKスキーム、実際のアクセント、背景色、壁紙、コンシューマ）によって記述されます。同じ内容のビルドは再利用されます。アクティブなビルドはbuilds/の隣にある`current`シンボリックリンクのターゲットであり、 `builds/` `rename(2)`に置き換えられます。古いビルドはアクティブなものと最新のものを除いて削除されます。
- **公式データ。** すべての公式テーマパッケージ、およびARGVUS Dark and Light用の`argvus-appearance`は、`/usr/share/argvus/themes/<id>/theme.toml`（必要に応じて`overrides/`も含む）とその壁紙のみを含んで出荷されます。旧形式のアプリケーションごとのコピーはなくなりました。各コンポーネントは`/usr/share/argvus/<component>/theme-template/`の下にテンプレートを、`/usr/share/argvus/theme/consumers.d/`の各ファイルごとに1つのレジストリエントリを（19の消費者用：コントロールパネル、タスクバーとそのメニューアイコン、テレメトリー、TUI、カレンダー、ランチャー、通知、Hyprtoolkit、アプリケーションスタイル、Hyprland、Qt6ct、ロック画面、ターミナル、システムモニター、Superfile、Yaziフレーバーとシンタックステーマ、リムーバブルデバイス）出荷します。`argvus-appearance`はStickyとSpacedレイアウトを出荷します。パレットとテンプレートは、古いテーマごとのファイルから抽出され、出力が同一であることを確認しました。マニフェストはレジストリのデフォルトと異なるエントリのみを保持し、ファイルを持つテーマは その構造自体がオーバーライドとして保持されます。`argvus-appearance/tools/test-theme-switch.py` はすべての公式テーマと、必要な色だけを使ったテーマを両方のレイアウトでレンダリングします。
- **テンプレートセクション。** `{{#if expression}}…{{/if}}` は値がゼロ以外の数字、空でないテキスト、または色の場合にのみテキストを保持します。カレンダーとTUIのスタイルシートは、Spaced にのみ存在するルールにこれを使用します。`contrast` フィルターは、色の上のテキストに黒または白を与え、`rgba_percent` は `rgba(r, g, b, NN%)` を書き、`rgb_hex` は `rgb(rrggbb)` を書きます。
- **コマンド。** `argvus theme list`、`argvus theme check DIRECTORY`（両方のレイアウトで登録されたすべてのコンシューマをレンダリングし、そのテンプレートと行ごとにすべてのエラーを報告）および `argvus theme render ID`（ビルド、または `--output` の下のファイルを書き込むが、それを有効化しない）。

## Wobble統合の決定

WobbleはHyprland → Animations → Windowsに属しており、アニメーションのドラフトを共有します。`effects.wobble_*`は権威的であり、`hypr/state.lua`と`decoration.wobble`はその投影および消費者です。結合されたアニメーション設定コマンドは1つのアトミックパッチを保存し、1回のリロードを要求します。Hyprland 0.57.0が最小の依存関係です（オプションA）；パッケージ対応のインストールではランタイムバージョンの検出は不要です。Wobbleは、有力ハードウェアでのレンダリングコストが測定されていないため、無効の状態で開始します。ARGVUSメッシュのデフォルトは8です。バージョン0.57.0のソースは強度を2に制限しているため、スキーマ、CLI、UIおよびLuaはその制限を使用します。

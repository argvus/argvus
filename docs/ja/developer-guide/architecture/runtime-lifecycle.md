`argvus-session` は環境をインポートし、`argvus start` を通じて Hyprland を起動し、コンポジタが準備完了後に `argvus-session.target` を起動します。ターゲットはシェル、通知、壁紙、アイドル、およびクリップボードサービスを取り込みます。`argvus sessionctl` は開始、停止、再読み込み、再起動、ステータス、およびログを調整します。

セッションは Hyprland の終了時にターゲットを停止します。個々のプロジェクトは、自身のバイナリと設定に引き続き責任を持ちます。

## 起動

グラフィカルなエントリーポイントは `/usr/share/wayland-sessions/argvus.desktop` で、これは `argvus session` を呼び出します。セッションは ARGVUS と XDG の設定環境をインポートし、それを `systemd --user` および D-Bus アクティベーションと同期し、コンポジタの起動を `argvus start` に委任します。

`argvus start`はHyprlandの設定を検証し、標準で生成されたファイルが見つかった場合やユーザー設定が無効な場合にパッケージ化されたフォールバックを適用し、仮想化の互換性を検出し、Hyprlandを起動します。コンポジタの準備ブリッジはその後`argvus sessionctl ready`を呼び出し、現在のWaylandおよびHyprland環境でARGVUSターゲットを開始します。

このターゲットは、長時間実行されるコンポーネントを開始する前にワンショット準備ユニットを使用します。準備では、生成された設定、テーマおよびアクセント状態、モニター状態、アプリケーション統合、およびセッション環境を適用します。永続的なサービスは臨時のバックグラウンドプロセスではなく、`systemd --user`によって所有されます。

`argvus start` は Hyprland を起動する直前に `argvus-config.service`（`--no-block`）をキューに入れます：プロジェクションにはコンポジタが不要なため、コンポジタの起動と重なります。その後 `argvus sessionctl ready` がターゲットを起動し、ターゲットはそのユニットがアクティブであることを確認するか、そのジョブを待機するため、標準の構成は準備が実行される前にまだプロジェクトされています。ターゲットが起動すると、`sessionctl ready` は壁紙（背景レイヤーのサーフェス）とタスクバーがマッピングされるまで最大 1.5 秒待ってからロードオーバーレイを削除します。これは、単純なサービスは描画される前に起動済みと見なされるためです。ユニットが実行されていないサーフェスは待機されず、その待機は `session.desktop-surfaces` としてログに記録され、各サーフェスにかかった時間は `session.wallpaper-surface` と `session.taskbar-surface` として記録されます。致命的なプロジェクションまたはターゲット起動の失敗はログに記録され、独立したロードオーバーレイが停止し、無限に見えるスピナーを防ぎます。オプション ビジュアル消費者は、セッションターゲットを置き換えることなく、フォールバックを解決するか、劣化した失敗を報告する必要があります。

### ログインコスト

設定変更なしでのログインは、高コストな作業を繰り返しません：

- プロジェクションは、外観やエフェクトのセクションが変更された場合、またはそれらの実際の出力物（マテリアライズされたユーザーコピーと`data/state/effects/<theme>.conf`）が存在しない場合にのみ、テーマスイッチとエフェクトアダプターを実行します。
- 準備は、`$XDG_CACHE_HOME/argvus/session/theme-startup.stamp`のスタンプがパッケージ化されたテーマファイルおよびアクセントマーカーと一致しなくなった場合にのみ、スタートアップテーマとその上のアクセントを適用します。スタンプはファイル内容のフィンガープリントを行うため、同一ファイルを再インストールしても無効にはなりません。テーマ入力が変更された場合や新しいアクセントが追加された場合は、一度だけ無効になります。古いタイムスタンプベースのスタンプを移行する場合も、一度だけ再構築されます。テーマが再適用されると、準備は以前のファイルで起動したHyprlandも再読み込みします。
- GTKの設定（`gsettings`）は、起動テーマが再適用されたときにのみ書き込まれます。ログイン間ではdconfがそれらを保持するため、安定したログインでは再度実行されません。
- `argvus-dunst.service`は`Type=dbus`です：Dunstが`org.freedesktop.Notifications`を所有した時点で一度起動と見なされるため、セッションターゲットはポーズ状態の復元を待ちません。
- 準備では`spaces-switch.sh`と`borders-switch.sh`（`--apply-static`）を並行して実行します：それぞれ異なるファイルを書き込みます（バーのJSONCマージンと実際のジオメトリ、バーのCSSおよびRofiテーマ）。
- プロジェクションは、内容が変更された場合にのみ生成されたファイルを書き換えます。変更されていないファイルはそのまま残るため、安定したログインでは再度fsyncされません。
- 準備のディスプレイステップ（`argvus config display session-prepare`）は、DPMSおよび無効化された出力にのみ適用されます：再度プロジェクションを行ったり、コンポジタをリロードしたりはしません。
- `argvus-session-reload.service` は `argvus sessionctl reload-desktop --login` を実行し、これはプロジェクションマニフェストに `hyprland` が影響を受けるコンシューマとしてリストされている場合にのみ Hyprland をリロードします。デスクトップコンポーネントはそれを待機しません。

セッションスピナー（Wayland モードのハンドオフヘルパー）は、`argvus sessionctl ready` がターゲットを起動するまでコンポジタのハンドオフからマッピングされるため、1つのスピナーで全体の起動をカバーします。`PartOf=` はありません。新しいログインでターゲットを再生成してもそれを停止させてはいけないためです；`sessionctl` は明示的にそれを停止し、`RuntimeMaxSec=30` は停止が到達しない場合に終了させます。

各準備、リロードおよびプロジェクションアダプターのステップは、その所要時間をセッションログに `<epoch-ms> timing <step> <N>ms` として追記します；[session startup troubleshooting](/docs/user-guide/troubleshooting/session-startup/) を参照してください。

パス解決、セッション準備、およびHyprlandリロード計画はRustが管理します。
`argvus config session-prepare`および`argvus config session-reload-config`が起動およびリロードの手順を実行します。レガシーの`hypr-init.sh`スクリプトは削除されました。

## サービスとシャットダウン

ターゲットは、`argvus-control-panel.service`、`argvus-taskbar.service`、`argvus-widget-telemetry.service`（有効の場合）、`argvus-wallpaper.service`、`argvus-dunst.service`、`argvus-hypridle.service`、クリップボード監視、キーボードレイアウト通知、およびPolicyKit統合を一般的に管理します。セッションロードオーバーレイはターゲットではなく`argvus start`によって起動されます。オプションサービスの障害は、セッション全体を置き換えることにはなりません。

Control Panelやidle managerを含むWaylandクライアント接続を必要とするサービスは、クライアントを起動する前に使用可能なHyprlandランタイムを待ちます。これにより、コンポジタの引き継ぎ中に古いソケットに対してQuickshellやhypridleを起動することを避けられます。Hyprlandが置き換えられた場合、systemdは新しいランタイムが利用可能になった後にコンポーネントを再び起動できます。

テーマの切り替えは、テーマロックの下でコミット、ビルド、プロジェクション、およびコンシューマのリロードを1つのライフサイクル操作として直列化します。`argvus-config.service`をリロードしたりサービスを再起動したりはしません：実行されるプロジェクションはファイルを書き込むだけで、ロックが保持されている間にテーマの切り替えを行い、実行中のコンシューマはその場でリロードします（[Appearance and themes](/docs/developer-guide/subsystems/appearance-and-themes/)参照）。

Hyprland が終了すると、`argvus start` は `argvus-session.target` とそれに関連するサービスを停止します。これにより、タスクバー、シェル、通知、アイドル、クリップボードのプロセスがログアウト後に残るのを防ぎます。

## 再読み込み

```sh
argvus sessionctl reload
```

リロードはグラフィカル環境を再インポートし、その後、`apply-theme`、`accent`、`set`/`patch`のような前のドメインコマンド、またはウィジェット・テレメトリブロックの変更によって変更が既に投影されている場合に、コミットされたジェネレーションを**適用**します。その場合、マニフェストプランにリストされているコンシューマを復元し、再投影は同一のツリーを再構築してプランを破棄することになるため、`argvus config project` を再度呼び出すことはありません。投影、移行、`ensure` は、有効な保留中プランが存在しない場合にのみ、セッション開始時、または `argvus config recover` が以前のドキュメントを復元する必要がある場合に実行されます。プロジェクションと管理されたランタイムの両方が最新である場合にのみ、クリーンな no-op が許可されます。標準状態が変更されていない場合でも、コンポジタソケット、サービス、またはコンシューマが古い場合、リロードは早期に終了するのではなくそれを調整します。通常のファンアウトは Hyprland、タスクバー、ウィジェット・テレメトリ、コントロールパネル、通知、壁紙、アイドルをカバーします。 投影マニフェストによると、変更されていないオプションのコンシューマはそのまま保持されます。`data/generated/` の下のすべてのファイルはこの時点で `argvus-config` によって書き込まれるため、セッション自体がテーマを再レンダリングすることはありません。その後のリロードでは `theme-adapters.sh` が実行され、独自に正規の文書や公開された投影を読み取ることができないコンシューマを調整します。これらのアダプタはコミットされた世代のみを読み取ります：自身のコンシューマファイルとキャッシュを書き込みますが、正規の文書や `data/generated/` は決して書き込みません。そのため、単一のユーザー操作でも、1回の変更、1回の投影、1回の公開、1回のリロードが必要になります。`argvus sessionctl restart <component>` は、単一の所有サービスが明示的に分離された再起動を必要とする場合にのみ使用してください。正確なユニット名については、[services reference](/docs/reference/services/) を確認してください。

射影およびリロード操作は、ユーザーランタイムロックで直列化されます。一時的なタイミングトレースを行うには、リロードを呼び出す前に`ARGVUS_SESSION_PERF=1`を設定し、`~/.local/state/argvus/session.log`を確認してください。トレースは通常のリロード動作を変更することなくステージの境界を記録します。

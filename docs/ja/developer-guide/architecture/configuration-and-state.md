title: 構成と状態
description: 共有状態、オーバーライド、生成されたランタイムファイル。
---
通常のユーザー root は `$XDG_CONFIG_HOME/argvus`（通常は `~/.config/argvus`）です。管理された論理設定は `config.json` に保存されます。テーマ、アクセント、壁紙、間隔、境界の設定はそこに標準的に存在します。ドットファイルは現在の Hyprland Lua およびシェルの利用者が `data/` に移行する間、互換性のための派生プロジェクションとして残ります。

`argvus-config`は`generated/`の下にある唯一の作成者です。ARGVUS所有のすべての消費者ファイルは`config.json`の投影であり、Hyprland、GTK、Qt6ct、Waybar、Quickshell、Dunst、Hyprlock、WaybarのタスクバーおよびウィジェットTelemetryプロファイル、YaziおよびSuperfile構成ツリー、端末およびQtプロファイルツリー、フォント管理ブロックおよびリムーバブルデバイスのスタイルシートを含みます。コンポーネントは、明示的なユーザーオーバーライド、次に生成された出力、次にパッケージのデフォルトの順に解決されます。Rofiは投影ではありません：`argvus-launcher`がそのファイルを所有し、ユーザーコピーは`data/rofi/`の下でライブになります。通常のテーマ/リロード投影は、生成されたファイルやパッケージ化されたファイルをユーザーオーバーライドに昇格させることはありません。ドキュメントとツールは、ユーザーに生成された出力を編集させるのではなく、論理的なソースを特定するべきです。

`argvus-appearance`はテーマとアクセントのオーケストレーションを所有しており、`argvus-config`は標準状態と構造化された投影を所有しています。`argvus theme-switch`（`argvus config theme-apply`トランザクション）および`argvus config accent`は、利用可能な場合に`argvus-config`を通じて検証、ロック、コミットし、その後`config.json`を直接読むことができない互換性のあるコンシューマを調整します。これらのアダプタは、ネイティブのQt6ctファイル、GTKの`settings.ini`および`gsettings`ヒント、ターミナルおよびシステムモニターのアプリケーション、foot、superfile自身の設定ディレクトリ、プリ認証グリーターです。新しいアダプタが必要なヘルパーは、`generated/`の内部ではなく、そこに追加する必要があります。

ランタイムの所有権は意図的に責任ごとに分割されています：Rustはカノニカルストア、スキーマ検証、マイグレーション、パスモデル、ロック、アトミック書き込み、プロジェクションハッシュ、および構造化レンダラーを所有します。Shellは`hyprctl`やアセット所有のテーマスクリプトなど、外部消費者向けの小さな互換エントリポイントまたはアダプターとしてのみ残ります。Pythonはテスト、監査、および開発補助のために予約されており、重要なデスクトップランタイムの一部ではありません。

`argvus config apply`はリビルド境界です（`project`は互換スペルのままです）。カノニカルドキュメントが変更されていない場合でも欠落している出力を再生成し、ステージングでプロジェクターをレンダリングし、すべてのプロジェクションが成功した後にのみ`data/`ツリーをアトミックに入れ替えます。セッションライフサイクルは`argvus sessionctl`が所有し、対象のリロードを計画するためにそのマニフェストを消費します。

呼び出し元がすでに世代を確定している場合 — `apply-theme`、アクセント変更、`set`/`patch`、またはウィジェット・テレメトリブロックの変更 — `reload` は、その世代を再度投影するのではなく適用します。これはマニフェストから計画を読み取り、ターゲットとなるコンシューマを復元し、マニフェストが存在しない場合や保留中の作業がない場合にのみ投影します。その時点での再投影は、同一のツリーを再構築し、変異によって生成された計画を破棄することになります。

マニフェストはまた、運用世代、実効構成ハッシュ、変更されたドメイン、および生成されたファイルリストを記録します。`data/internal/generation.json` は使い捨てのローカル投影マーカーであり、ユーザープリファレンスにはなりません。`argvus config status` はこれらの記録を解決済み構成と比較し、生成されたファイルの欠落や余分なものを報告します。

変異は同じエンジン境界に従います: `UserConfig` は `NextUserConfig` にクローンされ、検証され、`EffectiveConfig` に解決され、投影され、その後にのみ永続化されます。`.config-transaction.json` は運用回復状態です; `argvus config recover` は、`data/` と `config.json` の間で公開中にクラッシュした後、以前の標準的なドキュメントを決定論的に再投影します。リロードはコミット後にのみ要求され、リロードの失敗は一貫した永続化された構成をロールバックしません。

## 解決モデル

```text
config.json logical model
    ↓
ARGVUS native compatibility state and per-app override
    ↓
ARGVUS generated runtime file
    ↓
/usr/share/argvus packaged default
    ↓
upstream default
```
正確な候補はコンポーネントによって異なりますが、原則は一貫しています：ユーザーのオーバーライドが優先され、生成された出力は派生状態であり、パッケージ化されたファイルは読み取り専用の入力のままです。セッションは`ARGVUS_CONFIG_HOME`および`ARGVUS_SYSTEM_CONFIG`をエクスポートするため、ヘルパーやユーザーサービスは同じルートを解決します。

リロード回復は`recover → ensure → migrate → apply → runtime reload`に従い、受信したマニフェストがすでにコミットされた世代を記述している場合、投影ステップはスキップされます。`ensure`はプロファイルが存在しない場合にのみスキーマのデフォルトから`config.json`を具現化し、欠落しているフィールドを、明示的な`false`、`0`、またはカスタム値を置き換えることなく補完します。既存の不正なドキュメントは、黙って置き換えられるのではなく、エラーのままとなります。

永続的な変更は、`ChangedDomains`を通して解決済みの古い構成と新しい構成を比較します。コミット後、`argvus sessionctl`を通して1回のリロード要求が送信されます。リロードの失敗は、コミットされた構成をロールバックせずに報告および記録されます。セッションの起動は、ブートストラップの具現化と投影の前にリカバリを実行するため、コンシューマは放棄されたトランザクションに対して開始されません。

| 状態 | 目的 |
| --- | --- |
| `config.json` | 標準化された管理論理設定; 以下の`generated/`に関するすべての単一の情報源。 |
| `.active-theme`, `.accent-color`, `.accent-custom` | レガシーマイグレーションの入力; ランタイムのソースではなく再生成されません。 |
| `.wallpaper-custom` | `appearance.wallpaper`のレガシーマイグレーション入力; ランタイムのソースではありません。 |
| `.spaces`, `.borders` | レガシーレイアウトマイグレーションの入力; 標準値はconfig.jsonの下の`layout`に格納されています。 |
|  `config.json` `fonts.conf` | 標準フォント選択の互換性投影。 |
| `generated/effects` | 標準エフェクトの互換性投影; 使い捨て。 |
| `$XDG_STATE_HOME/argvus/config-projection.json` | 投影マニフェスト: 変更されたセクション、影響を受ける利用者、および再読み込みが必要かどうか。`reload`によって読み取られる; 真の情報源ではない。 |
| `$XDG_STATE_HOME/argvus/widget-telemetry-blocks` | 旧式テレメトリブロック設定。マイグレーションのフォールバックとしてのみ読み取り; 標準値は`/control_panel/widget_telemetry_blocks`にあり、このファイルはもはや書き込まれない。 |

プロパティは、`config.json`から読み取られ、そこから投影される場合、標準的（canonical）とされる。プロパティは、投影されつつもマイグレーション入力として消費可能な場合、派生（derived）とされる。コンポーネントが実行時にまだ書き込むもの — キャッシュ、`$XDG_CONFIG_HOME/<app>`下のネイティブ設定ファイル、グリーダーステートファイル — はアダプター対象であり、設定として再度読み取ってはならない。

Projectionは、Hyprland、GTK/Qt、Waybar、Quickshell、ターミナル、通知、ロック画面およびネイティブアプリケーション向けに消費者をカバーします。Hyprlandは、選択されたテーマからアクティブおよび非アクティブの境界色を読み取ります。明示的な`appearance.accent_custom=true`のみが、ユーザーアクセントでアクティブ/グループ境界を上書きする場合です。テーマの切り替えは、コンポジターのリロードを通じてこれらの値を再適用するため、前のテーマの色を保持することはできません。ユーザー設定が再作成される場合、エフェクトはデフォルトでアニメーションが有効になります。`generated/`を削除し`argvus config apply`を実行すると、`config.json`からバイト単位で再作成されます。生成されたファイルを直接編集することは耐久性がありません。  
ランタイム診断では、完全な実行タプルを特定する必要があります: バイナリーパス、バージョン/リビジョン、アセットルート、設定ルート、データルート、生成ルート、内部ルート、およびprojectionマニフェスト。`status --verbose`はこのタプルを公開します。
公開された世代／ハッシュと現在解決された設定を比較します。開発およびインストール済みパッケージのテストは別々のモードであり、どちらも無関係な実行可能ファイルや開発者のホームディレクトリに静かにフォールバックすることはできません。`apply` は、レガシーの統合テーマ識別子の調整境界でもあります：`argvus-dark-spaced` のような値は解決前に `theme=argvus-dark` および `variant=spaced` になります。このリリースでは、パッケージ化されたアセットの識別はマニフェストに記録されないため、それを説明する診断ファイルはありません。

---
title: アーキテクチャの概要
description: ARGVUSがどのように統合デスクトップ環境を形成するか。
---
ARGVUSには5つのランタイムレイヤーがあります：

1. `argvus`におけるエントリポイントとディスパッチ;
2. `argvus-session`におけるセッションライフサイクル;
3. `argvus-hyprland`、`argvus-waybar`、`argvus-taskbar`および`argvus-control-panel`におけるコンポジタとシェルサーフェス;
4. コントロールセンター、カレンダー、システムモニターなどのユーザーアプリケーション;
5. ディスプレイ、ネットワーク、電源、外観、アカウント、および通知のプロバイダとアセット。

共有状態がこれらのレイヤーを接続します。`argvus-config`は正規のドキュメントを保持し、`data/generated/`の唯一の書き込み者であるため、テーマやエフェクトの変更は複数のパッケージで使用されるファイルを1つのトランザクションで再生成します。セッションサービスは、各コンポーネントの実装の所有権を取ることなくライフサイクル所有権を提供します。

## 責任範囲

| レイヤー | 主な責任 | 例 |
| --- | --- | --- |
| エントリーポイントとディスパッチ | デスクトップアプリケーションを起動し、ARGVUSプロファイルを解決する。 | `argvus`, `argvus-app-profiles` |
| セッションライフサイクル | 環境を準備し、Hyprlandを起動し、ユーザーサービス環境を同期し、自セッションのシャットダウンを行う。 | `argvus-session`, `argvus sessionctl` |
| コンポジタとシェル | ウィンドウの動作と表示されるデスクトップサーフェスを定義する。 | `argvus-hyprland`, `argvus-waybar`, `argvus-taskbar`, `argvus-control-panel` |
| 設定 | `config.json`、自身のパスモデル、生成されるすべてのコンシューマファイルを管理する。 | `argvus-config` |
| アプリケーション | 設定と集中型デスクトップワークフローを提供する。 | コントロールセンター、カレンダー、ランチャー、システムモニター、リムーバブルデバイス |
| プロバイダーとアセット | ドメイン操作と共有ビジュアルリソースを実装する。 | ディスプレイ、ネットワーク、電源、通知、外観、フォント、壁紙 |

`argvus`パッケージはインストールの対象およびコーディネーターですが、モノリシックなランタイムではありません。特化されたパッケージは、自分のバイナリ、設定、およびサービスの管理権を保持します。セッションマネージャーは、グラフィカルセッションの適切な時点でそれらを起動しますが、その実装を吸収することはありません。

この区別はデバッグ時に重要です。セッションの障害はまず`argvus-session`に属し、タスクバーの障害は`argvus-taskbar`/`argvus-waybar`に属し、生成されたテーマや壁紙の障害は外観およびセッション設定のパスに属します。

---
title: Theme and wallpaper troubleshooting
description: Diagnose theme propagation and generated appearance files.
---

Check the canonical `appearance` section in `$XDG_CONFIG_HOME/argvus/config.json`, then inspect generated files under `$XDG_CONFIG_HOME/argvus/data/generated`. Legacy dot-files are migration inputs only.

`argvus-config` is the only writer below `data/generated/`. To recover a broken
theme or wallpaper, rebuild the whole generation from the canonical document and
apply the result instead of editing generated consumers directly:

```sh
argvus config validate
argvus config apply
argvus sessionctl reload
```

`argvus theme-switch` (which runs `argvus config theme-apply`) and `argvus config accent`
are orchestrators: they validate, lock, show the splash, commit through
`argvus-config` and then reconcile the external consumers that cannot read
`config.json`. They never write `data/generated/`, and the theme transaction does
not write the GTK, storage or `mode.css` files through separate scripts.
Use `argvus config accent --apply` to re-run only the accent reconciliation.

If the loading overlay stays on screen after a theme change, check whether a switch is still running. A switch records itself in `theme-switch.active`, beside its lock:

```sh
cat "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/theme-switch.active"
ps -ef | grep -E 'theme-switch|loading-theme'
```

A pid in the marker that is still alive means the switch has not finished. A switch that waits more than 60 seconds for the theme lock, or for the configuration reload, ends with an error message and removes its overlay, so an overlay that stays up points to a switch hung inside its reload. A marker whose process has exited is stale and the next switch ignores it. Include the output of the commands above when reporting the problem.

If only the pre-login greeter is white or uses the fallback theme, compare the private source with its public projection:

```sh
uid=$(id -u)
argvus config get /appearance/theme --raw
sudo cat "/var/lib/argvus/greeter/themes/$uid"
sudo cat "/var/lib/argvus/greeter/themes/$uid.accent" 2>/dev/null || true
```

Repair the projection without changing greetd configuration:

```sh
sudo argvus greeter-setup --sync-themes
```

That file is published for pre-authentication by the appearance orchestrator and
lives outside `data/generated/`, so a plain `argvus config apply` does not
refresh it.

If the greeter reports `Invalid color name: 'null'` in a Kitty cache, update the
`argvus terminal` package and regenerate the cache by opening the greeter again.
An absent canonical accent is a default, not a Kitty color; the current terminal
launcher rejects JSON `null` and invalid legacy values before writing
`active_tab_foreground`.

If the default terminal stops opening after several theme changes, inspect the derived Kitty cache instead of editing it manually:

```sh
argvus config get /appearance/theme --raw
ls -l "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/argvus-terminal"
argvus terminal --apply
argvus terminal --print-config
```

The command above reads the canonical preference. `.active-theme` is only a
compatibility projection. The cache is regenerated by `argvus terminal` and
synchronized with theme application. A missing or stale
`/usr/lib/argvus/loading-theme/splash` indicates an incomplete package update;
rebuild and install the coordinated packages before judging a live-session
result.

If window borders keep the previous theme color, do not edit Hyprland's Lua
file manually. Theme and accent changes are projected from `config.json`, then
`argvus sessionctl reload` reloads Hyprland and reapplies the active, inactive,
and group border colors through the session lifecycle:

```text
config.json → projection plan → Hyprland reload → hyprctl reapply of active/inactive/group borders
```

Border *preferences* are changed through `argvus config borders` (or its
`borders-switch.sh` delegate) in Control Center and the Control Panel; reload
reapplies the committed colors through the session lifecycle and does not
re-derive them.

Inspect the plan and the effective compositor values:

```sh
jq . "${XDG_STATE_HOME:-$HOME/.local/state}/argvus/config-projection.json"
hyprctl -j getoption general:col.active_border
hyprctl -j getoption general:col.inactive_border
argvus sessionctl reload
```

If `hyprctl` cannot reach the current Hyprland socket, the border projection is
reported as failed and dependent components are not considered successfully
reloaded. Check the user-session journal before retrying.

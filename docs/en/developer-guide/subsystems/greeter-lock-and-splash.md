---
title: Greeter, lock and splash
description: Separate startup and authentication visuals.
---

`argvus-greeter` provides the greetd interface. The session-loading spinner is the Wayland mode of the handoff helper (`/usr/lib/argvus/greeter/handoff --wayland`), started by `argvus-session-loading.service`; the GTK overlay `argvus loading-theme` covers theme transitions and direct reloads. `argvus-boot-splash` provides the separate boot splash. `argvus-lock` provides Hyprlock configuration.

Theme state is handed across the greeter and session transition, but these packages have different lifecycles and installed payloads.

The greeter runs before the user's authenticated session and uses greetd's IPC/PAM boundary. The session-loading overlay starts when the new Wayland socket becomes available and ends once `argvus sessionctl ready` has started the desktop components, so it covers the whole session startup. The Plymouth theme belongs to the boot path and is not the login screen. The lock component is used after login and does not replace either greeter.

The login handoff has a DRM surface of its own. Once authentication succeeds, the greeter starts `/usr/lib/argvus/greeter/handoff` (`argvus-greeter-handoff`) before it asks greetd to start the session. The helper takes DRM master as soon as the greeter compositor releases it and keeps a frame on screen until the user compositor takes over. It keeps running after the greeter exits. As soon as greetd accepts the session, the greeter asks its compositor to exit (`argvus config hyprland exit`): greetd starts the user session only after the greeter session ends, and the compositor does not leave on greetd's SIGTERM, so without this request the login waited for greetd's 5-second kill. `greeter-session` exports `HYPRLAND_RETAIN_FRAME_ON_EXIT=1`. A Hyprland build that supports it leaves its last frame on the outputs when it exits: it closes the scanned-out framebuffers with `DRM_IOCTL_MODE_CLOSEFB`, so they outlive the process, and skips the backend teardown that turns every output off. The helper then finds the CRTC on, in the same mode, and replaces the frame with a page flip, so the monitor keeps its signal. Hyprland builds without this support ignore the variable; their exit turns the output off, and the output goes dark for a moment while the monitor syncs again at the helper's modeset. While it waits for DRM master, the helper keeps a descriptor open on each card, so the compositor's exit is never the last close that makes the kernel restore the fbdev mode, and it logs every CRTC change as `handoff.crtc` in the timing log (a `fb=0` or `mode_valid=false` line means the output went off between the two masters). It reads the connectors from their cached state, without probing them again, and logs `handoff.page-flip-failed errno=<n>` when the page flip is refused and it falls back to a modeset. `greeter-session` disables core dumps for that compositor (`ulimit -c 0`), so a crash during its teardown does not keep the display off while the core is written.

The greeter splash, this surface and the session spinner read as a single splash. The greeter splash and the session spinner are the same helper in Wayland mode: a plain shared-memory layer-shell client that shows its first frame a few milliseconds after it connects (the GTK overlay needed about 300 ms, while the compositor already showed its background), with no GTK in the login path. All three draw the same spinner from `argvus-loading-theme-core`: four squares that grow, travel to the next corner and shrink back in a 1.5 s cycle (the CSS loader keyframes, with `cubic-bezier(0.3, 1, 0, 1)` on each segment), the same size in physical pixels, the user accent as color (the greeter passes `--accent` to both helpers), with the frame taken from `CLOCK_MONOTONIC` so the animation does not restart when one process takes over from another. When the greeter compositor left the output on in the same mode, the surface shows its first frame with a page flip instead of a modeset, so the monitor does not resynchronise. After a `release` the surface keeps its buffer on the output, with the spinner still animating, until the user compositor shows its own frame, for at most 10 seconds, instead of turning the output off. Hyprland shows its first frame about 150 ms before it starts serving clients, so for that moment the output shows Hyprland's first buffer without the spinner; the session spinner maps right after. Hyprland maps the `argvus-loading-theme` layer without an animation (`no_anim` layer rule), so the spinner appears and leaves in a single frame. Until it maps, Hyprland paints the splash background of the active theme, which `argvus config project` writes as `background_color` in the generated `hypr/state.lua`.

 `argvus-start` sends `release` to its socket (`/run/argvus-greeter/handoff.sock`) just before it launches Hyprland, and the helper acknowledges only after it has dropped DRM master. A session without a greeter sends the same command and finds no surface, so nothing happens. A failure to start the surface is logged and does not stop the login. While it runs, send it commands with `/usr/lib/argvus/greeter/handoff --send theme=<name>` or `--send release`. The socket and the greeter's pre-login `session.log` live in `/run/argvus-greeter`, which `systemd-tmpfiles` creates owned by the `greeter` user with mode 0755: only the greeter writes there, and the session that logs in only reads the log and connects to the socket.

This separation matters when diagnosing a visual problem: a missing boot splash is a Plymouth/package issue, a blank transition is a session-loading or compositor-readiness issue, and an authentication failure belongs to greetd/PAM rather than the desktop session.

The interactive theme transition and direct session reload pass the selected theme explicitly to `/usr/lib/argvus/loading-theme/splash`. A direct reload (`argvus sessionctl reload`, `SUPER + Shift + R`) starts the session splash before `argvus config project` runs, so the desktop changes it applies happen under the cover. It uses the spinner-only mode, so its first mapped frame is opaque, and it is started with `--detached`: the splash outlives the short-lived `argvus config session-splash start` helper that spawns it, because a parent-death signal would stop it as soon as that helper exits. The reload stops the splash after the runtime half finishes, on every exit path. Interactive transitions retain their visual fade. The interactive path also passes generated background, foreground and accent values; the splash palette is only a fallback. Verify the installed binary and package payload when source changes are not visible in the running session.

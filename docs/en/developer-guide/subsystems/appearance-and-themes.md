---
title: Appearance and themes
description: Theme state propagation across ARGVUS.
---

`argvus-appearance` owns theme, accent, wallpaper and font *state*. It consumes assets from `argvus-wallpapers`, `argvus-fonts` and `argvus-icons`, but it does not generate theme output: every ARGVUS-owned consumer file for Hyprland, GTK, Qt, Waybar, Quickshell, Rofi, Dunst, Hyprlock, Yazi, Superfile, terminals and native applications is a projection written by `argvus-config` alone.

The Control Center and Control Panel are user interfaces; neither is the sole source of theme state.

`theme-switch.sh` is the theme transaction entrypoint: it takes the lock, commits the selected theme, layout variant and wallpaper through `argvus-config` when available, refreshes the compatibility files consumed by the current compositor and then hands the runtime fan-out to `argvus-sessionctl reload`. Sticky and Float are represented canonically by `layout.variant`; the `-float` suffix remains a compatibility fallback. The final transaction reapplies Hyprland gaps and border geometry before services restart, so the compositor and surfaces cannot remain on the previous mode.

`theme-adapters.sh` owns every consumer that cannot read `config.json` or the published projection on its own — the native Qt6ct file, GTK `settings.ini` and `gsettings` hints, Foot and Kitty, the greeter theme state, the taskbar calendar cache, the Control Center palette cache, Snappy, the System Monitor, the wallpaper runtime and Hyprtoolkit. It runs from `argvus-sessionctl reload`, so a theme switch, a keybind reload and a session start all reach the same runtime state. Adapters only read the committed generation: they write their own consumer files and caches and never the canonical document or `data/generated/`. The lock screen blurred wallpaper is only invalidated, never rewritten, because it is already part of the committed projection. `accent-switch.sh` records the canonical accent and delegates to the same adapters, so an accent change and a theme change cannot disagree about a variant. The legacy taskbar utility-group marker is imported inside the transaction, and `argvus-config taskbar status` reports the effective value without writing a generation.

The Hyprland `SUPER + Shift + T` binding opens `theme-menu.sh`, which selects a theme before invoking that script. The transition overlay is visual-only: it receives the selected theme and generated `hyprtoolkit.conf` colors, and it is a first-frame handshake rather than a timed wait. The splash receives the write end of a FIFO through `--ready-fd` and reports `READY` once every monitor surface is mapped, so the switch blocks on that read with no fixed delay and no polling; an overlay that dies before mapping ends the read instead of hanging the switch. A direct `argvus-sessionctl reload` (including `SUPER + Shift + R`) applies the already committed generation without projecting again, and it also repairs stale runtime consumers when the canonical value is unchanged. `argvus-terminal --apply` generates derived Kitty profiles under the user's cache with a shared lock and atomic replacement.

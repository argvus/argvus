---
title: Appearance and themes
description: Theme state propagation across ARGVUS.
---

`argvus-appearance` owns theme, accent, wallpaper and font *state*. It consumes assets from `argvus-wallpapers`, `argvus-fonts` and `argvus-icons`, but it does not generate theme output: every ARGVUS-owned consumer file for Hyprland, GTK, Qt, Waybar, Quickshell, Dunst, Hyprlock, Yazi, Superfile, terminals and native applications is a projection written by `argvus-config` alone, except Rofi: `argvus-launcher` owns its files, and `argvus-appearance` edits the user copies under `data/rofi/`.

The Control Center and Control Panel are user interfaces; neither is the sole source of theme state.

`argvus theme-switch` runs the theme transaction, `argvus config theme-apply`: it takes the lock, commits the selected theme, layout variant and wallpaper through `argvus-config`, refreshes the compatibility files consumed by the current compositor, reloads `argvus-config.service` and restarts the services that were running. Sticky and Float are represented canonically by `layout.variant`; the `-float` suffix remains a compatibility fallback. The final transaction reapplies Hyprland gaps and border geometry before services restart, so the compositor and surfaces cannot remain on the previous mode.

The theme transaction of `argvus-config` (`argvus theme-switch`) owns every consumer that cannot read `config.json` or the published projection on its own — the native Qt6ct file, GTK `settings.ini` and `gsettings` hints, Foot and Kitty, the greeter theme state, the taskbar calendar cache, the Control Center palette cache, the System Monitor, the wallpaper runtime and Hyprtoolkit. It runs from `argvus sessionctl reload`, so a theme switch, a keybind reload and a session start all reach the same runtime state. Adapters only read the committed generation: they write their own consumer files and caches and never the canonical document or `data/generated/`. The lock screen blurred wallpaper is only invalidated, never rewritten, because it is already part of the committed projection. `argvus config accent` records the canonical accent and runs the same transaction, so an accent change and a theme change cannot disagree about a variant. The legacy taskbar utility-group marker is imported inside the transaction, and `argvus config taskbar status` reports the effective value without writing a generation.

The Hyprland `SUPER + Shift + T` binding opens `theme-menu.sh`, which selects a theme before invoking that script. The transition overlay is visual-only: it receives the selected theme and generated `hyprtoolkit.conf` colors, and it is a first-frame handshake rather than a timed wait. The switch starts the splash with `--ready-file` and checks that file every 50 ms for at most two seconds; the splash writes `READY` once every monitor surface is mapped. A splash that is not ready in time receives SIGTERM and then SIGKILL, so it cannot hold the switch. While a switch runs, it keeps `theme-switch.active` in the cache directory, with its pid and process start time. The configuration reload that the switch starts reads that marker and does not start a second switch, so the lock is never taken twice. The wait for the lock and the wait for the reload are each limited to 60 seconds. The overlay records its pid in its own pid file, so the switch stops only the overlay it started, never a session splash. The pid file also records the process start time, so stopping signals the process only while that start time still matches (a recycled pid is left alone). Stopping sends SIGTERM, reaps the process, and escalates to SIGKILL after five seconds. A direct `argvus sessionctl reload` (including `SUPER + Shift + R`) applies the already committed generation without projecting again, and it also repairs stale runtime consumers when the canonical value is unchanged. `argvus terminal --apply` generates derived Kitty profiles under the user's cache with a shared lock and atomic replacement.

# ARGVUS i18n

argvus-i18n é a infraestrutura única de idiomas do ARGVUS. Os catálogos
canônicos são JSON e ficam em /usr/share/argvus/i18n/<locale>/. en-US é a
fonte de verdade e o fallback obrigatório; a chave é retornada quando não
existe nenhum texto traduzido.

O idioma geral vem exclusivamente de `LANG` em `$XDG_CONFIG_HOME/locale.conf`
(padrão `~/.config/locale.conf`), com fallback `en-US`. `user_locale()` retorna
o locale POSIX e `detect_locale_from()` o normaliza para um catálogo instalado.
Variáveis herdadas, `session.language` e arquivos legados de idioma não participam
da escolha. `Lang::detect()` usa o cache por catálogo/locale, sem fixar a primeira
escolha do processo para sempre.

## APIs

Shell pode carregar /usr/share/argvus/lib/i18n.sh e chamar:

    argvus_tr common save
    argvus_tr common welcome name=William

Rust usa a crate compartilhada em memória:

    let i18n = argvus_i18n::I18n::new("common")?;
    let text = i18n.tr_args("welcome", [("name", username)]);

Quickshell importa o singleton I18n.qml; o host deve fornecer os objetos JSON
do locale selecionado e do fallback no seu mecanismo de leitura persistente.
Componentes QML não conhecem paths nem fazem detecção de locale.

## Catálogos e validação

As chaves são semânticas (language.title, nunca o texto inglês). Cada idioma
deve conter os mesmos domínios e chaves de en-US, com os mesmos placeholders.
argvus i18n validate [LOCALE] verifica JSON, tipos, domínios, chaves e
placeholders. argvus i18n list descobre idiomas pelos diretórios e locale.json.

Language packs são dados independentes: argvus-language-en-us e
argvus-language-pt-br podem coexistir. A instalação não escreve em HOME.

## Migração

Migre um repositório por vez: classifique strings visíveis, crie chaves em
en-US, traduza em pt-BR, substitua hardcodes pela API, teste fallback e
valide os catálogos. Nomes de executáveis, serviços, paths, chaves internas,
argumentos e logs puramente técnicos não são traduzíveis.

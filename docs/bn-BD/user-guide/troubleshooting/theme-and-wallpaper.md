---
title: থিম এবং ওয়ালপেপার সমস্যা সমাধান
description: থিম প্রচার এবং উত্পন্ন উপস্থিতি ফাইল নির্ণয়.
---

$XDG_CONFIG_HOME/argvus/config.json-এ ক্যানোনিকাল `appearance` বিভাগটি পরীক্ষা করুন, তারপর  `$XDG_CONFIG_HOME/argvus/config.json` `$XDG_CONFIG_HOME/argvus/data/generated`-এর অধীনে জেনারেট করা ফাইলগুলি পরীক্ষা করুন৷ লিগ্যাসি ডট-ফাইলগুলি শুধুমাত্র মাইগ্রেশন ইনপুট।

`argvus-config` হল `data/generated/` এর নীচে একমাত্র লেখক। একটি ভাঙ্গা পুনরুদ্ধার করতে
থিম বা ওয়ালপেপার, ক্যানোনিকাল ডকুমেন্ট থেকে পুরো প্রজন্মকে পুনর্নির্মাণ করুন এবং
উৎপন্ন ভোক্তাদের সরাসরি সম্পাদনা করার পরিবর্তে ফলাফল প্রয়োগ করুন:

```sh
argvus config validate
argvus config apply
argvus sessionctl reload
```

`argvus theme-switch` (যা `argvus config theme-apply` চালায়) এবং `argvus config accent`
অর্কেস্ট্রেটর হল: তারা যাচাই করে, লক করে, স্প্ল্যাশ দেখায়, কমিট করে
`argvus-config` এবং তারপর বহিরাগত ভোক্তাদের সাথে সমন্বয় করুন যারা পড়তে পারে না
`config.json`. তারা কখনই `data/generated/` লেখে না এবং থিম লেনদেন করে
GTK, স্টোরেজ বা `mode.css` ফাইলগুলি আলাদা স্ক্রিপ্টের মাধ্যমে লিখবেন না।
শুধুমাত্র উচ্চারণ পুনর্মিলন পুনরায় চালানোর জন্য `argvus config accent --apply` ব্যবহার করুন।

অফিসিয়াল থিম পরিবর্তনগুলি তাদের সংরক্ষিত চেহারা মান প্রয়োগ করে এবং প্রভাবিত রানটাইম গ্রাহকদের আপডেট করে। একটি কাস্টম থিম প্রয়োগ করা টাস্কবার, হাইপ্রল্যান্ড রিলোড, ওয়ালপেপার এবং কন্ট্রোল প্যানেল পরিষেবাগুলি পুনরায় চালু করে৷ স্টিকি বা স্পেসড স্যুইচ করা সেই মোডের স্পেসিং, সীমানা এবং টাস্কবারের মার্জিন পুনরায় প্রয়োগ করে, তারপর টাস্কবার, টেলিমেট্রি এবং হাইপ্রল্যান্ড রিলোড পরিষেবাগুলি পুনরায় চালু করে। ডু নট ডিস্টার্ব সক্রিয় থাকাকালীন Dunst-এর বিজ্ঞপ্তির রঙগুলি ব্যতিক্রম: DND বন্ধ না হওয়া পর্যন্ত তাদের পুনরায় লোড স্থগিত করা হয়। যদি অন্য একটি পৃষ্ঠ পুরানো রং রাখে, থিম বিল্ড সক্রিয় আছে কিনা তা পরীক্ষা করে দেখুন এবং এটি আপনার নির্বাচিত থিম, তারপর পুনরায় লোডগুলি চালান:

```sh
cat "${XDG_CONFIG_HOME:-$HOME/.config}/argvus/data/generated/theme/current/build.toml"
argvus config theme-runtime consumers
```

প্রতিটি থিমযুক্ত ফাইল বিল্ড থেকে আসে: একটি থিম যেটি ইনস্টল করা নেই ( `theme.toml` `/usr/share/argvus/themes/` বা `~/.local/share/argvus/themes/` এর অধীনে theme.toml) বা রেন্ডার করা হয় না তা প্রত্যাখ্যান করা হয়, এবং আগের থিমটি থেকে যায়। `argvus theme check DIRECTORY` প্রতিটি রেন্ডার ত্রুটির টেমপ্লেট এবং লাইন দেখায়। একটি ওয়েবার বার শুধুমাত্র তার JSONC-তে `reload_style_on_change` এর সাথে তার রঙগুলি পুনরায় লোড করে। একটি সুইচ আটকে আছে বলে মনে হলে, এটি এখনও চলছে কিনা তা পরীক্ষা করুন; এটি তার লকের পাশে, `theme-switch.active`-তে নিজেকে রেকর্ড করে:

```sh
cat "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/theme-switch.active"
ps -ef | grep -E 'theme-switch|theme-apply'
```

মার্কারের একটি পিড যা এখনও জীবিত রয়েছে তার মানে সুইচটি শেষ হয়নি। একটি সুইচ থিম লক এবং প্রজেকশনের জন্য সর্বাধিক 60 সেকেন্ড এবং পুনরায় লোড কমান্ডের জন্য 5 সেকেন্ড অপেক্ষা করে; একটি মার্কার যার প্রক্রিয়াটি প্রস্থান করা হয়েছে তা বাসি এবং পরবর্তী সুইচ এটিকে উপেক্ষা করে। সমস্যা রিপোর্ট করার সময় উপরের কমান্ডের আউটপুট অন্তর্ভুক্ত করুন।

যদি শুধুমাত্র প্রাক-লগইন গ্রিটার সাদা হয় বা ফলব্যাক থিম ব্যবহার করে, তাহলে প্রাইভেট সোর্সটিকে এর পাবলিক প্রজেকশনের সাথে তুলনা করুন:

```sh
uid=$(id -u)
argvus config get /appearance/theme --raw
sudo cat "/var/lib/argvus/greeter/themes/$uid"
sudo cat "/var/lib/argvus/greeter/themes/$uid.accent" 2>/dev/null || true
```

অভিবাদন কনফিগারেশন পরিবর্তন না করে প্রজেকশনটি মেরামত করুন:

```sh
sudo argvus greeter-setup --sync-themes
```

যে ফাইল উপস্থিতি অর্কেস্ট্রেটর দ্বারা প্রাক-প্রমাণিকরণের জন্য প্রকাশিত হয় এবং
`data/generated/` এর বাইরে থাকে, তাই একটি সমতল `argvus config apply` নয়
এটা রিফ্রেশ

যদি অভিবাদনকারী একটি কিটি ক্যাশে `Invalid color name: 'null'` রিপোর্ট করে, তাহলে আপডেট করুন
`argvus terminal` প্যাকেজ এবং পুনরায় গ্রিটার খোলার মাধ্যমে ক্যাশে পুনরুদ্ধার করুন।
একটি অনুপস্থিত ক্যানোনিকাল অ্যাকসেন্ট একটি ডিফল্ট, একটি কিটি রঙ নয়; বর্তমান টার্মিনাল
লঞ্চার লেখার আগে JSON `null` এবং অবৈধ উত্তরাধিকার মান প্রত্যাখ্যান করে
`active_tab_foreground`.

যদি ডিফল্ট টার্মিনালটি বেশ কয়েকটি থিম পরিবর্তনের পরে খোলা বন্ধ হয়ে যায়, তবে ম্যানুয়ালি সম্পাদনা করার পরিবর্তে প্রাপ্ত কিটি ক্যাশে পরিদর্শন করুন:

```sh
argvus config get /appearance/theme --raw
ls -l "${XDG_CACHE_HOME:-$HOME/.cache}/argvus/argvus-terminal"
argvus terminal --apply
argvus terminal --print-config
```

উপরের কমান্ডটি ক্যানোনিকাল পছন্দটি পড়ে। `.active-theme` শুধুমাত্র একটি
সামঞ্জস্য অভিক্ষেপ। ক্যাশে `argvus terminal` এবং দ্বারা পুনরায় তৈরি করা হয়
থিম অ্যাপ্লিকেশনের সাথে সিঙ্ক্রোনাইজ করা হয়েছে। একটি অনুপস্থিত বা বাসি
`/usr/lib/argvus/loading-theme/splash` একটি অসম্পূর্ণ প্যাকেজ আপডেট নির্দেশ করে;
একটি লাইভ-সেশন বিচার করার আগে সমন্বিত প্যাকেজগুলি পুনর্নির্মাণ এবং ইনস্টল করুন
ফলাফল

যদি উইন্ডো বর্ডার পূর্ববর্তী থিমের রঙ রাখে, হাইপ্রল্যান্ডের লুয়া সম্পাদনা করবেন না
ম্যানুয়ালি ফাইল করুন। `config.json` থেকে থিম এবং উচ্চারণ পরিবর্তন অনুমান করা হয়`argvus sessionctl reload` হাইপ্রল্যান্ড পুনরায় লোড করে এবং সক্রিয়, নিষ্ক্রিয়, পুনরায় প্রয়োগ করে,
এবং সেশন জীবনচক্রের মাধ্যমে বর্ডার রং গ্রুপ করুন:

```text
config.json → projection plan → Hyprland reload → hyprctl reapply of active/inactive/group borders
```

বর্ডার *অভিরুচি* `argvus config borders` এর মাধ্যমে পরিবর্তিত হয় (বা এর
`borders-switch.sh` প্রতিনিধি) কন্ট্রোল সেন্টার এবং কন্ট্রোল প্যানেলে; পুনরায় লোড
সেশন লাইফসাইকেলের মাধ্যমে প্রতিশ্রুতিবদ্ধ রঙগুলি পুনরায় প্রয়োগ করে এবং করে না
তাদের পুনরায় আহরণ.

পরিকল্পনা এবং কার্যকর কম্পোজিটর মানগুলি পরিদর্শন করুন:

```sh
jq . "${XDG_STATE_HOME:-$HOME/.local/state}/argvus/config-projection.json"
hyprctl -j getoption general:col.active_border
hyprctl -j getoption general:col.inactive_border
argvus sessionctl reload
```

যদি `hyprctl` বর্তমান হাইপ্রল্যান্ড সকেটে পৌঁছাতে না পারে, তাহলে বর্ডার প্রজেকশন হল
ব্যর্থ হিসাবে রিপোর্ট করা হয়েছে এবং নির্ভরশীল উপাদান সফলভাবে বিবেচনা করা হয় না
পুনরায় লোড পুনরায় চেষ্টা করার আগে ব্যবহারকারী-সেশন জার্নাল পরীক্ষা করুন।

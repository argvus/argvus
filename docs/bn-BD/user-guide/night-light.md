**কন্ট্রোল সেন্টার > ডেস্কটপ ও ইনপুট > ডিসপ্লে > নাইট লাইট** খুলুন, **নাইট লাইট** অনুসন্ধান করুন অথবা `argvus control-center displays night-light` চালান।

নাইট লাইট এবং এর সময়সূচী প্রাথমিকভাবে বন্ধ আছে। **1000 থেকে 20000 কেলভিন** (ডিফল্ট **4500 K**) তাপমাত্রা বেছে নিন। নিম্ন মান উষ্ণ রং দেয়। পৃষ্ঠাটি সংরক্ষিত ম্যানুয়াল অ্যাক্টিভেশন, কার্যকর অবস্থা এবং পরবর্তী রূপান্তর দেখায়। একটি মান সম্পাদনা লিখুন; Esc এটি বাতিল করে বা প্রদর্শনে ফিরে আসে। অকার্যকর মান সংরক্ষণ করার আগে প্রত্যাখ্যান করা হয়. পরিবর্তনগুলি সংরক্ষণ করুন এবং অবিলম্বে প্রয়োগ করুন৷ সংরক্ষণের পরে আবেদন ব্যর্থ হলে, সংরক্ষিত পছন্দটি প্রকৃত কার্যকর অবস্থা এবং ত্রুটির পাশাপাশি দৃশ্যমান থাকে।

## সময়সূচী এবং দ্রুত কর্ম

নির্দিষ্ট সময়সূচী বর্তমান স্থানীয় সময় অঞ্চল ব্যবহার করে। শুরু অন্তর্ভুক্ত এবং শেষ বাদ দেওয়া হয়; **20:00–07:00** মধ্যরাত অতিক্রম করে। শুরু এবং শেষ অবশ্যই আলাদা এবং `HH:MM` ব্যবহার করুন। কোন অবস্থান বা সৌর গণনা ব্যবহার করা হয় না.

দ্রুত টগলের জন্য কন্ট্রোল প্যানেলের **ডিসপ্লে** কার্ড বা **সুপার + শিফট + বি** ব্যবহার করুন। উজ্জ্বলতা নির্বাচক তার সমস্ত উজ্জ্বলতা ক্রিয়া রাখে এবং একটি উজ্জ্বলতা ব্যাকএন্ড ছাড়া ডিসপ্লে সহ ব্যাকএন্ড উপলব্ধ হলে নাইট লাইট যোগ করে। কোন স্থায়ী টাস্কবার মডিউল নেই।

সময়সূচী বন্ধের সাথে, ম্যানুয়াল অ্যাক্টিভেশন স্থায়ী হয়। সময়সূচী চালু হলে, একটি দ্রুত টগল পরবর্তী নির্ধারিত স্থানান্তর পর্যন্ত রানটাইম ওভাররাইড তৈরি করে। সময়সূচী বা তাপমাত্রা পরিবর্তন করা যে ওভাররাইড সাফ করে। লগআউট, একটি নতুন কম্পোজিটর ইনস্ট্যান্স বা একটি পরিবর্তিত পরবর্তী ট্রানজিশন (একটি টাইম-জোন পরিবর্তন সহ) এটিকে অকার্যকর করে।

## কমান্ড এবং রাষ্ট্র

সমস্ত ইন্টারফেস একই পাবলিক কমান্ড ব্যবহার করে:

```sh
argvus config display night-light status
argvus config display night-light enable
argvus config display night-light disable
argvus config display night-light toggle
argvus config display night-light temperature 4500
argvus config display night-light schedule on 20:00 07:00
argvus config display night-light schedule off 20:00 07:00
argvus config display night-light apply
argvus config display night-light apply-schedule
```

`status ` returns JSON schema version 1: ` available `, ` unavailable_reason `, ` settings ` (enabled, temperature, schedule_enabled, start, end), ` active `, ` effective_temperature `, ` mode ` (` manual ` or ` scheduled `), ` manual_override `,` next_transition ` (অফসেট সহ ISO 8601), ` minimum_temperature ` এবং ` maximum_temperature `। অনুপলব্ধ হলে কার্যকর ক্ষেত্রগুলি শূন্য হয়; পরিচয় সক্রিয় হলে কার্যকর তাপমাত্রা শূন্য। প্রাপ্যতা ব্যর্থতা অবস্থা রিপোর্ট করা হয়; কর্ম ব্যর্থতা একটি সঙ্গে অশূন্য ফেরতডায়গনিস্টিকক্যানোনিকাল পছন্দ হল `/displays/night_light `, ` argvus config ` দ্বারা `$XDG_CONFIG_HOME/argvus/config/displays.json `-এ পরমাণুভাবে সংরক্ষণ করা হয়েছে। উদ্বায়ী ওভাররাইড এবং অ্যাকশন লক `$XDG_RUNTIME_DIR/argvus/night-light/` এর অধীনে লাইভ। উত্পন্ন মনিটর ফাইল স্বাধীন. এই বৈশিষ্ট্যটি কনফিগার করতে জেনারেট করা ফাইলগুলি সম্পাদনা করবেন না৷

## রানটাইমহাইপ্রল্যান্ড এবং **হাইপ্রসানসেট >= 0.4.0** প্রয়োজন। সেশনটি একবার আপস্ট্রিম `hyprsunset.service ` শুরু করে, ` argvus-night-light-init.service ` এর মাধ্যমে সংরক্ষিত অবস্থা প্রয়োগ করে এবং ` argvus-night-light.timer ` এবং ` argvus-night-light.service ` এর মাধ্যমে প্রতি মিনিটে সময়সূচী মূল্যায়ন করে। ঘড়ি এবং সময় অঞ্চলের পরিবর্তনগুলি মূল্যায়নকেও ট্রিগার করে। সময়সূচী বন্ধ করে, পর্যায়ক্রমিক অপারেশন ম্যানুয়াল অবস্থাকে একা ছেড়ে দেয়। বারবার অ্যাপ্লিকেশনগুলি কার্যকর পরিচয়/তাপমাত্রা জিজ্ঞাসা করে এবং অপরিবর্তিত লেখাগুলি এড়িয়ে যান। কোন কম্পোজিটর পুনরায় লোড প্রয়োজন নেই.ARGVUS আপস্ট্রিম পরিষেবার জন্য একটি সিস্টেমড ড্রপ-ইন প্রেরণ করে: এটি `--identity ` দিয়ে শুরু হয় এবং এটির কনফিগার আবিষ্কারটিকে `/usr/share/argvus/session/config/night-light `-তে বিচ্ছিন্ন করে। এটি প্রতিযোগী নেটিভ প্রোফাইল এড়িয়ে যায় এবং ব্যক্তিগত ` hyprsunset.conf ` ফাইলগুলিকে স্পর্শ না করে। ARGVUS সেশন প্যাকেজ ইনস্টল করার সময় ARGVUS-এর বাইরে শুরু হওয়া সহ সেই আপস্ট্রিম পরিষেবাতে ড্রপ-ইন প্রযোজ্য। বিদ্যমান ব্যবহারকারী সিস্টেমড ওভাররাইড অগ্রাধিকার নিতে পারে; সেই পরিস্থিতি নির্ণয় করার সময় ` systemctl --user cat hyprsunset.service ` পরিদর্শন করুন। Hyprsunset 0.4.0 `--config `-এর পৃথক পাথ আর্গুমেন্টকে প্রত্যাখ্যান করে, তাই কনফিগার আবিষ্কার পরিষেবা-স্থানীয় XDG ভেরিয়েবলের সাথে আলাদা করা হয়।ব্যাকএন্ড অফিসিয়াল হাইপ্রসানসেট আইপিসি ব্যবহার করে (` temperature `, ` identity `, ` identity get`), বাউন্ডেড I/O সহ এবং পরিবর্তনের পরে রিড-ব্যাক। কোন শেডার, বিকল্প কম্পোজিটর ব্যাকএন্ড, সিস্টেম কনফিগারেশন লেখা বা বিশেষাধিকার বৃদ্ধি ব্যবহার করা হয় না। অনুপলব্ধ নিয়ন্ত্রণগুলি নিয়ন্ত্রণ কেন্দ্রে অক্ষম করা হয়েছে এবং ডিসপ্লে কার্ডে লুকানো আছে৷
